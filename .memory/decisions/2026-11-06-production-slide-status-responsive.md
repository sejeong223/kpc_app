# Decisions: 제작 슬라이드별 완료·반응형
Date: 2026-11-06
Status: confirmed

## User Request
1. 담당 슬라이드 하나의 완료가 다른 담당 슬라이드까지 전파되는 문제 수정. 선택한 슬라이드만 완료하며 해제 성공 텍스트 제거.
2. 중앙 편집 및 슬라이드 필드가 화면 크기에 맞고 출처에 가려지지 않도록 수정.
3. memory-plan 단계만 요청. 구현은 하지 않는다.
4. 추가 요청: 처음 제작 탭 진입 시 메뉴 사이드바 자동 접기, 이후 사용자가 펼치면 펼친 상태 유지까지 기존 계획에 추가.

## Explicit Answers
- 좁은 화면: “출처를 자동으로 접고, 펼치면 중앙 너비도 함께 조정 (추천)”
- 인접 문제: “이번에는 완료 상태·반응형만 수정 (추천)” — 제조업 편집 본문 저장의 슬라이드별 분리 제외.

## Derived Implementation Decisions
아래는 사용자에게 다시 묻지 않고 기존 데이터 보존 및 요청 범위에 따라 정한 구현 결정이다.
- 활성 slide.id가 상태 변경의 유일한 대상. 멀티 선택 배열을 완료 대상에 사용하지 않는다.
- ProposalSlide.state를 writing/done으로 추가하고, done이면 잠금으로 판정한다. 슬라이드에 별도 locked 중복 필드는 만들지 않는다.
- 저장 모델은 schemaVersion 3. 기존 v1/v2는 각 body의 소목차 상태에서 슬라이드 상태를 한 번 변환한다. 현재 body/각 snapshot/undo.previousBody를 각각 자기 소목차 기준으로 변환한다.
- 이전 완료 기록은 그대로 완료로 이관한다. 과거 개별 클릭 정보가 없으므로 자동 복구 대상 슬라이드를 추측하지 않는다.
- Section.state/locked는 비어 있지 않은 소목차에서는 자식 슬라이드 전체 완료의 집계값. 빈 소목차는 기존 상태를 보존하며 새 빈 소목차는 writing/false.
- 기존 목차 메뉴의 소목차 완료/해제 명령은 명시적인 소목차 일괄 명령으로 유지한다. 제작에서는 새 슬라이드 명령만 호출한다.
- 완료/해제 성공 안내만 조용히 처리한다. 충돌/권한/잠금/저장 실패 메시지는 유지한다.
- 화면 전환 기준은 window 폭이 아닌 ProductionPanels 실제 콘텐츠 폭이다. 좁은 데스크톱에서 자동 접기를 저장된 사용자 너비/열기 선호와 분리한다.
- 모바일 단일 패널 전환, 폰트·선택/담당 테두리·코멘트 디자인과 좌표는 보존한다.
- 메뉴 사이드바는 AppShell/NavSidebar의 앱 주 메뉴를 뜻한다. 내부 슬라이드 목록 및 우측 출처와 상태를 공유하지 않는다.
- “이후 유지”는 같은 사용자·같은 브라우저의 제작 재진입/프로젝트 전환/새로고침까지 유지하는 것으로 구체화한다. 다른 브라우저/기기 동기화는 추가하지 않는다.
- 저장된 제작용 메뉴 선택이 없으면 collapsed=true. 사용자가 명시적으로 조작한 collapsed boolean만 사용자 namespace별 localStorage에 저장한다. false(펼침)를 미설정으로 처리하면 안 된다.
- 제작 이외 화면의 메뉴 기본 상태와 모바일 menuOpen/닫기/포커스 처리는 기존대로 유지한다. 사용자 메뉴 선택을 창 너비 변경으로 덮어쓰지 않는다.
- 메뉴 사이드바 작업은 가용 중앙 폭과 연결되므로 기존 T03에 추가한다. 새 Task를 만들지 않는다.

## Exclusions
- demoPrompt의 소목차 공유 구조 변경.
- 기존 사용자 데이터 초기화, 실제 설정 권한 저장, 서비스 연동 추가.
- 브라우저/CUA/E2E/dev server/스크린샷 검증; tests/ 생성/복원.
