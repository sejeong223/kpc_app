## D01. 이번 구현의 범위

- **Chosen — 사용자 선택**: 화면 기능과 실제 파일 선택·로컬 보관까지 구현한다. 프로젝트·참여자 등 서버 데이터는 mock으로 제공한다. 실제 서버 저장, 문서 분석, 검색 연동은 후속으로 둔다.
- **Rationale**: 외부 저장소가 준비되기 전에 실제 파일로 UI와 자료 관리 흐름을 사용할 수 있게 한다.
- 업로드 성공은 브라우저 저장 완료를 뜻한다. 서버 업로드·색인·AI 분석 완료로 표시하지 않는다.
- 기획 HTML의 고정 시연 본문·가짜 검색 결과를 실제 업로드 파일의 내용처럼 표시하지 않는다.

## D02. IndexedDB 보관과 향후 저장소 교체

- **Chosen — 사용자 선택**: 등록한 원본 파일과 자료 설정을 IndexedDB에 저장한다. 같은 브라우저·사이트 주소에서 새로고침·재접속하면 복원한다.
- **Rationale**: 파일 재선택 없이 작업을 이어가고, 추후 DB가 준비되면 실제 저장소로 연결을 바꾸기 위해서다.
- UI와 저장소를 분리한다. 화면 → TanStack Query 훅 → 업무 서비스/저장소 계약 → IndexedDB 구현의 경계를 둔다.
- 메타데이터와 원본 바이트 저장을 구분한다. 추후 서버 DB와 파일 저장소를 연결할 수 있게 하되, 이번에 Azure 리소스를 생성하거나 기존 파일을 서버로 자동 이관하지 않는다.
- 실제 로그인 사용자와 프로젝트별로 저장 범위를 분리한다. 다른 PC·브라우저와는 공유되지 않으며 사이트 데이터 삭제 시 사라질 수 있다.
- 서버 전환 시 인증·권한 재검증, 기존 로컬 데이터 이관, 파일 저장 위치는 별도 후속 작업이다. 어댑터 분리만으로 서버 전환 완료를 주장하지 않는다.

## D03. 프로젝트 선택

- **Chosen — 사용자 선택**: 화면 상단에 재사용 가능한 프로젝트 선택을 추가한다. mock 프로젝트별로 파일·웹 링크·참조 설정을 구분한다.
- **Rationale**: 기획 HTML은 현재 프로젝트에 속한 자료를 다루지만 현재 앱에는 공통 프로젝트 선택 상태가 없다.
- 프로젝트 선택 컴포넌트와 상태 경계는 다른 작업 화면에서도 재사용 가능하게 만든다. 이번 작업에서 미구현된 모든 프로젝트 화면을 동시에 연결하지 않는다.
- 기존 RFP mock의 ID·이름·PM 정보를 우선 재사용한다. 권한 정보가 없는 토큰 사용량용 프로젝트 선택값을 실제 참여 권한으로 간주하지 않는다.
- 선택 가능한 프로젝트가 없으면 빈 상태를 제공하고, 존재하지 않거나 접근할 수 없는 프로젝트 ID에 대한 읽기·쓰기를 거부한다.

## D04. 웹 검색 영역

- **Chosen — 사용자 선택**: 기획 HTML에 실제 표시되는 링크·기간·활용 지침의 등록·수정·삭제를 구현한다.
- **Rationale**: 현재 화면의 요소를 구현하면서 실제 검색·본문 수집과의 경계를 유지한다.
- 링크는 필수다. 기간은 전체 기간·최근 1년·최근 3개월이며 활용 지침을 저장한다.
- 웹 자료 상세는 등록한 링크와 설정을 보여준다. 안전한 외부 링크 열기를 제공하되 내용을 자동 수집하지 않는다.
- 검색어, 사이트 포함·제외, 검색 결과 선택, mock 검색 결과 생성은 이번 범위에서 제외한다. HTML에 남은 비표시 분기를 다시 노출하지 않는다.

## D05. 원본 미리보기와 다운로드

- **Chosen — 사용자 선택**: PDF는 브라우저가 지원하는 범위에서 실제 파일을 미리 보고, TXT는 실제 텍스트를 표시한다. 나머지 허용 형식은 파일 정보와 원본 다운로드를 제공한다.
- **Rationale**: 기획 HTML의 고정 본문을 대체하면서 전체 Office/HWP 렌더링 엔진을 도입하지 않는다.
- PDF 표시 실패·미지원 시 원본 다운로드를 제공한다. TXT는 HTML로 실행하지 않으며, 대용량 내용의 표시 제한이 있으면 생략 사실을 명시한다.
- 미리보기용 임시 URL과 로딩은 닫기·파일 변경·프로젝트 변경·사용자 변경 시 정리한다.
- 원본이 없는 mock 메타데이터에는 실제 파일을 읽은 것처럼 미리보기나 다운로드 성공을 제공하지 않는다.

## D06. 파일 업로드 화면의 회차 생성

- **Chosen — 사용자 선택**: 파일 화면에 `다음 회차 시작`을 제공한다. 이전 자료를 보관하고 새 회차에 자료를 추가할 수 있다.
- **Rationale**: 현재 제작 화면의 완성·재작업 버튼은 동작이 연결되지 않았으므로 파일 관리 흐름을 먼저 완성한다.
- 프로젝트는 1차부터 시작한다. 새 회차 생성은 회차 증가·이전 상태 보관·현재 자료 및 순서 계승을 한 번의 저장 작업으로 수행한다.
- 제작 화면의 완성본, 미완료 섹션 재작업, 리뷰 전달 등 제작 전체 흐름은 후속이다. 파일 회차 생성이 제안서 완성본을 저장하는 것으로 표시하지 않는다.

## D07. 이전 회차의 불변 보관

- **Chosen — 사용자 선택**: 이전 회차는 읽기 전용이다. 조회·미리보기·다운로드는 가능하고 변경할 자료는 현재 회차로 복사하여 수정한다.
- **Rationale**: 과거 작업에 사용했던 원본과 설정이 이후 수정·삭제로 바뀌지 않게 한다.
- 자료 원본, 종류, 우선순위, 활용 지침, 회차 당시 자료 목록과 분류 순서를 보관한다.
- 과거 회차 읽기 전용은 PM·슈퍼 관리자에게도 적용하는 이력 보존 규칙이다. 역할별 권한 제한과 구별한다.
- 현재 화면에서 과거 자료를 바꾸는 경우 저장 전에 현재 회차 사본을 만든다. 취소만 한 사본을 정상 등록 자료로 남기지 않는다.

## D08. 회차 간 참조 대상 계승

- **Chosen — 사용자 선택**: 새 회차는 이전 자료를 이어서 참조한다. 같은 자료를 현재 회차로 복사·수정하면 현재 회차 버전을 참조하고 과거 버전은 이력으로 보관한다.
- **Rationale**: 재작업마다 같은 파일을 다시 올리지 않으면서 수정본과 원본을 중복 참조하지 않게 한다.
- 동일 자료를 연결하는 논리 ID와 개별 버전 ID를 구분한다. 각 회차의 유효 목록에는 같은 논리 자료가 한 번만 들어간다.
- 이름이 같은 새 업로드를 자동으로 기존 자료의 새 버전으로 판단하지 않는다. 명시적인 이력 복사·수정 동작만 기존 자료의 버전을 이어간다.
- `참조 제외`는 자료 보관을 유지하면서 AI 활용 대상에서 빼는 설정이다. 실제 AI 호출은 이번에 연결하지 않는다.

## D09. 개별 자료 관리 권한

- **Chosen — 사용자 선택**: 프로젝트 참여자는 전체 자료 조회·다운로드와 자료 추가가 가능하다. 현재 회차 자료의 수정·삭제는 본인이 등록한 자료만 가능하다. PM과 슈퍼 관리자는 전체 자료를 관리한다.
- **Rationale**: 협업 자료를 열람하되 다른 참여자가 등록한 자료를 임의로 변경하지 않게 한다.
- 일반 사용자도 참여 프로젝트에서 자료를 등록할 수 있다. 이 메뉴를 관리자 전용으로 바꾸지 않는다.
- PM은 프로젝트 역할이며 전사 역할인 슈퍼 관리자·부서 관리자와 구분한다. 부서 관리자라는 이유만으로 참여하지 않은 프로젝트나 타인 자료 수정 권한을 자동 부여하지 않는다.
- 슈퍼 관리자의 전체 관리 원칙을 유지한다. 단, D07의 과거 이력 보존은 유지한다.
- 기존 자료의 이력을 이어가는 복사·수정에도 원자료 관리 권한을 적용한다. 복사 행위나 편집자 변경만으로 타인 자료의 참조 버전을 대체할 권한을 얻지 않는다.

## D10. 파일 용량과 현재 목록 개수

- **Chosen — 사용자 선택**: 파일당 50MB 제한을 유지하고 현재 회차 자료 목록 기준 최대 30개를 적용한다. 이전에서 계승한 자료와 신규 자료는 합산하되 같은 자료의 과거 버전은 중복 계산하지 않는다.
- **Rationale**: 이력 누적으로 새 회차 작업 자체가 막히는 것을 피한다.
- 구현 기본값으로 HTML과 같은 `50 × 1024 × 1024`바이트를 사용하고 제한 안내와 실제 검증을 일치시킨다.
- 파일과 웹 링크를 현재 목록의 자료로 합산한다. `참조 제외`도 목록에 보관 중인 자료이므로 30개에 포함한다.
- 파일 선택, 끌어놓기, 일괄 추가, 웹 추가, 복원 등 모든 등록 경로에서 같은 규칙을 적용한다. 최종 저장 시에도 다시 검증한다.
- 문서당 300쪽은 HTML의 권장 안내를 계승한다. 이번에 지원하지 않는 문서 분석으로 쪽수를 검사했다고 표시하지 않는다.
- HTML의 `projMB:300`, `webResults:10`, `kmsDocs:20`은 현재 화면에서 일관되게 적용되지 않은 상수다. 이번 선택에 없던 별도 전체 이력 용량·웹 결과·KMS 제한을 확정된 정책으로 추가하지 않는다. 브라우저 저장 한도 실패는 D16에 따라 처리한다.

## D11. 프로젝트 공통 설정 권한

- **Chosen — 사용자 선택**: `다음 회차 시작`과 세 자료 분류의 공통 참조 순서 변경은 PM·슈퍼 관리자만 할 수 있다.
- **Rationale**: 개인 화면 배치가 아니라 프로젝트 전체의 작업 기준을 바꾸는 동작이기 때문이다.
- 분류 순서는 프로젝트·회차의 설정으로 보관한다. HTML의 전역 localStorage 순서를 그대로 재사용해 다른 프로젝트까지 변경하지 않는다.
- 새 회차는 기존 순서를 계승한다. 이전 회차의 순서를 이후에 변경하지 않는다.
- 권한 없는 사용자에게 변경 버튼·드래그 핸들을 렌더링하지 않고 업무 서비스에서도 동일한 권한을 검사한다.

## D12. 기획 요소와 컴포넌트 구성 기본값

- **Chosen — 코드·기획 기반 기본값**: 기획의 정보 구조를 유지하면서 현재 Dadam 공통 컴포넌트와 여백 규칙으로 구현한다.
- **Rationale**: 이미 정리한 공통 디자인을 재사용하고 이후 디자인 변경이 여러 화면에 일관되게 반영되게 한다.

| 기획 요소 | 이번 구현 기준 |
| --- | --- |
| 제안 관련 자료·유관자료·웹 검색 | 세 자료 영역, 자료 개수, 빈 상태, 추가 액션 |
| 분류 순서·번호·드래그 핸들 | D11 권한과 회차 범위 적용, 키보드용 순서 변경 수단도 제공 |
| 자료 카드 | 파일/링크 이름, 종류, 우선순위, 크기 또는 출처, 등록자·등록일, 상세·설정·삭제 |
| 회차별 업로드 | 현재 회차 표시, 이전 회차 펼치기·접기, 읽기 전용 상태 |
| 파일 선택·끌어놓기 | 다중 선택, 대기 파일 목록, 등록 전 개별 제거, 검증 오류 표시 |
| 파일별 설정 | 종류, 참조 우선순위, 접을 수 있는 선택적 AI 활용 지침 |

| 추가·설정·미리보기 | 공통 모달 프레임, 스크롤 영역·고정 액션·포커스 복귀 재사용 |

- 넓은 화면의 3열 정보 구조와 좁은 화면의 재배치를 공통 토큰으로 구성한다.

## D16. 로딩·오류·동시 작업 기본값

- **Chosen — 기존 저장 패턴과 선택 범위에서 도출한 기본값**: 저장 실패를 성공이나 빈 상태로 숨기지 않는다. 자료 변경과 회차 전환은 저장 완료 후 표시한다.

## D19. 공통 인증 세션 갱신 연결 — 계획 중 추가 확정

- **Chosen — 사용자 선택**: 공통 인증 Provider의 세션 갱신 수정도 이번 계획에 포함한다.
- **Source**: 계획 중 질문에 사용자가 “공통 인증 세션 갱신 수정도 이번 계획에 포함합니다.”라고 응답했다.
- **Rationale**: `components/providers.tsx`는 최초 props의 세션을 AuthRuntimeContext에 제공하고, 내부 SessionProvider의 갱신값은 전달하지 않는다. 파일 자료함도 이 공통 인증 상태를 사용하므로 사용자·역할 변경에 맞춰 저장 범위와 조회 캐시가 갱신되어야 한다.
- SessionProvider 내부의 useSession 결과를 공통 Context로 전달한다. `useAuthRuntime()`의 기존 `{ authEnabled, session }` 계약과 인증 비활성 모드를 유지한다.
- 실시간 세션 data가 없거나 로그아웃·갱신 오류이면 과거 props 세션을 fallback으로 유지하지 않는다. 라이브러리가 정상 data를 유지한 채 갱신 중인 경우에는 loading 표시만으로 session을 인위적으로 null로 만들지 않는다. 토큰 갱신 알고리즘·서버 권한 모델·로그인 화면 개편은 포함하지 않는다.
- 다른 화면의 소비 지점을 정적으로 검토하고 별도 Task에서 타입 검사·lint·build로 회귀를 확인한다. 브라우저 검증 제외 정책은 유지한다.

## 발견했으나 이번 범위에 자동 포함하지 않는 사항

1. HTML의 KMS 자료 타입·편집·시연 확인 함수는 남아 있지만 현재 세 자료 영역의 신규 추가 동선에는 노출되지 않는다. KMS 신규 등록·연결·버전 확인·본문 수집은 후속 검토 대상이다.
2. 제작 화면은 코멘트 기능과 완성·재작업 등의 미연결 버튼을 포함한다. 전체 제안서 제작 루프, 완성본 저장, 리뷰 전달, 실제 인용 삽입 및 제작 오른쪽 자료 탭 연결은 이번 범위를 넘으므로 별도 작업으로 남긴다.
3. 프로젝트 참여자 관리 UI·공유 서버 권한 저장소·실시간 협업은 없다. 이번 mock 권한 규칙과 브라우저 저장을 운영 보안 구현으로 취급하지 않는다.
4. `TemplateFileStore`의 새로고침 초기화는 기존 Skill/Template 결정에 따른 동작이다. 새 자료함의 IndexedDB 선택을 근거로 Template 보관 정책까지 변경하지 않는다.
5. 서버 저장소가 준비되면 원본 파일 저장, 메타데이터 DB, 로컬 자료 이관, 서버 권한 검사, 문서 분석·색인·검색 연결을 별도로 계획한다. 파일 자료함 구현만으로 연결 완료를 주장하지 않는다.
6. 일반 문서 분석이 없으므로 실제 페이지 수 검사, Office/HWP 내용 미리보기, OCR, 악성 문서 검사, 자동 요약은 완료 범위가 아니다.
