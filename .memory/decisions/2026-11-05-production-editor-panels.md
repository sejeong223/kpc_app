- 한글 입력 조합 중 Enter나 상태 갱신으로 입력을 확정·전송하거나 커서를 초기화하지 않는다. 내용 입력 중 슬라이드용 복사·삭제 단축키가 작동하지 않도록 편집 영역을 구분한다.
- 프로젝트·회차·슬라이드 이동, AI 요청·적용, 완성·재작업에는 기존 미저장 입력 보호를 적용한다. 저장 실패나 버전 충돌 시 초안을 보존하고 사용자가 처리할 수 있는 경로를 제공한다.

## D03. 출처는 조회와 원문 열기

- **Chosen — 사용자 선택 1**: 선택한 슬라이드의 출처를 표시하고 원문을 여는 기능까지만 구현한다.
- **Rationale**: HTML의 출처 패널은 RFP와 참조 자료의 페이지·인용문을 확인하는 화면이다. 별도의 출처 관리 폼을 추가하지 않는다.
- 오른쪽 패널 제목은 `출처`이며 선택한 슬라이드 번호·소목차 정보를 표시한다. `RFP`와 `참조 자료`를 같은 패널 안의 두 목록으로 보여준다. 기존 SourcePanel의 RFP/자료/의견 탭 구성을 그대로 복원하지 않는다.
- 슬라이드의 저장된 `SourceRef`와 해당 섹션에 연결된 `Requirement`를 사용한다. 섹션의 RFP는 같은 섹션 슬라이드에서 공유할 수 있으며, 목차 미연결 요구사항을 현재 슬라이드의 근거로 임의 분류하지 않는다.
- 자료명, 종류, 실제로 저장된 페이지·위치 정보, 인용문을 표시한다. 페이지·인용문이 없으면 미등록 상태를 표현하며 HTML의 임의 페이지·가짜 인용문을 생성하지 않는다. 시연 근거는 시연 자료임을 알 수 있게 표시한다.
- 파일 출처는 참조에 기록된 프로젝트·회차·자료 버전을 찾아 기존 파일 미리보기로 연다. 웹 출처는 기존 웹 자료 보기와 원문 링크를 사용한다.
- 원문 파일 식별 정보가 없는 RFP 항목이나 누락된 자료는 원문 연결이 없는 상태를 표시한다. 다른 파일이나 현재 최신 버전을 임의로 원문 대신 열지 않는다. 기존 뷰어에 없는 PDF 특정 문장 하이라이트 기능은 이번에 추가하지 않는다.
- 연결된 RFP·참조 자료가 없으면 각 목록에 빈 상태를 표시한다. 실제 데이터가 없다는 이유로 예시 출처를 자동 주입하지 않는다.
- 자료 연결·해제, 페이지·인용문 수정, RFP 반영 상태 변경, 출처 자동 추출은 이번 출처 UI에 포함하지 않는다. 관련 저장 데이터와 기존 서비스 명령은 삭제하지 않는다.

- **Rationale**: Template 연결 이전에도 작성 내용과 슬라이드 목록을 확인하며 작업할 수 있어야 한다.

- 중앙 미리보기와 썸네일은 같은 저장 내용·레이아웃 기준을 사용한다. 선택·반영 후 수동 `미리보기 갱신`을 별도로 눌러야만 내용이 보이는 흐름은 개선한다.
- 유효한 Template 연결은 기존 `SlideTemplateRef`와 지원되는 PPT 구조 미리보기를 이용한다. 기존 Template 선택·내용 칸 연결 기능이 필요하면 중앙 영역의 보조 설정 진입점으로 제공하고 긴 설정 폼을 기본 화면에 상시 펼치지 않는다.
- 새 블록 추가·삭제 시 기존 내용 칸 연결을 확인한다. 연결되지 않은 내용이나 지원하지 않는 구조를 미리보기·PPT에 정상 반영되었다고 표시하지 않는다.

- Template 미리보기는 PowerPoint와 완전히 동일한 렌더링을 보장하지 않는다. 넘친 내용을 조용히 숨기거나 잘린 상태를 완성된 출력으로 처리하지 않는다.

## D06. 슬라이드 목록과 선택·조작 기본값

- **Chosen — HTML과 기존 확정 기능에 근거한 기본값**: 현재 프로젝트·조회 회차의 전체 슬라이드를 목차 순서로 보여주고 단일·다중 선택 및 기존 슬라이드 조작을 연결한다.
- **Rationale**: HTML의 `writeThumbs`는 모든 섹션의 슬라이드를 표시하지만 이전 `SlideNavigator`는 선택한 한 섹션만 필터링한다. 새 화면에는 전체 목록이 맞다.
- 썸네일, 전체 장수, 슬라이드 번호, 소목차·제목, 현재 선택, 내 담당, 완료·고정 상태를 표시한다. 없는 표지 슬라이드를 가정해 번호를 2부터 시작하지 않고 실제 프로젝트 순서를 기준으로 한다.
- 단일 클릭은 활성 슬라이드·섹션과 중앙 내용·출처를 함께 변경한다. Ctrl/Command와 Shift 선택, 선택 해제는 같은 전체 목록 순서를 기준으로 동작한다.
- 기존 추가·복제·삭제·복사·붙여넣기·순서 변경·섹션 이동·되돌리기 기능을 필요한 메뉴로 연결한다. 썸네일마다 많은 액션을 상시 나열하지 않고 추가 진입점 및 더보기/우클릭 메뉴를 사용한다. 키보드로도 같은 메뉴에 접근할 수 있게 한다.
- 순서와 섹션 이동은 기존 명령으로 저장한다. 드래그 정렬 엔진이나 새로운 클립보드 변환 엔진을 필수 범위로 추가하지 않는다.
- 삭제 전 기존 영향 안내를 재사용한다. 기존 슬라이드 귀속 의견에 영향이 있다면 표시하며, 제작 캔버스 코멘트는 슬라이드 삭제에 따라 삭제하지 않는다.
- 현재 도메인은 마지막 슬라이드 삭제와 빈 섹션을 허용한다. HTML의 마지막 슬라이드 삭제 금지 조건을 새 업무 규칙으로 넣지 않고, 빈 섹션에는 추가 경로를 제공한다.
- 목차가 없으면 기존 목차 메뉴로 안내한다. 슬라이드가 없으면 편집 권한에 맞춰 추가·기존 초안 생성 경로를 제공하며 무단 seed 생성은 하지 않는다.

- **Chosen — 사용자 요청 및 기존 패널 코드 기반 기본값**: 넓은 화면은 좌측 슬라이드 목록, 중앙 문서 편집 + 미리보기, 우측 출처로 구성한다. 현재 페이지 셸과 간격 체계를 유지한다.
- **Rationale**: HTML의 정보 구성을 따르되 기존 제작 화면과 동떨어진 새로운 앱 레이아웃을 만들지 않는다.
- 중앙은 섹션 경로·제목·작성 상태, 문서/AI 입력, 슬라이드 순서로 구성한다. 섹션 선택과 상태 변경은 기존 업무 명령·권한을 사용한다.
- 목록·출처의 접기/펼치기와 패널 너비 조절은 기존 `useProductionPanels`를 재사용한다. 폴더·프로젝트의 다른 UI 설정을 덮어쓰지 않고 현재 사용자 범위에서 저장한다.
- 드래그뿐 아니라 기존 키보드 너비 조절·기본 배치 복원 경로를 제공한다. 패널이 접혀도 다시 여는 버튼에 접근할 수 있어야 한다.
  - **2026-11-05 수정**: 위의 기본 배치 복원은 별도 상단 버튼을 뜻하지 않는다. D11에 따라 상단 텍스트 토글·`기본 배치` 버튼을 없애고 패널별 아이콘과 separator의 Home 너비 복원만 제공한다.
- 가용 폭에 따라 중앙 공간을 확보한다. 중간 폭에서는 출처를 오버레이로, 좁은 폭에서는 슬라이드/편집/출처 전환으로 제공하는 기존 반응형 방향을 따른다. 세 패널을 강제로 고정 폭으로 나열해 가로 넘침을 만들지 않는다.
- 목록과 출처의 긴 내용은 각 영역에서 스크롤할 수 있게 하며, 기존 코멘트 팝업·핀을 패널의 overflow로 잘라내지 않는다.

## D08. 완성된 헤더·캔버스 코멘트 유지

- **Chosen — 사용자 요청 및 현재 코드의 대상 모델 유지**: `ProjectHeader`와 `CommentsWorkspace`, `ProjectCanvasCommentsProvider`의 현재 기능을 보존한다.
- **Rationale**: 현재 새 코멘트는 개별 슬라이드가 아닌 프로젝트·회차의 제작 작업 영역 전체에 연결된다. 슬라이드 UI 추가만으로 의견 대상을 변경하면 기존 핀·대화의 의미가 달라진다.
- 기존 핀 생성·이동·미리보기·팝업·답글·멘션·수정·삭제·처리 상태·키보드 조작·회차 초안 보호를 유지한다. 현재 핀의 저장 좌표와 대상을 임의 재해석하거나 슬라이드 ID를 붙여 이관하지 않는다.
- 슬라이드 전환만으로 캔버스 코멘트 저장 범위를 바꾸거나 이전 슬라이드 코멘트 구현을 중복 마운트하지 않는다. HTML의 슬라이드 하단 의견 입력과 출처의 의견 탭도 추가하지 않는다.
- 새 편집기·입력·표 조작·AI·패널 핸들은 코멘트 생성 클릭과 충돌하지 않도록 기존 코멘트 제어 경계를 적용한다. contenteditable 내부 클릭이나 표 선택이 핀 생성으로 처리되지 않아야 한다.
- 새 캔버스 코멘트에는 슬라이드 귀속 정보가 없으므로 이를 개별 썸네일의 의견 수로 임의 배분하지 않는다. 기존 슬라이드 귀속 의견 데이터가 있다면 보존하되 새로운 의견 모델로 자동 합치지 않는다.
- 헤더의 프로젝트·회차·권한·완성·재작업·이력·PPT 동작은 기존 단일 연결을 사용한다. 본문 통합 때문에 별도 공급자·상태·중복 헤더를 생성하지 않는다.

## D09. 기존 데이터·권한·저장 계약 재사용

- **Chosen — 코드와 이전 확정 결정 유지**: 기존 프로젝트 runtime, TanStack Query, 서비스/도메인, IndexedDB 저장 경계를 사용한다.
- **Rationale**: 파일·목차·설정·헤더·코멘트가 이미 같은 프로젝트와 회차를 공유한다. 제작 본문도 같은 상태를 사용해야 새로고침·메뉴 이동·회차 전환에서 일관성이 유지된다.
- 핵심 계약: `ProposalSlide { id, sectionId, revision, content, template, usedSettings, sources }`, `SlideContent { title, lead, blocks }`, `SourceRef`, `Requirement`를 유지한다. 문서형 UI 때문에 두 번째 슬라이드 원본 모델을 만들지 않는다.
- 기존 URL 선택·선택 복원·보관본 조회를 존중한다. 삭제된 대상이나 잘못된 ID는 기존 복구/오류 정책을 사용하며 다른 프로젝트로 조용히 전환하지 않는다.
- 작성 내용 수정은 해당 섹션 담당자·PM·슈퍼 관리자 및 기존 capabilities를 기준으로 한다. 조회 전용·완성본·과거 보관본·고정 섹션에서는 변경 동작을 막는다. 고정 해제는 기존 허용 주체와 명시적 동작을 유지한다.
- 실제 저장 직전에도 프로젝트·사용자·회차·권한·revision을 확인한다. 로컬 변경 실패·용량 부족·다중 탭 충돌을 성공 안내나 빈 데이터로 감추지 않는다.
- 기존 자료 원본·사본·회차·완성본·출처·코멘트를 보존한다. 브라우저 DB 삭제/재생성·초기화·seed 덮어쓰기로 통합 문제를 해결하지 않는다.
- 새 서버 API, Cosmos DB, Azure 리소스, 실시간 공동 편집, 실제 알림 발송은 포함하지 않는다. 이 UI 인터뷰에는 Cosmos DB 데이터 작업을 하지 않아 관련 스킬 적용 대상이 아니다.

## D11. 사용자 피드백 반영 — 패널 헤더 아이콘과 접힌 세로 영역

- **Source**: 사용자 지적 — “HTML에서는 아이콘으로 접었다 펼 수 있게 되어있잖아”, “기본 배치 버튼의 역할은 뭐고”; 설명 후 “수정 사항 반영해서 계획서 수정해줘.”
- **확정 수정 방향**: 데스크톱의 상단 `슬라이드 목록`·`출처` 텍스트 토글과 `기본 배치` 버튼을 제거한다. 각 패널 헤더 오른쪽 아이콘으로 접고, 접힌 위치에 좁은 세로 영역(rail)과 펼치기 아이콘·패널명을 남긴다. HTML의 `paneToggle`/`rail` 정보 구조를 현재 Dadam/Fluent 스타일로 구현한다.
- 패널 제목·장수·현재 슬라이드 정보는 기존 헤더에 한 번만 표시한다. 아이콘에 접근 가능한 이름, 펼침 상태, 대상 ID와 포커스 복구를 제공한다. 패널 토글은 저장 내용·선택 슬라이드에 영향을 주지 않는다.
- 구현 기본값: 기존 너비·namespace별 저장 상태·breakpoint를 유지한다. 좁은 화면의 세 화면 전환은 이름이 있는 아이콘 제어로 제공하고, 모바일 패널의 접기 아이콘은 편집 화면으로 돌아간다. 데스크톱 열림 상태와 모바일 선택 상태를 서로 덮어쓰지 않는다.
- 별도의 전체 배치 초기화 UI는 추가하지 않는다. separator의 Home은 해당 패널 너비만 240/320px로 복구한다. 저장소 초기화나 슬라이드 레이아웃 변경 기능으로 오해할 표현을 사용하지 않는다.

## D12. 사용자 피드백 반영 — 중앙 상단의 명확한 편집 입력

- **Source**: 사용자 지적 — “편집 필드는 왜 없는거고”; 후속 계획 수정 요청.
- **확정 수정 방향**: 단일 슬라이드에서는 중앙 상단에 `편집` 제목, 입력 가능한 문서 영역, `슬라이드에 반영` 동작을 명확히 표시하고 아래에 저장된 `슬라이드` 미리보기를 배치한다. 직접 편집을 AI 요청보다 먼저 제공한다.
- 기존 contenteditable 문서 엔진과 `SlideContent { title, lead, blocks }` 왕복 변환은 유지한다. 별도 textarea로 내용을 평탄화하거나 제목·리딩 메시지·블록별 폼을 다시 만들지 않는다. 구조 편집 도구는 보조 펼침 영역으로 정리하고 문서 입력 자체는 기본으로 펼친다.
- 구현 기본값: 문서 입력은 최소 48px, 최대 180px의 내부 스크롤 영역으로 두고 기존 테마 경계·포커스 표시를 사용한다. AI·Template 보조 설정은 그 아래, 저장본 미리보기는 이어서 표시한다.
- 다중 선택은 일괄 요청 입력과 선택 미리보기를 표시하며 단일 슬라이드로 돌아갈 경로를 명시한다. 빈 섹션·목차 없음·읽기 전용·접근 오류·초안 충돌에는 각각 이유를 표시한다. 존재하지 않는 슬라이드의 편집기를 꾸미거나 자동 생성하지 않는다.
- **진단 한계**: 현재 코드는 단일 슬라이드가 있으면 편집기를 렌더링한다. 사용자 화면에서 안 보인 원인을 특정 데이터 오류로 단정하지 않는다. 청사진은 편집기의 배치·식별성과 선택/권한별 렌더 분기를 함께 점검하도록 한다. 유효한 빈 섹션에서 다른 섹션으로 자동 이동하는 변경은 하지 않는다.

## D13. 사용자 피드백 반영 — 제작 화면 높이와 내부 스크롤

- **Source**: 사용자 지적 — “왜 전체 화면에 스크롤바가 잡히는지”; 후속 계획 수정 요청.
- **확정 수정 방향**: 제작 경로에만 viewport 높이 제약을 두고 헤더 아래 남는 높이를 세 패널이 나누어 사용한다. 목록·중앙 본문·출처는 각각 내부 스크롤하며 길어진 본문이 페이지 전체 높이를 늘리지 않는다.
- 기존 T03의 `Math.max(420, viewportBottom - top - 12)` 계산은 폐기한다. 페이지 여백·안내·undo를 따로 누적하는 방식 대신 `flex: 1`, `min-height: 0`을 연결하고 실제 flex 배치가 남은 공간을 계산하게 한다.
- 패널 제목과 접기 아이콘은 본문 스크롤 밖에 둔다. 오류·undo는 중앙 스크롤 안으로 옮기며 되돌리기 기능 자체는 유지한다. 과도하게 긴 헤더 안내도 상한과 자체 스크롤을 갖게 하되 헤더 기능·버튼을 변경하지 않는다.
- 코멘트 surface의 좌표 기준, 저장된 비율 좌표, provider/controller/geometry와 핀·팝업을 유지한다. 코멘트 surface 또는 전역 body에 `overflow:hidden`을 붙여 문제를 가리지 않는다. 내부 스크롤 컨테이너에 코멘트 팝업을 넣지 않는다.
- 이전 T01~T04 커밋·검증 기록은 당시 실행 이력이다. 실제 화면 실측 없이 해당 검증을 이번 시각적 문제의 해결 증거로 재사용하지 않는다. 브라우저 제외·tests 폴더 금지 정책은 계속 유지한다.

## 코드 조사로 확인한 사항과 범위 밖 후속

- **기존 구현 재사용**: 슬라이드 CRUD, 구조 데이터 저장, 권한·회차 검사, 미저장 초안 보호, AI 시연 제안·비교·선택 적용, 파일 원문 열기, 패널 설정이 이미 존재한다. 존재한다는 사실이 현재 제작 메뉴에 연결되어 있거나 이번에 동작 검증을 마쳤다는 뜻은 아니다.
- **중복 위험**: 이전 `ProductionWorkspace`와 `WorkspaceFlow`를 그대로 연결하면 현재 헤더·PPT 액션·코멘트와 중복될 수 있다. 본문 통합에 필요한 부분만 사용해야 한다.
- **모델 제약**: 현재 저장 형식은 제목·리딩 메시지·텍스트/목록/표/이미지 블록이다. 임의 HTML·글자별 풍부한 서식을 저장하는 모델은 아니다. 새 문서 편집기는 이 구조를 보존해야 한다.
- **의견 귀속 차이**: 현재 캔버스 코멘트와 이전 슬라이드별 의견은 서로 다른 대상이다. 슬라이드별 핀 전환·기존 코멘트의 슬라이드 매핑·새 귀속 모델은 보고만 하며 자동 범위에 포함하지 않는다.
- **미리보기와 출력 차이**: 기본 16:9 화면이 표시되어도 Template 없는 실제 PPT 생성이 지원되는 것은 아니다. 기본 레이아웃의 PPT 출력 확장은 별도 후속이다.
- **원문 연결 제한**: `Requirement` 자체에는 파일 버전 식별자가 없고 일부 `SourceRef`의 페이지·인용문·파일 연결도 null일 수 있다. 실제 근거 자동 추출, 누락 원문 연결을 위한 새 모델, PDF 특정 위치 하이라이트는 별도 후속이다.
- **기존 자산 제한**: 등록 자산 원본·현재 이용 권한을 확인할 수 없는 상태는 재선택이 필요한 기존 정책을 유지한다. 관리자 카탈로그 전체 영속화는 자동 포함하지 않는다.
- **실제 서비스 후속**: 실제 AI/RAG, 서버 저장·서버 권한 검증, 사용자 간 실시간 공유, 알림 전송은 이번 범위가 아니다. 로컬 권한 검사만으로 서버 보안이 완성된 것으로 표현하지 않는다.
