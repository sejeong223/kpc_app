## D01. 제작 화면과 전체 헤더 정리

- **Chosen**: `/workspace/write`에서 핀 코멘트 기능을 검증한다. 모든 메뉴의 공용 헤더를 제거하고, 제작 화면 오른쪽 위에 독립적인 핀 생성 버튼을 배치한다. 핀은 사이드바를 제외한 제작 작업 영역 전체에 꽂을 수 있다. 헤더가 차지하던 상단 공간도 작업 영역에 포함한다.
- **Source**: 사용자 요청 1번과 인터뷰 선택. 사용자는 헤더를 제작 화면에서만 제거하는 안이 아니라 모든 메뉴에서 제거하는 안을 선택했다.
- **Rationale**: 제작 본문이 아직 없으므로 현재 화면에서 위치 기반 코멘트를 직접 검증한다.
- **Implementation implications**: 기존 제작 안내 문구를 최소 작업 영역으로 교체한다. 별도 슬라이드 편집기나 별도 시험용 작업판은 만들지 않는다. 제작 영역은 기존 `maxWidth: 1320px`와 중앙 여백 때문에 핀을 꽂을 수 있는 영역이 불필요하게 좁아지지 않도록 한다. 다른 메뉴의 본문 레이아웃 변경은 헤더 제거에 필요한 범위로 한정한다.
- **Code constraints**: `AppHeader`의 모바일 메뉴 열기 버튼을 독립 버튼으로 옮긴다. `workspace-sidebar-trigger` 식별자와 포커스 복귀를 유지해 모바일 사이드바 및 토큰 모달 사용성을 보존한다. 사이드바·팝업·조작 버튼 자체는 핀 생성 대상이 아니다.

## D03. 핀 생성·좌표·이동

- **Chosen**: 작업 영역에 대한 상대 좌표로 저장한다. 창 크기나 사이드바 너비가 달라져도 같은 비율 위치를 유지하며, 스크롤 시 작업 영역과 함께 움직인다. 핀을 드래그해 이동할 수 있다.
- **Source**: 사용자 요청 2·9번 및 상대 위치 유지 선택.
- **Rationale**: 아직 슬라이드나 문서 요소가 없는 제작 화면에서 화면 폭 변화에 일관되게 대응한다.
- **Implementation defaults**: 좌표는 작업 영역 기준 `xRatio`, `yRatio`를 0~1 범위로 저장한다. 팝업은 핀 좌표와 별도의 화면 위치를 계산한다. 핀의 확대 효과나 팝업 리사이즈가 저장 좌표를 바꾸지 않는다.
- 핀 생성 버튼 → 위치 선택 모드 → 작업 영역 클릭 → 임시 핀과 작성 팝업 표시 → 입력창 포커스 순서다. 위치 한 번 지정 후 생성 모드는 종료한다. 위치 지정 전 `Esc` 또는 버튼 재클릭으로 취소한다.
- 클릭과 드래그를 구분하고, 드래그가 끝났을 때 위치를 저장한다. 움직이는 동안 매 프레임 DB에 쓰지 않는다. 영역 밖으로 드래그하면 유효 범위로 제한한다.
- 메모리에 내용이 있는 새 임시 핀이 있으면 생성 버튼으로 그 초안을 재개한다. 여러 미등록 핀을 무제한 만들지 않는다. 등록된 핀 개수는 이 제한의 대상이 아니다.
- 번호는 작업 영역 내 등록 순서로 부여하고, 삭제 후 기존 핀의 번호를 다시 매기지 않는 것을 기본값으로 한다. 임시 핀의 표시 번호는 실제 저장 때 확정한다.

## D04. 핀 클릭 팝업

- **Chosen**: 핀 옆에 기존 대화와 입력창이 열리는 Figma 방식의 팝업을 제공한다. 상단 버튼 순서는 `⋯` → 체크 → `X`다.
- **Source**: 사용자 요청 2·5·6·10번.
- **Rationale**: 지정한 위치와 대화를 함께 보면서 답글을 작성할 수 있다.
- **Implementation defaults**: 한 번에 하나의 대화 팝업을 연다. 배경을 어둡게 덮거나 작업 영역 전체를 잠그지 않는 팝오버 방식이다. 기본적으로 핀 가까이에 배치하고 화면 가장자리에서는 방향을 바꾸거나 위치를 보정한다.
- 다른 핀 클릭 시 해당 대화로 전환한다. `X`, 바깥 클릭, `Esc`는 완료 처리나 삭제가 아니라 닫기다. 미등록 내용은 D12에 따라 보관한다.
- 상단 조작부와 하단 작성창은 유지하고 대화 목록을 내부 스크롤한다. 새 답글을 등록하면 해당 답글을 볼 수 있게 한다.
- 핀이 화면 밖으로 스크롤되어 위치 관계를 유지할 수 없으면 팝업을 닫고 초안을 보관한다. 다시 핀을 열면 초안을 복원한다.
- 키보드로 열기·닫기·메뉴 접근이 가능해야 한다. 닫기 후에는 해당 핀, 임시 핀이 없어졌다면 생성 버튼으로 포커스를 복귀한다. 다른 메뉴 이동 시에는 새 화면의 포커스를 빼앗지 않는다.

## D05. 팝업 크기 조절과 상단 완료 버튼

- **Chosen**: 사용자가 팝업 너비와 높이를 조절할 수 있다. 데스크톱 최대 너비는 브라우저 표시 영역의 `50%`, 최대 높이는 `80%`다. 작은 화면에서는 화면 안에 들어오도록 조정한다.
- **Source**: 사용자 요청 7번 및 최대 가로 50%·세로 80% 선택.
- **Rationale**: 긴 대화를 읽을 수 있는 공간을 주면서 작업 영역도 함께 볼 수 있다.
- **Chosen**: 좁은 팝업에서는 체크 아이콘만, 충분히 넓어지면 `✓ 반영 완료` 버튼으로 표시한다. 완료된 대화에서는 같은 자리에 `다시 열기` 동작을 제공한다.
- **Source**: 사용자 추가 요구. 너비 전환 기준은 약 `420px`을 출발점으로 실제 배치를 검증해 조정한다.
- **Implementation defaults**: 반응형 판단은 브라우저 너비가 아니라 팝업 자체 너비를 기준으로 한다. 기본 너비 약 `360px`, 최소 조작 가능한 크기 약 `320 × 240px`을 기준으로 화면에 맞게 제한한다. 작은 화면에서는 여백을 둔 가용 너비를 사용해 데스크톱 50% 제한 때문에 입력창이 지나치게 좁아지지 않게 한다.
- 경계·모서리의 크기 조절 손잡이를 제공한다. 크기를 바꿔도 입력 내용, 핀 좌표, 메뉴 조작부가 유실되지 않는다. 콘텐츠 높이가 제한을 넘으면 내부 스크롤한다. 팝업 크기는 현재 앱 실행 동안 재사용하는 UI 상태로 두고 코멘트 데이터와 분리한다.

## D06. 호버 미리보기

- **Chosen**: 등록된 핀을 호버하면 왼쪽 위에 작성자, 오른쪽 위에 등록 시간, 아래에 내용을 표시한다. 완료 핀도 미리보기·열람이 가능하다.
- **Source**: 사용자 요청 4번 및 완료 핀 열람 선택.
- **Rationale**: 대화를 열기 전에 의견의 내용을 빠르게 확인한다.
- **Implementation defaults**: 해당 대화의 첫 의견을 미리보기 대상으로 사용한다. 본문은 긴 경우 일부만 표시하고 클릭하면 전체를 보여준다. 수정 후에는 변경된 내용을 보여주되 등록 시각과 수정 시각을 혼동하지 않는다.
- 팝업이 열린 핀에는 미리보기를 중복 표시하지 않는다. 키보드 포커스에서도 정보를 확인할 수 있게 한다. 터치 환경은 핀 탭으로 전체 팝업을 연다.
- 시각은 실제 생성 시각을 저장하고 한국어 표시로 변환한다. 간단한 상대 시각과 정확한 시각 안내를 제공하며, 고정 문자열 `방금` 자체를 DB 값으로 저장하지 않는다.

## D07. 첫 의견·답글·전송 버튼

- **Chosen**: 핀 하나에 첫 의견과 답글 여러 개를 묶는 대화 구조를 사용한다. 입력창 placeholder는 정확히 `의견 남기기 (@이름 멘션) · Enter 등록`이다.
- **Source**: 사용자 요청 3·5번.
- **Chosen**: 전송 버튼은 비활성 시 회색 배경과 흰 종이비행기 아이콘, 활성 시 핀과 같은 빨간색 배경과 흰 종이비행기 아이콘이다.
- **Implementation defaults**: 회색은 `#9ca3af`, 활성 빨강은 `#d7192f`, 아이콘은 `#fff`로 통일한다. 새 의견·답글은 공백을 제외한 유효 내용이 있을 때 활성화한다. 수정에서는 저장된 내용과 달라지고 유효할 때만 활성화한다. 저장 중에는 중복 제출을 막는다.
- `Enter`로 등록, `Shift+Enter`로 줄바꿈한다. 한글 조합 중 Enter는 등록하지 않는다. 멘션 목록이 열려 있을 때 Enter는 사용자 선택을 우선한다.
- 첫 의견을 성공적으로 저장하는 시점에 대화와 핀을 함께 확정한다. 빈 본문만 있는 등록 핀은 만들지 않는다. 저장 실패 시 초안을 지우거나 성공한 것처럼 표시하지 않는다.
- 본문은 일반 텍스트와 구조화한 멘션으로 렌더링한다. 입력한 HTML을 실행하거나 삽입하지 않는다.
- **Rationale**: 입력 상태·저장 결과·버튼 상태가 일치하고 한국어 입력에서도 오등록이 없어야 한다.

## D08. 로컬 멘션

- **Chosen**: `@` 입력 시 가상 사용자 목록을 검색·선택할 수 있다. 선택한 이름을 본문에서 강조하고 대상 사용자 식별자를 DB에 저장한다.
- **Source**: 가상 사용자 목록으로 멘션 구현 선택.
- **Rationale**: 별도 조직 사용자 검색 서비스 없이 코멘트 작성과 멘션 데이터 저장을 검증한다.
- **Implementation defaults**: 현재 작성자와 소수의 가상 동료를 고정 ID로 관리한다. 표시 이름만 비교해 사용자를 식별하지 않는다. 선택된 멘션과 일반 텍스트로 입력한 `@이름`을 구분한다.
- 마우스·키보드 선택, 검색 결과 없음, 목록 닫기, 멘션이 포함된 문장 수정·삭제를 처리한다. 본문 편집 후 멘션 위치와 실제 텍스트가 맞지 않는 데이터는 저장하지 않는다.
- 이번 선택은 로컬 검색·선택·강조·저장에 대한 것이다. 실제 조직 검색이나 외부 알림 발송을 요청한 것으로 해석하지 않는다.

## D09. 반영 완료와 다시 열기

- **Chosen**: 체크 버튼으로 대화 전체를 반영 완료 처리하면 핀이 회색이 된다. 회색 핀은 클릭·호버가 가능하며 기존 대화를 읽을 수 있다. 다시 열기 버튼을 누르면 빨간 핀으로 복귀하고 답글 작성이 가능해진다.
- **Source**: 사용자 요청 6번 및 완료 핀의 열람 가능·명시적인 다시 열기 선택.
- **Rationale**: 완료 이력을 남기면서 추가 논의가 필요한 경우 같은 대화를 재사용한다.
- 완료 상태에서는 새 답글 등록을 비활성화한다. 답글 등록으로 자동 재개하지 않는다. 완료·재개 상태는 DB에 저장한다. `X`는 상태를 변경하지 않는다.
- 본인 의견 수정·삭제는 D10의 권한을 적용한다. 완료는 새 답글 작성을 제한하는 상태이며, 본인 의견의 관리 권한을 제거하는 별도 권한 체계로 만들지 않는다.

## D10. 수정·삭제 단위와 권한

- **Chosen**: 상단 `⋯`는 첫 의견 수정·대화 전체 삭제를 제공한다. 각 답글의 `⋯`는 해당 답글 수정·삭제를 제공한다. 본인이 작성한 항목에만 표시한다.
- **Source**: 사용자 요청 10번 및 첫 의견과 답글 모두 본인 작성분 관리 선택.
- **Rationale**: 대화 전체에 대한 작업과 개별 답글에 대한 작업을 명확히 구분한다.
- 첫 의견 작성자가 대화 전체를 삭제하면 다른 작성자의 답글도 함께 삭제된다. 확인 창에 삭제 범위를 명시하고, 핀·첫 의견·답글을 하나의 일관된 저장 작업으로 삭제한다.
- 개별 답글 삭제는 해당 답글만 제거한다. 수정 시 생성 시각은 유지하고 수정 시각을 별도로 기록한다. 수정 취소 시 저장된 내용은 바뀌지 않는다.
- 메뉴 표시뿐 아니라 저장 동작에서도 작성자 ID를 확인한다. 개발용 관리자 역할 선택을 타인의 본문 수정·삭제 권한으로 확장하지 않는다.

## D11. 핀 이동·완료·재개 권한

- **Chosen**: 해당 작업 영역을 이용하는 모든 사용자가 핀 이동·반영 완료·다시 열기를 할 수 있다. 내용 수정·삭제는 계속 D10의 본인 작성분 제한을 적용한다.
- **Source**: 최종 인터뷰 선택.
- **Rationale**: 의견 작성자와 실제 작업 담당자가 달라도 담당자가 위치를 조정하거나 반영 완료로 처리할 수 있어야 한다.
- 현재 로컬 환경에서는 다른 작성자의 예시 대화로 이 동작을 검증한다. 이 결정 자체가 여러 PC 간 동기화나 서버 권한 API 구현을 의미하지 않는다.

## D12. 미등록 내용의 임시 보관

- **Chosen**: `X`·바깥 클릭·`Esc`로 닫아도 미등록 내용은 메모리에 보관하고 다시 열면 복원한다. 새 핀은 첫 의견 등록 전까지 임시 상태다. 새로고침하면 미등록 내용은 사라진다.
- **Source**: 초안을 DB에 저장하거나 닫을 때 폐기하는 안 대신 잠시 보관 선택.
- **Rationale**: 팝업 간 이동 중 작성 내용을 잃지 않으면서 확정된 코멘트와 초안을 구분한다.
- **Implementation defaults**: 같은 앱 실행의 레이아웃 생명주기 동안 새 핀 초안, 대화별 답글 초안, 수정 초안을 분리해 관리한다. 메뉴 이동 시 팝업은 닫되 메모리 초안은 유지한다. 로그아웃·작성자 변경 시 이전 작성자의 초안을 재사용하지 않는다.
- 텍스트가 없는 새 임시 핀은 닫을 때 정리할 수 있다. 내용이 있는 임시 핀은 복원 가능한 상태로 남긴다. 전송 성공 후 해당 초안만 비우며 실패한 초안은 보존한다.

## D13. IndexedDB 영구 저장과 오류 처리

- **Chosen**: 브라우저의 IndexedDB에 등록된 코멘트·답글·핀 위치·완료 상태·멘션 정보를 저장한다. 같은 브라우저와 같은 사이트 주소에서 새로고침·재접속 시 복원한다.
- **Source**: SQLite 서버 파일 DB 대신 IndexedDB 선택.
- **Rationale**: 서버 API나 Azure 리소스 없이 실제 입력·수정·삭제 결과가 쌓이는 로컬 기능을 검증한다.
- **Implementation defaults**: UI와 저장 로직을 분리한 저장소 계층을 둔다. 클라이언트에서 비동기로 DB를 열고, 스키마 버전과 초기화 상태를 관리한다. IndexedDB API를 이용하며 별도 서버 DB 서비스는 만들지 않는다.
- 모델은 작업 영역, 대화, 메시지, 사용자, 초기화 메타데이터를 구분한다. 대화에는 ID·영역 ID·안정적인 번호·작성자 ID·상대 좌표·진행 상태·시각을, 메시지에는 ID·대화 ID·첫 의견/답글 구분·작성자 ID/표시 이름·본문·멘션·생성/수정 시각을 둔다. 구체적인 필드 타입과 저장소 인덱스는 `/memory-plan`에서 청사진으로 작성한다.
- 현재 제작 예시 작업 영역에 고정 ID를 부여한다. 로그인 사용자와 개발 미리보기는 안정적인 식별자로 저장 범위를 분리한다. 실제 인증 토큰을 저장하지 않는다.
- 대화 생성과 첫 의견 저장, 대화와 답글 일괄 삭제, 최초 예시 데이터와 초기화 표식 저장은 각각 함께 성공하거나 함께 실패하도록 트랜잭션을 사용한다.
- DB 열기·읽기·쓰기 실패를 사용자에게 알리고 다시 시도할 수 있게 한다. 로드 실패를 빈 DB로 오인해 예시를 중복 생성하지 않는다. 저장 실패를 임의의 메모리 성공 상태로 숨기지 않는다.
- 브라우저 사이트 데이터 삭제 시 데이터가 없어질 수 있으며, 다른 브라우저·PC와는 공유되지 않는다. 실제 협업 데이터베이스와 같은 보존·동기화 보장을 의미하지 않는다.

## D14. 작성자와 최초 예시 데이터

- **Chosen**: 기존 프로필 표시 구조를 재사용한다. 로그인 상태에서는 로그인 사용자 이름, 개발 미리보기에서는 기존 `PROFILE_PREVIEW_USER`인 정소담을 사용한다.
- **Source**: 코드 확인 후 인터뷰 중 설명한 연결 방식. 표시 이름과 별도로 안정적인 작성자 ID를 사용한다. 세션의 `oid` 등 기존 식별자를 우선 활용한다.
- **Chosen**: 진행 중 핀, 반영 완료 핀, 답글·멘션을 포함한 최소 예시를 최초 한 번만 DB에 저장한다. 사용자가 직접 추가한 데이터는 이어서 쌓인다. 예시를 삭제해도 다시 생성하지 않는다.
- **Source**: 빈 상태 대신 최초 예시 데이터 제공 선택.
- **Rationale**: 미리보기·완료·재개·본인/타인 메뉴 차이까지 바로 검증한다.
- 현재 작성자의 첫 의견과 가상 동료의 첫 의견, 서로 다른 작성자의 답글을 포함한다. 예시는 실제 발송·실제 협업으로 오해하지 않도록 로컬 fixture 데이터로 구분한다.
- 초기화 완료 여부는 코멘트 개수와 독립된 메타데이터로 저장한다. 모든 대화를 삭제한 빈 상태도 정상 상태이며 다음 접속 때 다시 채우지 않는다.
