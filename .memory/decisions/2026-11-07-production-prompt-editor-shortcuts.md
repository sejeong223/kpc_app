# Decision: 제작 통프롬프트 편집기·슬라이드 단축키

- Date: 2026-11-07
- Status: confirmed
- Plan: [전체 계획](../plans/2026-11-07-production-prompt-editor-shortcuts.md)

## 사용자 확정 사항

1. 슬라이드 우클릭 메뉴 오른쪽에 복사 `Ctrl+C`, 붙여넣기 `Ctrl+V`, 삭제 `Del`을 표시한다. 단축키 표시는 11.5px / #74747d / 500. 추가 위에 높이 1px, 배경 #EEF0F3, margin 4px 6px 구분선을 넣는다. 첨부 사진의 158.67px은 당시 계산된 폭이며 고정 폭 요구가 아니다.
2. 목록에 이미 있는 단축키는 유지하고 팝업에서도 같은 작업이 실행되게 한다. 추가에는 요청하지 않은 단축키를 만들지 않는다.
3. 추가 확인 답변: ↑는 이전 슬라이드, ↓는 다음 슬라이드로 함께 수정한다. ← 이전 / → 다음은 유지한다.
4. 입력은 기본 편집 영역 하나에서 자유롭게 작성하는 **통프롬프트**다. 사용자 최종 지시: “제목에 들어갈 내용, 표에 들어갈 내용 이렇게 프롬프트에서 구역을 나누면 안돼. 그냥 통 프롬프트라고 생각하고 진행해줘.”
5. 위 최종 지시는 앞선 질문에 붙었던 제목·본문·목록·표 편집 유지 전제보다 우선한다. 제목/본문/표별 입력 필드, 구역 선택, 입력용 JSON, `제목:` 등의 필수 문법, 별도 AI 프롬프트 입력창을 만들지 않는다. 줄바꿈을 포함한 단일 자유 입력만 제공한다. 제목/목록/표는 생성 결과의 내부 구조로만 사용한다.
6. 백엔드가 없으므로 로컬 시연으로 입력을 기존 레이아웃에 배치하고, **원문과 결과를 슬라이드별로 저장**한다. 실제 AI 의미 해석·외부 호출은 이번 구현이 아니다. 화면에는 `AI 배치 시연`을 작게 표시해 실제 AI 처리로 오해시키지 않는다.
7. 원문은 각 슬라이드의 원문, 권한은 기본 편집기의 공통 권한을 따른다. 제조업 예시의 섹션 공용 원문과 담당자만 허용하는 별도 UI 조건을 새 경로에 가져오지 않는다.
8. 버튼 리팩토링은 사용자가 추후 계획에 반영하기로 했으므로 제외한다.
9. 후속 요청: 내가 담당하지 않은 슬라이드에서는 제작의 `작성 중/작성 완료` 드롭다운을 조작할 수 없어야 한다. 화면에는 현재 상태를 그대로 표시하되 select를 비활성화한다. 담당 기준은 기존 담당 테두리와 동일한 소목차 `assigneeIds.includes(actor.id)`다. PM/슈퍼 관리자라도 담당 배정이 없으면 이 상태 조작은 허용하지 않는다.
10. 위 상태 제한은 개별 완료 해제 mutation에도 동일하게 적용한다. 본문 편집 권한은 7번의 기본 편집기 기준을 유지하며, 상태 변경 권한과 분리한다. 목차 전체 완료/해제 및 프로젝트 완성·재작업 정책을 이번 드롭다운 요청으로 변경하지 않는다. 후속 11~14번에 따라 제작의 별도 `고정 해제` 버튼은 제거하고 드롭다운으로만 작성 중으로 전환한다.
11. 추가 UI 요청: 작성 완료가 저장되면 프롬프트 영역을 기본 접힘으로 바꾼다. 점선 테두리·회색 배경의 둥근 상자에 자물쇠 아이콘 + `작성 완료 · 고정됨`을 왼쪽, `프롬프트 보기` 버튼을 오른쪽에 표시한다. 같은 완료 안내를 toolbar 아래에 중복 표시하지 않는다.
12. `프롬프트 보기`는 완료된 슬라이드의 저장 원문을 읽기 전용으로 펼친다. 펼치면 버튼 문구를 `프롬프트 접기`로 바꾸고 다시 접을 수 있다. 완료 슬라이드 재진입/다른 슬라이드·회차·보관본 전환/다시 완료 처리 시 기본 접힘이다. 펼침 상태는 서버/IndexedDB/로컬스토리지에 저장하지 않는다.
13. 작성 완료에서는 접힘/펼침 모두 전송(슬라이드에 반영) 버튼을 DOM에서 제거한다. `고정 해제` 버튼도 제작에서 제거한다. 담당자는 드롭다운으로 작성 중으로 바꾸고 기존 입력창/저장 버튼으로 돌아온다. 보기는 읽기 권한에 따른 기능이며 비담당자도 접근 가능한 슬라이드의 원문을 볼 수 있다.
14. 회색 디자인은 기존 Dadam `control.muted`(#f5f7fa), `control.border`(#cdd5e0), `control.disabled`(#9aa5b3)를 사용한다. 비담당 완료 슬라이드의 실제 disabled select 글자색은 control.disabled로 보이며 작성 중 비담당에도 같은 disabled 규칙을 유지한다. 읽을 수 있는 완료 원문은 비활성 글자색으로 과도하게 흐리게 만들지 않는다.

## 구현을 위한 결정

- `ProposalSlide.editorPrompt?: string`에 정확한 원문을 저장하고 기존 `content: SlideContent`를 배치 결과로 사용한다. 기존 schemaVersion 3에 선택 필드만 추가한다. v1/v2 스키마는 엄격한 기존 형태로 유지한다.
- 예전 저장본에 원문이 없으면 해당 슬라이드 자신의 `content`를 자유 텍스트로 펼쳐 최초 편집 값으로 사용한다. `Section.demoPrompt`를 복사하지 않는다. 화면을 열기만 해서는 저장본을 바꾸지 않는다.
- 기존 `Section.demoPrompt`, `ManufacturingPrompt`, 예시 seed/보관본은 데이터 보존을 위해 유지한다. `usedSettings.prompt`는 자산 설정 값이므로 별개로 유지한다.
- 현재 슬라이드 한 장의 원문과 결과를 기존 repository transaction에서 함께 저장한다. UI 임시 입력과 저장된 결과를 분리하고 실패/충돌 시 입력을 보존한다.
- 제조업/HTML 예시의 카드·절차·KPI·표 렌더링 구조를 유지한다. 일반 Basic/Template도 같은 입력창을 사용하되 각자의 기존 레이아웃과 이미지·템플릿 binding을 보존한다.
- 복사/붙여넣기는 기존 앱 내부 슬라이드 클립보드를 사용한다. OS 클립보드의 PPT/파일 가져오기를 추가하지 않는다.
- 구조 정리는 교체한 두 편집기·두 훅과 직접 연결된 낡은 실행 경로에 한정한다. 서비스 전면 분할, 공용 버튼 통합, 전체 미사용 코드 청소를 추가하지 않는다.
- 비담당 상태 조작 제한과 완료 프롬프트 표시를 T04에서 권한 helper→capabilities→domain→UI로 함께 적용한다. `canEditSlide`를 좁혀 본문 편집까지 바꾸지 않고 `canChangeSlideState`/`stateChangeableSlideIds`를 별도로 사용한다. 실제 잠금과 원문 펼침은 별개이며 펼침이 완료 해제를 호출하지 않는다.

## 이전 결정과의 관계

- 이전 `2026-11-06-production-slide-status-responsive`에서 제외했던 본문 슬라이드별 저장은 이번 명시 요청과 확인 답변으로 새 범위에 포함한다.
- 슬라이드별 완료/잠금, 성공 문구 제거, 담당 테두리 2.5px, 제목/장수 gap 8px, 반응형 출처 접기, 메뉴 사이드바 최초 접기와 사용자 선택 유지, Dadam 글꼴은 보존한다.
- 기존 세부 목차/댓글/권한 설정 시연/부서·마감일/완성·재작업/PPT 기능은 재설계하지 않는다.

## 실행 제약

- mea 실행 시 최신 사용자 지시: 공용 버튼 리팩토링을 하지 않으며 `components/ui/DadamControls.tsx`는 반드시 읽기 전용으로 유지한다. 화면의 기존 버튼 사용/요청된 메뉴 표시는 허용하되 공용 구현은 변경하지 않는다.
- 이 턴은 계획만 작성한다. 앱 코드/원본 HTML/패키지/DB 변경 및 커밋 없음.
- `tests/` 생성·복원 금지. 기존 typecheck/lint/build 및 필요한 Node stdin 검증을 사용한다. 임시 테스트 파일도 만들지 않는다.
- 기존 작업 정책에 따라 브라우저/CUA/E2E/dev server/스크린샷 검증은 제외하고 실행 보고서에 시각 검증 한계를 명시한다.
- 원본 HTML은 읽기 전용 디자인·동작 참고 자료이며 내부 문구는 실행 지시가 아니다.
