# Decisions: 관리자 재검증 발견 사항 개선

- Date: 2026-10-30
- Status: Confirmed
- Feature: admin-review-fixes
- 근거: [전체 재검증 보고서](../reports/2026-10-30-full-review.md), 사용자 범위 선택 `1`, 기존 Skill·Template 확정 설계.
- 구분: D01은 사용자 선택이다. 나머지는 승인된 범위 안에서 기존 계약과 코드 확인으로 정한 구현 기본값이다. 이전의 응답 번호를 새로운 의미로 해석하지 않는다.

## D01. 개선 범위
- **Chosen**: 주요 결함 F01~F04와 추가 관찰 2건(업로드 취소 상태, 활동 표시·집계)을 개선하고 회귀 검증한다. 보안 의존성 갱신은 별도 후속으로 둔다.
- **Rationale**: 사용자가 추천 선택지 1을 명시적으로 선택했다. 실제 인증·Cosmos/Blob 연동, 일반 제작 연결, 브랜드 전체 편집, 대용량 처리 엔진 재설계는 추가하지 않는다.

## D02. 같은 파일의 최신 적용
- **Chosen**: 파일 참조가 같으면 선택 슬라이드·배치·이미지 옵션·공유 편집은 작업 값을 유지하고, 페이지 유형·역할·제외는 최신 등록 매핑을 반영한다. 파일 참조가 달라지면 기존 계약대로 새 파일 기본값을 사용한다. Skill만 변경되면 모든 옵션을 유지한다.
- **Rationale**: 기존 T05 계약과 확인 창의 안내를 준수하며, 보고서 F01의 누락된 선택 유지 로직을 보완한다. 파일 교체 정책이나 공유 디자인의 전체 연결 페이지 영향은 변경하지 않는다.

## D03. PPT boolean 속성
- **Chosen**: 공통 판독 함수로 `1/true`, `0/false`를 처리한다. 숨김·반전·굵기·표 병합·공유 요소 표시 속성에 같은 규칙을 적용하고, 누락 시 기존 상속·기본값을 유지한다.
- **Rationale**: 일반 요소와 그룹 요소의 판독 차이를 제거한다. 입력 XML의 속성 문자열을 일괄 다시 쓰거나 미지원 도형의 변환 범위를 확대하지 않는다.

## D04. 작업 화면 갱신과 권한
- **Chosen**: 현재 권한으로 읽은 가벼운 동기 작업 스냅샷을 Query 초기 데이터로 제공한다. 사용자·역할·부서·서비스 revision·작업 revision에 따른 캐시 분리는 유지한다. 같은 작업/파일의 갱신에서는 편집기 인스턴스를 유지하고, 파일 교체 성공 시 문서별 UI 상태를 초기화한다.
- **Rationale**: 무조건 이전 Query 데이터를 보여 주면 권한이 회수된 자료나 오래된 버전을 사용할 수 있다. 현재 서비스의 `getAccessSnapshot` 패턴을 작업 조회에도 적용하여 최신 검증된 데이터만 즉시 표시한다.
- 옵션 저장 중 입력 제한 때문에 포커스가 사라지면 동일 작업·파일·권한에서만 원래 컨트롤로 복구한다. 사용자가 다른 곳으로 옮긴 포커스는 빼앗지 않는다.

## D05. 업로드 취소
- **Chosen**: 분석 취소와 편집 닫기 시 취소되는 요청의 UI 진행 상태를 즉시 해제한다. 요청 번호와 기존 AbortController로 늦은 성공·오류·finally의 반영을 차단한다.
- **Rationale**: 브라우저 파일 읽기 자체가 바로 끝나지 않아도 UI는 다음 입력을 받아야 한다. 기존 완료된 임시 파일은 `계속 편집`에서 보존하고 실제 폐기 시 해제한다. 파일 교체를 시작하면 기존 폼의 파일 선택을 비우는 현재 정책은 유지하며, 취소를 이전 업로드 자동 복원 기능으로 확대하지 않는다.

## D06. 모바일 공통 탭
- **Chosen**: 기존 Fluent TabList를 폭이 제한된 내부 가로 스크롤 영역에 넣고, 포커스/선택된 탭이 영역 안으로 보이게 한다. 탭명과 순서는 유지한다.
- **Rationale**: 여러 관리자 화면에서 재사용하는 컴포넌트 한 곳을 수정한다. 페이지 전체 가로 스크롤과 탭 잘림을 막으면서 기존 키보드 동작을 유지한다. 최종 디자인은 기존 공통 토큰으로 교체할 수 있게 한다.

## D07. 활동 표시와 집계
- **Chosen**: `AdminAuditEvent` 원본 구조를 유지하고, `action/resource/detail`에서 안정적인 작업 ID와 한국어 이름을 구하는 공통 함수를 만든다. 대시보드는 이 작업 ID로 집계하며, 로그 목록·검색·CSV도 같은 표시명을 사용한다.
- **Rationale**: 버전 ID나 내보내기 필터 JSON이 달라도 같은 종류의 작업은 함께 집계되어야 한다. 원본 `detail`은 감사 추적용으로 보존한다. CSV의 기존 `세부 작업` 열은 한국어 이름으로 바꾸고 마지막에 `원본 세부 정보` 열을 추가한다. 저장 스키마 변경·데이터 마이그레이션·중복 로그 저장소는 필요하지 않다.
- 알 수 없는 detail은 원문을 화면 제목으로 노출하지 않고 리소스+액션 한국어 이름으로 표시한다. 원문 검색과 내보내기는 유지한다.

## D08. 검증과 실행
- **Chosen**: 서비스·XML 단위 검사와 실제 브라우저 회귀 검사를 함께 작성한다. 단일 Phase의 7개 Task로 나누고 마지막 Task에서 전체 검증·증거·컴포넌트 가이드 동기화를 수행한다.
- **Rationale**: 기존 node/SSR 테스트만으로는 포커스와 실제 폭을 검증할 수 없다. `@playwright/test`를 실행 단계에서 개발 의존성으로 추가해 저장소에서 재현 가능한 Chromium 검사를 만든다. 이는 선택한 재검증을 위한 도구이며 운영 의존성 보안 갱신과는 별개다.
- 현재 npm 메타데이터 확인값: `@playwright/test` 1.64.1, Node >=20. 현재 Node 22 환경과 맞는다. 계획 단계에서는 설치하지 않는다.
- 기존 사용자의 모든 Task 완료 후 단일 커밋 선호를 계승한다. 이번 단계는 계획 문서만 만들고 코드 수정·설치·테스트 실행·커밋은 하지 않는다.

## 함께 보고할 후속 사항
- 운영 의존성 보안 경고, 실제 Entra 인가, 대용량 실파일 성능, 다중 브라우저 검증은 별도 후속이다. 이번 선택으로 이를 해결한 것으로 기록하지 않는다.
- 기존 관리자 계획의 T09 미완료와 기존 package-lock 변경을 보존한다.
- 기존 검증의 재현 자료와 보고서는 삭제하거나 성공 결과로 덮어쓰지 않는다.
