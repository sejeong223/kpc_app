# Decisions: RFP 등록 화면 초안

- Date: 2026-11-02
- Status: Confirmed
- Feature: rfp-register
- Workflow: grill-me 인터뷰 완료. 구현·Task 청사진은 memory-plan 이후 진행한다.
- 기준 코드: `cd573cf`
- 레퍼런스: 대화에 첨부된 `KPC_제안서_UI_v12 8.html`의 `pageRegister()` / `regAnalyze()` / `regSubmit()` / `openRevPick()`
- 출처 구분: **사용자 선택**은 인터뷰 답변(6회 모두 1번 외 1회 2번), **코드 확인**은 저장소에서 확인한 사실, **설계 기본값**은 선택을 구현하기 위한 판단이다.

## D01. 구현 수준

- **Chosen**: 목업 UI. 실제 AI 추출·Cosmos DB·Blob 업로드는 하지 않는다. (사용자 선택 1번)
- **Rationale**: "초안" 요청이며 기존 관리자 화면도 목업 서비스 기반이다. Cosmos DB 작업이 아니므로 cosmosdb 스킬 규칙은 적용 대상이 아니다.
- 코드 확인: `/workspace/register`(라벨 "RFP 등록")는 `config/sidebar.ts`에 이미 있고, `app/(authenticated)/workspace/[screen]/page.tsx`가 빈 `WorkspacePage`를 렌더링한다. 이 분기에 등록 화면을 연결한다.

## D02. 데이터 모델과 등록 후 동작

- **Chosen**: RFP 전용 스키마·저장소를 새로 만들고, 등록 시 폼 초기화 + 완료 토스트. 검토 목록(`pipeline`) 화면은 이번 범위에서 제외. (사용자 선택 1번)
- **Rationale**: 기존 `AdminRfpSchema`(번호·이름·부서·PM·등록일·예산·상태)에는 레퍼런스 필드가 없고, 관리자 스키마·대시보드 집계를 건드리지 않기 위해 분리한다.
- 설계 기본값: zod `RfpDraftSchema`(입력) / `RfpRecordSchema`(저장) — id, 프로젝트명, 발주처, 제안 마감일, 사업예산(원, 정수, 선택), 사업 주요내용, 공식 공고명, 사업기간, 메모, 검토자[{id,name}], 첨부파일 메타[{name,size,kind,isMain}], AI 추출 필드 목록, 등록자{id,name}, 담당부서/PM(등록자 기본값), 상태(`review`), 등록일시.

## D03. 파일 업로드와 AI 추출 흉내

- **Chosen**: 레퍼런스 동작 그대로 재현. (사용자 선택 1번)
  - 드롭존(끌어놓기) · 파일 선택 · "샘플 RFP로 체험" 버튼
  - 약 1초 진행바 후 고정 샘플값으로 필드 채움, AI가 채운 칸은 강조 배경 + "AI 추출 · p.N" 태그
  - 파일 목록에서 파일별 종류 선택(RFP / 사업 관련 문서 / 참고자료 / 기타 자료), 첫 파일에 "대표 RFP" 배지
  - "다시 하기"로 초기 상태 복귀
- 설계 기본값: 파일당 50MB 초과 파일은 거절하고 안내. 사용자가 AI가 채운 칸을 수정하면 그 칸의 AI 태그를 해제. 파일 내용은 읽거나 저장하지 않는다(메타데이터만).

## D04. 입력 항목과 필수 여부

- **Chosen**: 레퍼런스 구성 그대로. (사용자 선택 1번)
  - 필수: 프로젝트명, 발주처, 제안 마감일, 사업 주요내용, 검토자 1명 이상 — 모두 충족 시에만 "등록" 활성화, 필수 진행 수(n/5) 표시
  - 선택: 사업예산(원), "추가 정보" 영역(공식 공고명, 사업기간 칩 3·6·8·12개월, 기타 메모)
  - 담당부서·PM은 화면에 노출하지 않고 등록자 본인으로 저장(PM은 이후 '진행 결정' 단계에서 지정)
- 설계 기본값: 사업예산은 천 단위 콤마 표시, 저장 시 정수. 마감일이 오늘 이전이면 경고 메시지(등록은 막지 않음).

## D05. 검토자 선택 UI

- **Chosen**: Fluent `Popover` + 검색 입력 + 체크박스 다중 선택, 선택 결과는 아바타·이름·× 칩. 신규 `ReviewerPicker` 컴포넌트. (사용자 선택 1번)
- **Rationale**: 레퍼런스와 동일한 가벼운 상호작용. 코드 확인: `DirectoryPickerDialog`는 관리자 명령(역할 부여)에 결합되어 재사용하지 않는다.
- 후보 데이터: 관리자 시드(`createAdminSeed()`)의 활성 사용자, 잠긴 사용자 제외. 시드는 읽기만 하고 관리자 저장소에 쓰지 않는다. 이름·부서로 검색.

## D06. 저장 방식

- **Chosen**: IndexedDB 저장. (사용자 선택 2번)
- **Rationale**: 새로고침 후에도 등록 데이터가 남아 이후 검토 목록 화면에서 바로 활용할 수 있다.
- 코드 확인 및 설계 기본값: `lib/comments/repository.ts`의 `IndexedDbCommentRepository` 패턴을 따른다 — 전용 DB 이름·버전 상수, `RfpRepository` 인터페이스, `factory`/`dbName`/`now` 주입으로 테스트에서 `fake-indexeddb` 사용. 첨부파일은 메타데이터만 저장. 작성 중 폼 임시 저장은 하지 않는다.

## D07. 사용자별 분리

- **Chosen**: 로그인 사용자 id를 네임스페이스로 분리. 인증 비활성 개발 모드에서는 목업 사용자. 등록자·검토자는 id로 저장하고 표시 이름을 저장 시점에 함께 복사. 시드 RFP는 넣지 않는다. (사용자 선택 1번)
- 코드 확인: 코멘트 기능이 `identity.scope.namespace` + `identity.actor`로 같은 방식을 사용한다(`components/comments/CommentsProvider.tsx`).

## D08. 화면 스타일 (코드 기준 자동 확정)

- **Chosen**: 레퍼런스 레이아웃(드롭존 → 파일 목록 → 사업개요 카드 → 하단 등록 버튼)을 따르되, 색·컴포넌트는 기존 결정을 따른다.
- 스타일 Q1(전체 레이아웃)은 미응답 상태로 계획 단계로 넘어왔다. **계획 기본값**으로 추천안을 적용한다: 한 열 세로 흐름(드롭존 → 파일 목록 → 사업개요 카드 → 하단 오른쪽 등록 버튼), 본문 최대 폭 960px, "필수 n/5"는 카드 헤더. 사용자가 다른 안을 고르면 T04 청사진만 수정한다.
- 완료 알림은 코드 관례(관리자 화면의 `<p role="status">` 안내)를 따른다. 별도 토스트 컴포넌트를 새로 도입하지 않는다.
- 근거: `2026-10-30-dadam-look-and-feel.md`(Fluent UI 토큰, 파란 강조색 — 레퍼런스의 빨간 강조색 미사용), `2026-11-02-workspace-spacing-system.md`(공통 페이지 헤더·여백). 목업 안내 문구는 짧게 두되 "저장은 이 브라우저에만 보관" 의미를 포함.

## D09. 검증 (정책 자동 적용)

- `2026-10-30-task-validation-policy.md`에 따라 브라우저 검증 제외.
- **변경(2026-11-02, 사용자 지시)**: 이번 계획에서 `tests/` 폴더와 테스트 파일 작성을 제외한다. 검증은 `npm run typecheck`·`npm run lint`·`npm run build`와 Task별 동작 검토 포인트(코드 확인)로 한다. 테스트 파일이 없으므로 `npm test`는 실행하지 않는다.

- 완료한 제안 불러오기(재사용) 기능
