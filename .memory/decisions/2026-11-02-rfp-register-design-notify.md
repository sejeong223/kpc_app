## D01. 시각 디자인 기준

- **Rationale**: 구조는 맞지만 Fluent 기본 모양이라 레퍼런스와 달라 보였다. 강조색은 dadam 결정(`2026-10-30-dadam-look-and-feel.md`)과 충돌하지 않게 유지한다.

## D02. 알림(토스트) 공통 기능

- **Chosen**: 앱 전체가 공유하는 알림 기능을 만든다. Fluent `Toaster`를 공통 위치에 하나 두고 `useAppToast()` 같은 공용 훅으로 호출한다. 모양은 레퍼런스를 따른다. (사용자 선택 1번)
- **Rationale**: 이후 검토 목록 등 다른 화면에서도 같은 알림을 재사용한다.
- 레퍼런스 확인(`.toast`): 화면 아래 가운데(본문 영역 기준 가운데, 아래 64px), 배경 `#1d1e22`, 흰 글자 12px 650, padding 10px 16px, radius 10px, 체크 아이콘 + 문구, 표시 약 2.2초. 오류 알림은 같은 모양에 오류 아이콘을 쓴다(설계 기본값).
- 코드 확인: `components/profile/token/TokenDialogs.tsx`가 자체 `Toaster`(bottom-end, 3.5초)를 쓰고 있다. 이번 결정은 이 기존 알림을 바꾸지 않는다(범위 밖 보고 참조).
- 설계 기본값: 알림은 Fluent Toaster의 aria-live 공지를 그대로 사용한다. 동시에 여러 개가 오면 쌓아서 보여 준다.

## D03. 알림을 띄우는 동작

- **Chosen**: 레퍼런스에 있던 4종만 알림을 띄운다. (사용자 선택 2번)
  1. AI 분석 완료 — "AI가 사업개요를 채웠습니다" (성공)
  2. 업로드 제한 초과 — "{파일명}: 파일당 50MB를 넘을 수 없습니다" / "파일은 최대 30개까지 올릴 수 있습니다" (오류, reducer의 `fileError` 문구 그대로)
  3. 검토자 지정·해제 — "{이름}님을 검토 담당자로 지정했습니다" / "{이름}님을 검토 담당자에서 뺐습니다" (성공). 팝오버 체크박스와 칩 × 버튼 모두 해당.
  4. 등록 성공 — "'{프로젝트명}' RFP를 등록했습니다" (성공)
- 파일 종류 변경·파일 빼기·다시 하기·업로드 시작·사업기간 칩에는 알림을 띄우지 않는다.

## D04. 화면 안 안내 문구

- **Chosen**: 레퍼런스처럼 알림 위주로 간다. 드롭존 아래 파일 거절 문구와 등록 성공 `role="status"` 문구는 **없앤다**. 등록 실패 `role="alert"` 문구와 "사용자 정보를 확인할 수 없습니다" 안내는 화면에 남긴다. (사용자 선택 2번)
- **Rationale**: 실패 시에는 입력값이 남아 있어 다시 시도해야 하므로 안내가 사라지면 안 된다. 성공·파일 거절은 알림으로 충분하다고 사용자가 판단했다.
- 설계 기본값: reducer의 `fileError` 상태는 알림 문구 생성용으로 유지하되 화면에는 그리지 않는다. 같은 오류가 연속으로 나도 매번 알림을 띄운다.
