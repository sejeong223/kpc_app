## D07. 제작 AI도 mock, 편집·적용·저장은 실제 동작

- **Chosen — 사용자 선택 1**: 초안 생성·문장 다듬기·요구사항 누락 점검 등 제작 AI의 결과는 mock으로 제공한다. 비교·적용·유지·다시 생성 및 저장은 실제 동작한다.
- **Rationale**: 기존 제작에는 모델 호출이 없으며, 이번 범위를 실제 모델·문서 분석 인프라까지 확대하지 않는다.
- 단일·다중 슬라이드 요청 모두 적용 전 검토를 거친다. 요청 후 사용자·프로젝트·회차·권한·본문이 바뀌면 오래된 결과가 현재 내용을 덮어쓰지 않는다.
- mock 점검 결과를 실제 RFP 적합성 검증이나 실제 토큰 과금으로 기록하지 않는다. AI 결과·출처의 mock 여부는 해당 결과에서 알 수 있게 한다.

## D12. 미완료 항목 확인 후 회차 완성 가능

- **Chosen — 사용자 선택 1**: 작성 중 섹션·미처리 의견·미확인 행정 체크리스트를 보여주고, 확인 후 현재 상태를 완성본으로 보관할 수 있다.

- `완성`을 제출 승인 또는 실제 AI 품질검증 통과로 표현하지 않는다.

## D13. 로컬 저장·통합 회차의 구현 기본값

- **Chosen — 기존 결정 및 D01·D08에서 도출**: UI → TanStack Query 훅 → 업무 서비스 → 저장소 계약을 두고, 현재 단계는 IndexedDB로 보관한다. 실제 로그인 사용자와 프로젝트별 범위를 유지한다.
- **Rationale**: 기존 파일 자료함을 재사용하면서 새로고침 후 목차·제작·원본·완성본을 함께 복원해야 한다.
- 정확한 스키마·저장소 버전·이관 단계는 memory-plan에서 청사진으로 확정한다. 현재 파일 저장소의 기존 records/Blob을 보존하는 추가적 업그레이드를 설계한다.
- 통합 전 파일만 여러 회차인 프로젝트는 기존 회차 번호와 자료를 유지하여 시작한다. 과거에 존재하지 않았던 제작 완성본을 만들어 넣지 않는다.
- 작업 중 재작업 시작 시 현재 내용이 이전 작업 이력으로 보존됨을 확인시키되, 완료하지 않은 이력을 완성본으로 표시하지 않는다.
- 완성본은 당시 목차·섹션 상태·본문·슬라이드·선택 자산 버전·자료 버전·체크리스트 및 해당 시점 의견 상태를 참조 가능한 불변 사본으로 보관한다. 이후 리뷰 의견은 과거 보관본을 수정하지 않는 별도 기록으로 관리한다.
- 사이트 데이터 삭제·다른 브라우저·다른 PC 사이의 공유는 지원되지 않는다. 실제 공동 편집 서버, Cosmos/Blob 연결, 데이터 이관은 후속이며 이 단계에서 리소스를 생성하지 않는다.

## D14. 목차·체크리스트의 기능 기본값

- **Chosen — HTML 및 확정 권한에서 도출**: 프로젝트별 2단계 목차와 행정 체크리스트를 구성한다.
- 대목차·소목차의 위/아래 추가, 이름 변경, 삭제·되돌리기, 대목차 접기/펼치기, 묶음 이동 및 소목차의 대목차 간 이동을 제공한다. 드래그와 동등한 버튼·키보드 경로를 둔다.
- 화면 번호는 순서에서 계산하고, 실제 연결은 불변 ID를 사용한다. 이름·번호·순서 변경으로 슬라이드·의견·프롬프트 연결이 끊기지 않는다.
- 담당자·리뷰자는 복수 선택, 이름·부서 검색을 지원한다. 담당자는 최소 1명, 리뷰자는 선택 사항으로 한다. 선택 대상은 접근 가능한 프로젝트 참여자를 기본으로 하며 선택만으로 외부 사용자를 몰래 참여자로 추가하지 않는다.
- 표의 번호·목차·담당자·리뷰자·상태·슬라이드 수·RFP 반영·미처리 의견, 대목차 완료 수와 전체 합계를 유지한다. 제작에서 바꾼 데이터가 같은 집계에 반영된다.
- 체크리스트의 항목·근거·복수 담당자·확인 여부·확인자/시간·추가·삭제·되돌리기를 제공한다. 구조 변경은 목차 관리 권한, 담당 지정은 지정 권한, 확인은 해당 담당자·PM·슈퍼 관리자 기준으로 처리한다.
- 삭제 대상에 관련 슬라이드·미처리 의견이 있으면 영향을 보여준다. 고정·권한·회차·버전 검증은 삭제 및 되돌리기 양쪽에 적용한다. 과거 완성본의 참조 데이터는 삭제하지 않는다.

## D15. 제작 화면·참조 자료·의견의 기능 기본값

- **Chosen — HTML 및 D02·D03·D07·D10에서 도출**: 왼쪽 슬라이드 목록, 가운데 내용 편집·슬라이드·비교, 오른쪽 출처 패널을 공통 컴포넌트로 구성한다.
- 섹션 선택과 이전/다음 이동, 슬라이드 썸네일·현재 선택·전체 수·담당/고정/의견 표시, 패널 접기·크기 조절을 포함한다. 작은 화면에서는 편집 영역을 유지하도록 패널을 전환한다.
- 단일/다중 슬라이드 선택과 일괄 mock 요청, 비교 후 적용/유지/재생성, 수정 되돌리기를 제공한다. 적용 대상과 실패·제외 이유를 표시한다.
- 기획의 우클릭·단축키 슬라이드 복사/붙여넣기는 화면 액션도 제공한다. 입력 중 단축키를 가로채지 않으며 외부 텍스트·지원 래스터 이미지 붙여넣기는 데이터 검증 후 처리한다. 이미지를 편집 가능한 PPT 객체로 변환했다고 표현하지 않는다.
- 프로젝트 간 내부 슬라이드 복사는 원본 조회와 대상 편집 권한을 모두 확인한다. 권한 없는 프로젝트의 메모리 클립보드가 사용자 전환 뒤 남지 않는다.
- 의견의 스레드·답글·멘션·핀·반영 완료·다시 열기와 본인 의견 수정/삭제를 기존 컴포넌트·정책에서 재사용한다. 완료 처리 권한은 섹션 담당자·PM·슈퍼 관리자 기준이며 과거 보관본은 수정하지 않는다.
- 신규 의견은 안정적인 슬라이드 ID에 연결하고 핀은 슬라이드 상대 좌표로 저장한다. 썸네일 순서나 슬라이드 번호를 저장 키로 삼지 않는다.
- 출처 패널은 RFP 요구사항·반영 상태와 연결 자료를 제공한다. 업로드한 실제 자료는 기존 파일 서비스의 접근·버전·미리보기·다운로드를 사용한다.
- 실제 분석하지 않은 파일에 HTML의 시연 발췌문·페이지 번호·검색 결과를 붙이지 않는다. mock RFP 근거와 실제 파일 정보는 구분하고, 원문 위치를 알 수 없으면 위치를 지어내지 않는다.
- 알림·검수 요청은 이 단계의 로컬 작업 기록/상태로만 다룬다. 이메일·메신저 또는 다른 사용자에게 실제 전달됐다고 표시하거나 외부 메시지를 전송하지 않는다.

## D16. 제작 설정·적용 자산의 버전과 사용 권한

- **Chosen — 기존 Skill/Template·프롬프트 세트 결정 및 D05·D09에서 도출**: 프로젝트의 프롬프트 세트·Skill·Template 선택, 적용 버전 확인, 프로젝트 전용 프롬프트 수정을 연결한다.
- 소목차의 빈 프롬프트·소스 우선순위는 상위 대목차에서 상속한다. 프롬프트 세트와 프로젝트 목차는 별도 데이터이며, 자산 선택만으로 목차나 담당자·본문을 자동 교체하지 않는다.
- 목차 항목 연결은 안정적인 항목 ID로 유지한다. 이름 유사 매칭은 제안으로만 사용하고 애매한 연결을 임의 확정하지 않는다. 프로젝트에서 고친 프롬프트는 세트 원본을 변경하지 않는다.
- 작업은 적용 당시 자산 버전과 필요한 Template 원본 바이트를 보관한다. 등록 자산 수정은 자동 반영하지 않고 `새 버전 있음`과 명시적인 최신 버전 재적용으로 처리한다. 재적용 전 변경 영향과 역할 매핑을 확인한다.
- 비활성화·삭제는 새 선택을 막되 기존 적용본을 유지한다. 공개 범위 등 이용 권한 회수는 기존의 생성·재적용·다운로드 검사에도 반영한다. 보관 사본을 권한 우회에 사용하지 않는다.
- 일반 사용자의 제작용 조회·선택/적용 경로와 관리자 자산 CRUD를 분리해야 한다. 현재 `canReadAsset`/`canReadPrompt`는 관리자 CRUD read에 결합되어 있다. 관리자 메뉴·등록/수정 권한을 일반 사용자에게 열지 않고, 제작에서는 프로젝트 권한과 해당 자산의 공개·이용 범위를 함께 확인한다.
- `TemplateFileStore`와 관리자 runtime은 메모리 기반이다. 프로젝트 복원에는 적용 사본의 원본·규칙·매핑·출처 버전 및 이용 판단에 필요한 기록이 필요하다. 메모리의 `fileRefId`만 저장하지 않는다.
- 선택된 작업의 복원에 필요한 저장 범위를 설계하되 관리자 카탈로그 전체 영속화나 서버 권한 저장소를 임의 추가하지 않는다. 최신 원본·권한 상태를 확인할 수 없는 경우를 삭제·권한 허용으로 임의 추정하지 않고 제한 상태와 복구 경로를 제공한다.

## D17. 실제 PPT 출력·수정본 처리의 기술 기본값

- **Chosen — D02·D04·D09와 기존 PPT 코드에서 도출**: 실제 `.pptx` 결과 파일을 생성·다운로드하고, 수정본 원본·변경 내용·기준 버전을 보관한다. 알림만 띄우는 시연 다운로드를 사용하지 않는다.
- 기존 ZIP/XML 검증·관계 처리·원본 보존·취소·파일명 정규화·다운로드 정리 기능을 우선 재사용한다. 원본의 사본에서 생성하며 등록 Template 원본을 직접 수정하지 않는다.
- 제작 수정본 입력은 실제 지원되는 `.pptx`로 제한한다. 구형 `.ppt`, 암호화/손상 파일은 이유를 표시한다. 자료함의 단순 파일 보관 허용 형식과 PPT 분석 지원 형식은 구분한다.
- 슬라이드 순서와 내부 ID를 포함한 출력 연결 정보를 보관한다. 외부에서 슬라이드 추가·삭제·순서 변경·중복으로 연결이 불명확해지면 자동 덮어쓰기를 중단하고 확인 가능한 대상만 제시한다.
- 인식된 텍스트·표는 기존/수정본을 비교하고 대상별 적용을 선택한다. 적용 시 권한·고정·기준 버전을 재검증한다. 외부 원본 등록은 성공했으나 내용 적용이 취소/실패한 상태도 구분한다.
- 완성본/PPT 버전/자료 회차를 같은 번호나 객체로 취급하지 않는다. 프로젝트 회차 안에서 PPT 출력 및 외부 수정본 버전이 여러 개 존재할 수 있다.
- 출력은 해당 입력 버전과 연결한다. 내용이 바뀐 뒤 이전 출력 파일을 현재 내용으로 생성된 결과처럼 제공하지 않는다. 이전 성공 출력은 명시적인 이력으로 보존한다.
- 신규 슬라이드 작성·템플릿 요소 내용 주입·PPT 재조립·외부 수정본 비교는 현재 서식 적용 엔진에 추가 개발이 필요하다. 기존 엔진이 이미 이 기능을 지원한다고 전제하지 않는다.

- 브라우저 로컬 검사와 mock 참여 권한은 서버 보안 구현이 아니다. 실제 서버 연결 시 같은 규칙을 서버에서 강제해야 한다.

- **Chosen — 기존 사용자 검증 정책 유지**: `tests/` 생성/복원, 브라우저·CUA·E2E·스크린샷·검증용 dev server 실행은 하지 않는다. 기존 테스트를 이 결정만으로 삭제하지 않는다.
- memory-plan에서 `npm run typecheck`, `npm run lint`, `npm run build`, `git diff --check`와 필요한 기존 도구의 인라인 도메인/저장소/PPT 검증을 변경 범위에 맞게 배치한다.
- 핵심 검증 대상은 담당/위임/슈퍼 권한, 고정 우회, 원자적인 회차 전환, 기존 파일·의견 보존, 완성본 불변성, 사용자·프로젝트 격리, 재접속 복원, 변경 충돌, 지원 내용의 PPT 왕복 비교다.
- 실제 PowerPoint 표시, 브라우저 드래그·클립보드·다운로드, 반응형 육안 검증을 수행한 것으로 보고하지 않는다.
- 기존 관리자 자산 카탈로그 전체 영속화, 프로젝트 구성원 관리 전체 UI, 실시간 공동 편집, 실제 알림·메일, 실제 AI/RAG, Azure 저장소 연결은 별도 후속이다. 필요한 제작용 선택·적용과 로컬 프로젝트 권한 UI는 이번 범위다.
- HTML의 별도 검토·제출 화면에는 PDF/제출 패키지·승인 흐름이 있으나 이번에 선택한 목차·제작 범위만으로 해당 화면 전체를 추가하지 않는다. 발견 사항으로 보고하고 별도 요청 시 계획한다.
- 기획 HTML의 가짜 본문·출처·다운로드·분석 완료 알림, 허술한 권한 검사를 구현 사양으로 복사하지 않는다.
- 이번 단계에서는 결정 문서만 작성했다. 구현·의존성 변경·검증 실행·커밋·push는 하지 않았다. 다음 `/memory-plan`에서 이 문서를 근거로 전체 로드맵·Phase·Task를 작성하고 새 current 포인터를 설정한다.

## D21. 관리자 카탈로그 초기화의 처리 — 계획 중 추가 확정

- **Chosen — 사용자 추가 선택**: 현재 범위를 유지한다. 프로젝트 사본은 보존하되, 새로고침 후 원본 자산·현재 이용 권한을 확인할 수 없으면 재선택하도록 안내한다.
- **Rationale**: 직접 등록한 Template·Skill·프롬프트 세트의 관리자 목록이 메모리에서 초기화되는 인접 문제를 설명하고 질문했으며, 사용자가 관리자 자산 목록·원본의 전체 로컬 영속화는 이번에 추가하지 않는 선택을 했다.
- 자산 권한 상태를 확인하지 못하는 것은 비활성화/삭제가 확인된 상태와 구분한다. 접근 허용으로 추정하여 생성·재적용·다운로드하지 않는다. 사용자가 작성한 프로젝트 내용과 적용 사본을 삭제하지 않고 복구를 안내한다.
- 이 선택은 D16의 제한 상태를 명확하게 한 것이며 기존 관리자 카탈로그 보관 정책을 변경하지 않는다.
