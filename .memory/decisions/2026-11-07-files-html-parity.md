## D01. 적용 범위

- **Chosen — 사용자 선택 1**: 목록 화면과 모든 관련 팝업을 함께 적용한다.
- **Rationale**: 목록만 바꾸고 진입 후 화면이 달라지는 상태를 피하기 위해서다.
- 목록: 자료 사용량/진행 막대, 용량·쪽수 안내, 참조 순서 안내, 회차 펼치기·접기, 제안 관련 자료·유관자료·웹 검색 영역, 자료 카드, 빈 상태, 분류 순서 변경 및 추가 버튼.
- 팝업: 파일 추가, 자료 설정, 현재 회차로 복사하여 수정, 웹 링크 추가·설정, 파일·웹 자료 미리보기, 삭제 확인, 미저장 입력 확인. 삭제 후 되돌리기 영역도 포함한다.
- 기존 공통 프로젝트 헤더를 재사용한다. 헤더 전체·제작 화면·공용 버튼 리팩토링을 이번 범위로 확대하지 않는다.

## D02. 회차별 목록 표시

- **Chosen — 사용자 선택 1**: HTML처럼 각 회차에 등록한 자료만 해당 회차에 표시한다. 이전 자료를 현재 회차에서도 계속 참조하는 기능은 유지한다.
- **Rationale**: 같은 자료가 여러 회차에 반복 표시되는 것을 줄이면서 기존 참조 관계와 보관 이력을 유지하기 위해서다.
- 현재 회차의 새 자료와 복사·수정해 생성한 현재 회차 버전은 현재 회차 목록에 표시한다. 수정하지 않고 이어받기만 한 자료는 이전 회차를 펼쳐 확인한다.
- 기존 `FileVersion.createdInRound`와 `FileRoundView.number`를 이용해 표시 자료를 구분할 수 있다. 저장된 `FileRound.entries`나 전체 조회 결과에서 계승 자료를 삭제해서 구현하지 않는다.
- 회차 요약과 분류 제목의 자료 개수는 그 회차에 실제 표시하는 카드 수와 일치한다.
- 이전 회차는 보관 당시 버전을 유지한다. 이전 카드에서 편집에 진입할 때는 현재 코드의 최신 유효 버전 선택과 현재 회차 복사 저장 경로를 재사용한다.
- 현재 회차를 위에, 과거 회차를 그 아래에 둔다. 일반 진입 시 현재 회차는 펼치고 이전 회차는 접는 기준을 유지한다. 명시적 완성본/보관본 조회의 기존 읽기 전용 조건은 유지한다.

## D03. 자료 사용량과 30개 제한

- **Chosen — 사용자 선택 1**: 현재 참조 중인 자료 전체를 기준으로 집계한다. 이전 회차에서 이어받은 자료도 포함한다.
- **Rationale**: 목록의 표시 방식이 바뀌어도 업로드 가능 개수와 실제 저장 검증이 서로 달라지지 않아야 한다.
- 예: 1차 자료 10개를 계승하고 2차에 3개를 추가하면, 2차 목록에는 3개를 표시하고 상단에는 `자료 13 / 30개`를 표시한다.
- 상단 사용량·진행 막대·모달의 추가 가능 개수·저장 시 한도 검사는 기존 `currentCount`와 `FILE_LIMITS.currentMaterials` 기준을 공유한다.
- 현재 참조 목록에 없는 과거 보관 자료나 이전 버전들을 누적해 계산하지 않는다. 회차마다 별도의 30개 추가 한도를 새로 만들지 않는다.
- 참조 제외 우선순위와 현재 목록에서의 삭제는 기존처럼 구분한다. 우선순위만 바꿔 자료 개수 제한을 우회하지 않는다.

## D04. 성공 안내 문구

- **Chosen — 사용자 선택 1**: 일반 저장 완료 문구를 제거한다. 오류 안내와 삭제 후 되돌리기 안내는 유지한다.
- **Rationale**: 이전 제작 화면과 같은 기준으로, 작업 후 불필요한 상단 문구가 생기지 않게 한다.
- 파일 추가, 웹 링크 추가, 설정 변경, 분류 순서 변경 등에 사용하는 `변경 사항을 저장했습니다.` 공통 성공 문구를 제거한다. 다른 일반 성공 토스트나 빈 안내 줄로 대체하지 않는다.
- 저장 중 버튼 상태, 입력 오류, 권한·충돌·저장 실패, 미저장 확인은 유지한다.
- 삭제 안내와 15초 되돌리기 버튼은 유지하며 일반 성공 문구와 중복 표시하지 않는다. 복원 등 기존 작업별 안내를 일반 성공 문구로 확장하지 않는다.

## D05. 기존 자료와 저장 경계 유지

- **Chosen — 기존 결정·코드 기반 유지**: 현재 프로젝트·회차·등록 자료·원본 파일·자료 설정을 보존한다. 예시 목록을 맞추기 위해 저장소 초기화나 HTML의 파일 배열 덮어쓰기를 수행하지 않는다.
- **Rationale**: 이 작업은 기존 자료함의 화면을 맞추는 것이며, 실제 파일 보관·권한 기능은 이미 구현돼 있다.
- 실제 파일 선택, 여러 파일 추가, 분류 영역/모달에 끌어놓기, 대기 목록에서 빼기, 개별·일괄 설정을 재사용한다.
- UI → 조회/변경 훅 → 서비스·도메인 → IndexedDB(브라우저 내부 파일·데이터 저장소)의 기존 경계를 유지한다. 새 서버 업로드·AI 분석·웹 수집·Azure 리소스를 추가하지 않는다.
- 표시용 회차 필터는 자료함 화면에 한정한다. 제작 출처·인용·완성본 조회 등에 쓰이는 전체 참조 자료를 전역 selector에서 제거하지 않는다.
- 파일과 웹 링크 추가는 같은 30개 한도를 공유하며, 50MB 파일 제한·4,000자 지침 제한·기존 허용 확장자와 검증을 유지한다. 300쪽은 권장 안내이며 이번에 문서 분석 기반 차단을 도입하지 않는다.
- 같은 파일명으로 자동 덮어쓰지 않고, 설정 편집은 기존 자료/버전 식별자 기준으로 저장한다.

## D06. 실제 미리보기와 다운로드 유지

- **Chosen — 기존 결정·코드 기반 유지**: 미리보기 팝업의 디자인은 HTML에 맞추되 내용은 현재 앱의 실제 파일 처리 결과를 사용한다.
- **Rationale**: HTML의 `fileBody`는 고정 시연 본문을 만들고 다운로드 버튼은 시연 알림만 표시한다. 이를 실제 파일 처리처럼 복제하면 기존 기능이 후퇴한다.
- PDF는 브라우저 지원 범위의 원본 미리보기, TXT는 실제 텍스트 표시, 나머지 허용 형식은 정보·원본 다운로드를 유지한다.
- PDF 미지원·잘못된 헤더, TXT 표시 범위/인코딩 제한, 원본 누락은 기존 안내를 보존한다. 원본 없는 예시를 실제 PDF·Office 파일처럼 보여주지 않는다.
- 웹 자료는 등록한 링크·기간·지침을 표시하고 외부 링크를 연다. HTML의 비표시 검색 결과 생성·KMS 분기를 새 기능으로 복원하지 않는다.
- 현재 제조업 예시 자료와 실제 등록 자료는 유지하며, 새 목업 자료·원본 파일 생성은 포함하지 않는다.

## D07. 디자인·반응형·공용 컴포넌트

- **Chosen — 요청 및 기존 사용자 제약에서 도출**: 원본 HTML의 최종 적용 CSS·최종 함수 정의를 기준으로 화면의 글꼴, 크기, 굵기, 색상, 여백, 테두리, 아이콘, 버튼 및 팝업 구성을 맞춘다.
- **Rationale**: HTML에는 같은 선택자와 함수의 이전 정의가 남아 있어 앞부분만 복사하면 현재 참조 화면과 달라진다.
- Dadam의 `Spoqa Han Sans Neo` 계열 폰트가 자료명·메타정보·회차·버튼·입력·팝업·포털까지 적용되게 한다. 임의의 강조색·배지·추가 설명 영역을 만들지 않는다.
- 최종 HTML 분류 레이아웃은 768px 미만 1열, 768px 이상 2열, 1280px 이상 3열이다. 긴 파일명·링크·제목 및 좁은 화면에서 내용/액션이 잘리지 않게 한다.
- 주요 기준: 영역 간격/안쪽 여백 12px, 영역 테두리 반경 12px, 카드 반경 8px, 자료명 14px/500, 메타정보 12px, 회차 제목 14px/500, 분류 제목 13px/700. 최종 전체 CSS에 다른 우선 규칙이 있으면 그 규칙을 함께 확인한다.
- 파일 추가 820px, 자료 설정 760px, 웹 추가·설정 640px, 미리보기 960px, 삭제·미저장 확인 560px의 HTML 기준을 따르되 화면보다 넓어지지 않게 한다.
- `DadamControls.tsx`는 변경하지 않는다. 기존 Dadam 컴포넌트·ModalFrame을 재사용하며 필요한 모양은 파일 화면 전용 스타일/기존 확장 지점으로 적용한다. 공용 버튼 리팩토링은 제외한다.
- `FileDiscardDialog`는 제작·코멘트에서도 사용하므로 파일 화면의 차이를 맞추기 위해 다른 화면의 동작·스타일을 함께 바꾸지 않는다. 공통 헤더·전역 여백·공용 테마 변경도 피한다.
- 파일 저장 범위를 알리는 짧은 안내는 HTML처럼 업로드 모달 등에 둔다. HTML에 없는 본문 중복 안내·메뉴 제목을 늘리지 않는다.

## D08. 권한·보관·오류 동작

- **Chosen — 기존 결정·코드 기반 유지**: 현재 앱의 참여 권한, 자료 소유자/PM/관리자 권한, 회차·버전 검사 및 미저장 보호를 유지한다.
- **Rationale**: HTML의 시연용 이벤트에는 실제 저장소 검증과 이력 보호가 일부 생략돼 있다. 화면 일치를 위해 이런 보호를 제거하지 않는다.
- 참여자는 기존 조건에 따라 자료를 추가하고, 자료 소유자 또는 PM/슈퍼 관리자가 해당 자료를 관리한다. 분류 참조 순서 변경은 PM/슈퍼 관리자 권한을 유지한다.
- 이전 회차 원본·설정과 완성본은 직접 수정하지 않는다. 현재 회차에 복사해 저장하며 취소한 초안을 정상 등록 자료로 남기지 않는다.
- 삭제는 현재 회차 참조에서만 제외한다. 기존 보관본·원본은 보존하고 기존 15초 되돌리기를 유지한다.
- 저장 시 현재 사용자·프로젝트·회차·revision(동시 변경을 감지하는 버전 번호) 검사를 유지한다. 저장 실패는 성공으로 표시하지 않으며 입력을 보존한다.
- 파일 선택 취소만으로 빈 설정창을 열거나 미저장 경고를 만들지 않는다. 실제 초안 변경 후 닫기·이동은 기존 미저장 확인을 거친다.
- 키보드 탐색, ESC 닫기, 모달 포커스 복귀 및 사용 불가 상태를 유지한다.

## D09. 검증과 다음 단계

- **Chosen — 기존 검증 정책 유지**: 계획 단계에서 타입 검사·lint·정적 HTML 대응 검토와 필요한 파일 없는 Node 검증을 지정한다. `tests/` 및 임시 검증 파일을 생성하지 않는다.
- **Rationale**: 기존 사용자 검증 제한을 지키면서 표시 자료와 실제 저장 자료가 섞이지 않는지 확인해야 한다.
- 주요 검증: 회차별 표시 개수와 카드 일치, 계승 자료의 참조·30개 집계 유지, 과거 자료 편집 시 현재 버전 생성과 과거 보존, 삭제/되돌리기, 기존 권한, 추가·설정·미리보기의 실제 데이터 처리, 일반 성공 문구 제거, 공용 컴포넌트 영향 범위.
- 브라우저/CUA/E2E/dev server/스크린샷·시각 검증은 기존 정책에 따라 제외한다. 픽셀 수준의 화면 동일성을 실제 확인했다고 보고하지 않는다.
- 이번 인터뷰에서는 결정 문서만 작성한다. `/memory-plan`에서 수정 파일·청사진·검증 커맨드·커밋 단위와 active pointer를 정한다.

| `FileUndoNotice.tsx`, `FileDiscardDialog.tsx`, `components/ui/ModalFrame.tsx` | 삭제 복원·초안 보호·공통 모달 |
| `types/workspace-files.ts`, `lib/workspace/files/selectors.ts`, `domain.ts`, `permissions.ts`, `config/workspace-files.ts` | 회차·버전·계승·개수·권한·한도의 기준 |

## 요청 밖에서 확인한 사항 — 보고만 하며 자동 포함하지 않음

- 새로운 FluentProvider 테마 ID/`style` 태그 hydration 오류는 직전 작업에서 조사 중이었다. 기존 `c357cac` 이후 보고된 별도 오류이며, 이번 인터뷰 시작 시 코드 변경은 없고 해결이 확인되지 않았다. 전역 Provider 수정은 이 파일 업로드 계획에 자동 포함하지 않는다.
- HTML의 `saveRef`/`delRef`는 시연 자료 객체를 직접 변경·삭제하는 분기가 있어 보관 유지 문구와 완전히 일치하지 않는다. 현재 앱의 이력 보존을 유지하며 원본 HTML 자체의 버그 수정은 별도 범위다.
- 파일 선택·브라우저 저장·권한·버전·초안 보호·미리보기는 이미 구현돼 있다. 같은 기능을 HTML 이벤트 기반의 별도 저장 경로로 중복 구현하지 않는다.
- 실제 서버 공유 저장, Office/HWP 문서 렌더러, 웹 검색·본문 수집, RFP 원본 자동 연계 및 새로운 예시 파일 생성은 포함하지 않는다.
