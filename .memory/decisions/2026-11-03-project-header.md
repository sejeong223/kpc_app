## D01. UI 구현 범위와 저장 제외

- **Chosen**: 헤더와 드롭다운·모달·팝업·설정 패널의 UI를 구현한다. 열기/닫기, 탭 전환, 입력/선택은 제공하되 실제 완성·재작업 처리, 데이터 저장, 권한 변경, 알림 발송, 다운로드는 제외한다.
- **Source**: 최초 범위 질문에 사용자 `1번` 선택. IndexedDB에 대한 중간 질문은 선택 확정이 아니었으며, 그 답변으로 저장 기능을 추가하지 않는다.
- **Rationale**: 공통 헤더와 각 버튼의 연결 화면을 먼저 완성한다. 업무 처리까지 연결하려면 아직 없는 프로젝트 상태/완성본 도메인이 필요하다.
- 이후 사용자가 명시적으로 추가한 UI 동작은 프로젝트 선택에 따른 헤더 정보 변경·토스트(D04), 예시 PM 여부에 따른 리뷰 메뉴 표시·제작 화면 이동(D08)이다. 이 동작을 완성/재작업 시연 루프 전체의 승인으로 확대하지 않는다.
- 이 기능에 IndexedDB/localStorage/sessionStorage/서버 API/DB를 새로 연결하지 않는다. 기존 코멘트의 IndexedDB는 그대로 유지한다.

## D02. 공용 헤더 적용 메뉴와 신규 메뉴

- **Chosen**: 프로젝트 헤더는 아래 6개 메뉴에 적용한다. 리뷰와 완료한 제안은 사이드바 및 접근 가능한 페이지를 추가한다. 완료한 제안에는 프로젝트 헤더를 표시하지 않는다.
- **Source**: 적용 범위 질문 `2` 및 “리뷰, 완료한 제안 메뉴 ... 추가하는 것도 이번 결정문에 추가해줘.”
- **Rationale**: HTML `pageDone()`은 프로젝트별 헤더가 없는 목록 화면이다. 신규 메뉴의 본문 기능까지 만들 필요는 없다.

| 메뉴 | 경로 | 프로젝트 헤더 | 이번 연결 범위 |
| :--- | :--- | :--- | :--- |
| AI 분석 | `/workspace/analysis` | 적용 | 기존 빈 본문 유지 |
| 파일 업로드 | `/workspace/files` | 적용 | 기존 빈 본문 유지 |
| 목차 | `/workspace/toc` | 적용 | 기존 빈 본문 유지 |
| 제작 설정 | `/workspace/setup` | 적용 | 기존 빈 본문 유지 |
| 제작 | `/workspace/write` | 적용 | 기존 코멘트 본문 유지 |
| 리뷰 | `/workspace/review` | 적용 | 메뉴·헤더만 있는 페이지 추가, D08 적용 |
| 완료한 제안 | `/workspace/done` | 미적용 | 메뉴·빈 페이지 추가, 목록/검색/상세/최종본 기능 제외 |

- 경로의 `review`/`done`은 기존 SidebarScreen 및 HTML 키를 따른 구현 기본값이다. 현재 코드에는 두 값이 없어 config와 화면 분기에 추가해야 한다.
- 사이드바의 기존 프로젝트 메뉴 그룹에서 `제작 → 리뷰(PM만) → 완료한 제안` 순서로 둔다. 완료한 제안은 PM 여부로 숨기지 않는다.
- 완료한 제안도 접근성용 제목과 모바일 메뉴 열기는 기존 WorkspacePage/WorkspaceHeader 방식으로 유지한다. “프로젝트 헤더 없음”을 모바일 탐색 수단까지 제거하는 의미로 해석하지 않는다.
- RFP 등록·검토 목록·관리자 화면·전역 셸을 프로젝트 헤더로 일괄 변경하지 않는다.

## D03. 공용 컴포넌트와 룩앤필

- **Chosen**: `components/common/ProjectHeader.tsx`를 공용 헤더 진입점으로 두고 6개 화면이 재사용한다. 버튼은 기존 `components/common/Button.tsx`를 사용한다.
- **Source**: 사용자의 공용 컴포넌트 분리 요청 및 앞선 common 디렉토리·dadam 스타일·버튼 재사용 지시.
- **Rationale**: 현재 제작 화면에만 있는 버튼 JSX를 여러 메뉴에 복제하면 상태와 팝업의 동작이 갈라진다.
- 좌측에는 프로젝트명(긴 이름 말줄임), 기관·마감일, 내 역할 배지, 드롭다운 화살표를 둔다. 그 옆에는 회차/작성·재작업·완성 상태를 표시한다. 우측 버튼 순서는 재작업 → 완성본 N → 완성 → 설정이며 실제 표시 여부는 D07을 따른다.
- 색·폰트·굵기·둥근 모서리·포커스·비활성 표현은 기존 dadam 값을 사용한다. HTML의 빨간 accent나 별도 폰트를 복사하지 않는다.
- 우측 네 버튼은 기존 결정대로 모두 34px, 재작업 아이콘 버튼은 34×34px다. 완성만 공통 Button의 `primary`를 사용한다. 프로젝트 선택기는 두 줄 정보를 담을 수 있는 별도 높이를 사용하며 공통 Button의 전역 높이를 바꾸지 않는다.
- 기존 WorkspaceHeader의 모바일 메뉴·접근성 제목·leading/actions 구조를 활용한다. 헤더나 모바일 메뉴 버튼이 화면에 중복 렌더링되지 않게 한다.
- 스타일은 해당 컴포넌트 파일 안에서 기존 Griffel 방식으로 관리한다. 이 기능을 위해 버튼 CSS/테마/예시/index/README를 다시 분리하거나 새로 생성하지 않는다. Provider와 패널 분리는 실제 책임상 필요한 최소 파일만 계획한다.

## D04. 프로젝트 선택과 토스트

- **Chosen**: 드롭다운 항목을 선택하면 프로젝트명·기관·마감일·내 역할·회차/진행 상태·완성본 개수·버튼 노출이 선택한 예시 프로젝트에 맞게 바뀐다. 드롭다운을 닫고 `현재 프로젝트: {프로젝트명}` 토스트를 표시한다.
- **Source**: 사용자 `2` 및 “html에서 보이는 것처럼 변경되었을 때 알림 토스트 뜨는 것까지 구현해야해.”
- **Rationale**: 화면 사이에 재사용되는 프로젝트 선택기의 실제 UI 흐름을 확인할 수 있어야 한다.
- HTML `openProjPick()`의 “내가 참여 중” 목록·현재 선택 표시·프로젝트명·역할·기관·마감 정보를 참고한다. 사용되지 않는 HTML 검색 핸들러만을 근거로 새 검색 기능을 추가하지 않는다.
- 기본 예시는 HTML의 `mois`(내가 PM, 2차 재작업, 완성본 1개)와 `edu`(내가 PM 아님, 1차 작성, 완성본 없음)를 사용한다. 최초 선택은 첨부 이미지에 해당하는 `mois`다. 예시 데이터는 실제 로그인 사용자의 프로젝트/권한이라고 해석하지 않는다.
- 토스트는 앱에 이미 설치·사용 중인 Fluent Toast/Toaster/useToastController를 재사용한다. 별도 알림 라이브러리를 추가하지 않는다. HTML의 위치/나타남 방식과 짧은 자동 닫힘(2200ms)을 참고하고 dadam 스타일을 적용한다. 빠른 재선택 시 지난 프로젝트 토스트를 쌓지 않고 최신 선택 알림으로 갱신한다.
- 같은 프로젝트를 다시 선택하면 목록만 닫는다. “변경되었을 때” 알림이라는 요구에 따라 중복 변경 토스트는 만들지 않는다.
- 본문 데이터나 코멘트 저장 영역은 전환하지 않는다. 현재 경로는 유지하되, 리뷰에서 비PM 프로젝트를 고르는 경우만 D08의 제작 이동을 적용한다.

- **Chosen**: HTML의 열림 형태를 유지한다.
- **Source**: 형태 질문 사용자 `1`.
- **Rationale**: 완성/재작업 확인은 중앙 모달, 목록 조회는 작은 팝업, 여러 설정 탭은 오른쪽 패널이라는 원본 구조를 재사용한다.

| 재작업 | 중앙 모달 | 다음 회차 제목, 리뷰 코멘트 전달 안내(예시 건수 있을 때), 현재 회차 미완성 경고, 작성 완료로 고정할 섹션/다시 작업할 섹션 목록, 취소·재작업 시작 |
| 완성본 N | 버튼 아래 팝업 | 회차별 완성본을 최신순으로 표시, 저장 시각·작성자·작성 완료/작성 중·슬라이드 수, 보기·PPT |

- 제작 설정 메뉴의 프롬프트/Skill/Template 편집 화면, 섹션 편집기, 리뷰 본문, 파일 업로드 동작은 이번 설정 패널과 별개이며 구현하지 않는다.

## D06. 설정의 네 탭과 임시 입력

- **Chosen**: 기본정보·권한·알림·로그 네 탭 모두 구현한다. 폼 입력·체크박스·선택은 UI 안에서 조작 가능하되 실제 저장이나 권한/알림 시스템에는 반영하지 않는다.
- **Source**: 설정 범위 질문 사용자 `1`.
- **Rationale**: 공용 헤더에서 열리는 설정의 전체 구조를 확인하되 업무 저장 기능을 도입하지 않는다.

| 탭 | 표시/조작 범위 |
| :--- | :--- |
| 기본정보 | 제안 프로젝트명·발주기관·사업 예산·제출 마감일 입력과 진행 상태 표시. 진행안함 전환/되돌리기 같은 상태 변경 버튼은 D09에 따라 비활성 |
| 권한 | 참여자 행과 완성·재작업·제작 설정·담당 지정·권한 부여 체크박스. PM 행은 전부 체크·변경 불가. 예시 현재 사용자가 PM 또는 권한 부여 권한을 가졌을 때만 다른 행의 체크박스 조작 가능 |
| 알림 | 제출 마감 리마인더·완성·재작업 시작·의견 등록 체크박스, 앱 내 알림·이메일 수신 방식 선택 |
| 로그 | 이름·부서 등 부가 정보·권한·변경 내역·일시의 예시 로그 표, 조회 UI만 |

- 입력은 패널이 열린 동안의 임시 값이다. 탭을 오갈 때는 유지하고 패널 닫기/프로젝트 변경 시 버린다. 다시 열면 선택 프로젝트의 원본 예시 값으로 시작한다.
- 기본정보 입력으로 헤더의 프로젝트명을 즉시 바꾸거나, 권한 체크 조작으로 헤더/사이드바 권한을 즉시 바꾸지 않는다. 그러면 제외하기로 한 실제 적용/저장 동작과 혼동된다.
- 원본에 없는 저장 처리·성공 토스트·추가 저장 확인 모달을 만들지 않는다. 입력 취소/복귀는 UI 메모리에서만 처리한다.

## D07. 헤더의 역할·진행 상태 규칙

- **Chosen**: 예시 프로젝트의 역할·진행 상태에 따라 HTML과 같이 표시한다. 역할은 실제 로그인 권한과 별개인 UI 예시 값이다.
- **Source**: 헤더 버튼 노출 질문 사용자 `1`.
- **Rationale**: 프로젝트 선택에 따라 실제로 달라질 헤더 모습을 공용 컴포넌트에서 일관되게 표현한다.
- PM은 모든 예시 프로젝트 작업 권한을 가진 것으로 표시하고, 비PM은 예시 권한 목록을 따른다.
- `redo` 권한이 있을 때만 재작업 버튼을 표시한다. `done` 권한이 있을 때만 완성 버튼을 표시하며 현재 회차가 이미 완성이면 완성 버튼을 비활성화한다.
- 완성본 이력이 0개면 완성본 버튼을 숨긴다. 개수는 선택 프로젝트의 예시 이력 길이로 계산한다. 현재의 정적 `완성본 1`을 모든 프로젝트에 고정하지 않는다.
- 역할 배지는 HTML처럼 PM·작성자·리뷰자를 조합하고, 해당 역할이 없으면 프로젝트 상태에 맞는 검토자/참여자를 표시한다.
- 회차 상태 표시는 1차 작성 중 / N차 재작업 중 / N차 완성으로 구분한다. HTML의 프로젝트 진행 결정 전 상태(`p.status === "review"`)에서는 회차 칩과 재작업·완성본·완성 묶음을 숨기고 설정은 유지한다. 이 상태 값은 `/workspace/review` 메뉴와 다른 의미다.
- HTML의 다른 업무 CTA(진행 결정·검수 요청·제출하기 등)는 이번 네 버튼 범위에 추가하지 않는다. 새 업무 루프나 메뉴 잠금 정책도 임의로 만들지 않는다.

## D08. 리뷰 메뉴의 PM 조건과 이동

- **Chosen**: 선택한 예시 프로젝트에서 내가 PM일 때만 사이드바의 리뷰 메뉴를 표시한다. 리뷰 화면에서 PM이 아닌 프로젝트로 바꾸면 `/workspace/write`로 이동한다.
- **Source**: 마지막 메뉴 노출 질문 사용자 `2`.

## D13. 발견한 인접 사항 — 보고만, 범위 추가 없음

4. **Tailwind 탐색 범위가 제한됨**: 팀원 CSS를 되돌리거나 범위를 넓히지 않아도 기존 Griffel로 구현 가능하다. 전체 Tailwind 설정 정리나 DadamControls/CommonButton 통합은 범위 밖이다.
