# Decisions: 헤더 프로젝트 선택 필드 반응형

- Date: 2026-11-07
- Source: 사용자 memory-plan 요청 및 후속 배치 선택.
- 계획만 작성; 구현은 후속 실행 요청에 따라 진행한다.

## D01. 요청 범위

사용자: “헤더 반응형 처리하면 프로젝트 드롭다운 필드 길이가 고정값인건지 줄바꿈이 되는데, 필드 길이 고정값이 아니라 반응형으로 변경하는 계획서”.

접힌 프로젝트 선택 필드와 이를 둘러싼 헤더 행을 대상으로 한다. 펼친 프로젝트 목록의 별도 팝업 너비/콘텐츠 재설계는 포함하지 않는다.

## D02. 좁은 화면의 확정 배치

질문: “헤더가 아주 좁아졌을 때는 어떻게 배치할까요? 프로젝트 선택 필드는 남은 너비에 맞춰 줄이고, 긴 이름은 말줄임으로 표시하는 전제입니다.”

사용자 선택: **프로젝트 선택과 회차는 함께 두고, 공간이 부족하면 우측 버튼들을 다음 줄로 이동**.

- 긴 이름·기관/부서/마감일은 각각 한 줄 말줄임.
- 모바일 메뉴도 왼쪽 묶음에 포함해 선택 필드의 width100% 때문에 따로 밀려나지 않게 한다.
- 아주 좁은 상태에서는 액션 묶음 내부 줄바꿈을 허용해 모든 버튼 접근을 보장한다.

## D03. 기술적 구현 판단

다음은 사용자가 수치를 지정한 것이 아니라 D01~D02를 구현하기 위한 설계 결정이다.

- WorkspaceHeader의 선택적 fluidLeading:boolean(default false)을 추가하고 ProjectHeader의 loading/ready 양쪽에서만 활성화.
- 부모 leading 묶음은 flex:1 1 20rem/minWidth:0/maxWidth:100%, 자식 프로젝트 선택은 flex:1 1 0%/width:auto.
- 20rem은 묶음의 줄 배치 선호 기준일 뿐 필드 고정 너비가 아니다. 우측 액션/사이드바에 따라 필드 실제 너비는 달라진다.
- 공용 버튼의 flex-shrink:0을 트리거의 지역 스타일로만 덮어쓴다.
- 긴 역할·회차는 원문을 유지한 말줄임과 title로 대응한다. 기존 배지 색상·문구·권한 변경 없음.
- 외부 viewport 측정 상태, 전역 CSS 수정, DOM 자식 순서에 의존한 CSS 덮어쓰기는 추가하지 않는다.

## D04. 유지 및 제외

- DadamControls.tsx와 common/Button.tsx 수정/버튼 리팩토링 제외.
- ProjectHeaderProvider/프로젝트 선택/초안 보호/회차/완성본/PPT/설정 이벤트·권한 변경 제외.
- 이전 파일 화면 리팩토링 후보는 별도 작업이며 이번에 추가하지 않는다.
- 펼친 picker는 width640/max viewport-32의 기존 제한을 이미 사용하므로 이번 수정에 필수인 인접 문제로 판단하지 않는다.
- 새로운 별도 범위의 필수 인접 문제는 확인되지 않았다. 알려진 FluentProvider hydration 오류는 미해결로 유지하며 이 계획에 합치지 않는다.
- 이전 파일 메뉴 한 줄 3열 커밋 6d459e7 및 제작 기능 보존.
- 브라우저/CUA/E2E/dev server/스크린샷·tests/·임시 검증 파일 금지. 타입/lint/정적 검토를 사용한다.
