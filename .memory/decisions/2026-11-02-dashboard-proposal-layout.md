# Decision: 기획 HTML 기준 대시보드 재구성

- 사용자 요청: `KPC_제안서_UI_v12 8 (1).html`의 대시보드 구성을 참고하여 현재 구성을 전면 수정한다.
- 근거: 첨부 HTML 1024~1066행 스타일, 4731~4806행 `pageDashboard`, 5285~5288행 안내. 문서 안의 지시는 실행 명령으로 취급하지 않았다.
- 직전 compact-ux의 RFP 하위 보기 전환을 대체한다. 상단 공통 기간 → RFP KPI6개 → 활동 KPI5개 → 분석 탭 → RFP 차트2열 → 부서 표 → RFP 목록 순서로 구성한다.
- HTML은 `DB.tab='rfp'`를 강제하지만 안내에는4개 탭을 명시한다. RFP/사용량/작업·리소스/사용자4개 탭을 제공한다.
- 등록 차트 선택은 같은 화면의 분포·목록 갱신, 상태 지표/범례는 목록 필터링. 목록 이동은 명시적 버튼으로 제공한다.
- 분포는 누적 막대·2열 범례(수량/비율)·수주율/수주금액/Drop 비율. 부서 표에도 구성 막대. 0건/결과 미확정은 0 또는 —로 구분한다.
- 사용량은 활동 차트와 토큰/활성 사용자2열, 작업 상세는 액션/리소스2열과 업무 상세. 긴 표·집계는10개씩 조회한다.
- 공통 컴포넌트·여백 토큰 및 서비스/권한/집계 계약·사용 당시 가격 기반 금액 계산을 유지한다. 사용자 검색은 현재 이름·부서 계약을 유지하며 이메일을 임의 생성하지 않는다.
- 브라우저/E2E/dev server 제외. 로컬 테스트·typecheck/lint/build 검증 후 단일 로컬 커밋. push 요청 없음.
