- **Rationale**: 사용자는 기존 관리자 화면과 같은 방식의 구현을 요청했고, 마지막 선택에서 제작 설정·제작까지 연결하는 대신 관리자 메뉴 안의 적용 테스트를 선택했다.
- 사용자 선택: Template에서 Skill 선택 → 실제 적용 → 전후 비교 → PPT 다운로드 흐름을 이번 범위에 포함한다.

## D02. Skill·Template의 관리 동작과 정보 구조

- **Chosen**: 기획 HTML의 목록·검색·공개 범위/상태 필터·상세·등록·수정·복제·활성/비활성·삭제 흐름을 기존 관리자 컴포넌트로 구성한다. 관리 데이터는 mock이며 파일 분석·변환은 실제 동작으로 구분한다.
- **Rationale**: 메뉴와 관리 UX는 기획 HTML을 따르면서 실제 파일을 읽겠다는 사용자 선택을 반영한다.
- 코드 확인으로 정한 기본값: Skill의 실제 입력 화면은 기본 정보, 글꼴, 간격, 표, 도형/이미지, 여백/안내선, 보정, 페이지 유형, 공개 범위의 9개 영역을 기준으로 한다. 도움말에 남은 7단계 설명을 구현 범위로 삼지 않는다.
- Template은 업로드·추출 결과·설정 편집·저장의 흐름을 제공한다. 적용 테스트에서 등록 자산을 자동 수정하지 않는다.
- 기존 HTML의 전사·부서·그룹·개인 공개 범위를 현재 앱의 사용자·부서·그룹 ID에 연결한다. 공개 범위와 소유 부서는 별도 정보다.
- 필드명·타입·서비스 메서드·파일별 수정 위치는 다음 계획에서 구체화한다.

## D03. 관리자별 소유권과 CRUD 권한

- **Chosen**: 슈퍼 관리자는 전사 자산을 관리하고, 부서 관리자는 자기 부서 자산을 등록·수정·삭제한다. 다른 부서가 공유한 자산은 조회·적용할 수 있다. 일반 사용자에게 관리자 메뉴를 제공하지 않는다.
- **Rationale**: 사용자 선택으로 확정한 관리 범위이며, 공개와 편집 권한을 혼동하지 않기 위함이다.
- 기존 역할별 CRUD(등록·조회·수정·삭제) 설정에 Skill·Template을 추가하되, 체크박스가 소유 부서 경계나 역할 상한을 우회하지 않게 한다.
- 슈퍼 관리자만 역할별 권한을 편집하는 기존 정책을 유지한다. 부서 관리자에게 Skill·Template 관리 권한을 추가한다고 사용자·그룹 관리 권한까지 확대하지 않는다.
- 메뉴·액션은 권한이 없으면 렌더링하지 않는다. 서비스에서도 행위 권한·대상 부서·현재 공개 범위를 검사한다.
- 목록뿐 아니라 상세·필터 후보·추출 정보·파일 적용·다운로드도 허용 범위에 맞춘다. 부서를 알 수 없다고 전사 범위로 대체하지 않는다.

## D04. 부서 자산의 전사 공개

- **Chosen**: 부서 관리자는 자기 부서 자산을 별도 승인 절차 없이 전사에 공개할 수 있다. 공개 후에도 원래 소유 부서가 수정 권한을 유지한다.
- **Rationale**: 사용자 선택. 공개는 이용 범위를 넓히는 동작이며 소유권 이전이 아니다.
- 다른 부서에는 조회·적용만 허용한다. 전사 공개 여부로 모든 부서에 편집 권한을 주지 않는다.
- 공개 범위 변경은 이용 권한에 영향을 주므로 버전 내용 변경과 구분하여 처리한다.

## D05. 실제 PPT 추출과 이전 PoC 재사용

- **Chosen**: 실제 PPTX를 열어 슬라이드·텍스트·표·이미지·마스터·레이아웃·관계 정보를 분석한다. 이전 대화에서 찾은 v3.4 PoC의 분석·변환·보고서 모듈을 검토하여 현재 앱에 맞게 재사용한다.
- **Rationale**: 사용자가 mock 추출 대신 실제 추출을 선택했고, 이전 기술 검증의 대화와 구현을 참고하도록 요청했다.
- 참조 소스: `C:/Users/k2020/Documents/Codex/2026-10-23/new-chat/work/kpc-skill-poc/`.
- 확인한 모듈: `src/_scheme/skill.ts`, `src/_types/template.ts`, `src/_lib/pptx-xml.ts`, `template-read.ts`, `template-apply.ts`, `shared-design.ts`, `template-results.ts`.
- 코드 확인으로 정한 기본값: 기존 PoC가 지원하는 `.potx` 입력과 `.pptx` 출력 변환도 파일 유형 검증과 함께 재사용한다.
- JSZip과 XML 처리를 사용하는 규칙 기반 브라우저 변환이다. AI·RAG·LLM·Agent 호출을 추가하지 않는다.
- PptxGenJS로 새 샘플 PPT를 만드는 별도 경로와 업로드 PPT의 XML을 수정하는 경로를 혼동하지 않는다. esbuild 독립 HTML 빌드와 기존 vendor 전역 구성을 Next 앱에 그대로 이식하지 않는다.

## D06. Template과 Skill의 서식 우선순위

- **Chosen**: 글꼴·글자 크기·줄 간격·표 서식은 Skill 규칙을 우선 적용한다. Template의 색상·로고·기본 배치를 유지하고, 배치 변경은 사용자가 명시적으로 옵션을 켰을 때만 적용한다.
- **Rationale**: 사용자 선택으로 기존 PoC의 기본 적용 방향을 채택했다.
- 기존 파일의 내용·관계·미변경 구성 파일을 보존하고, 재적용은 항상 원본의 사본에서 시작한다. 이미 변환한 출력에 반복 적용하여 변경을 누적하지 않는다.
- 현재 작업의 편집 설정과 등록 자산 버전의 불변 원본을 구분한다.

## D07. 공유 디자인 편집의 영향과 저장 위치

- **Chosen**: 마스터·레이아웃의 로고·공통 글꼴 등 공유 디자인 편집은 현재 PPT 작업과 출력에만 반영한다. 등록된 Template을 바꾸려면 별도의 Template 수정 화면에서 새 버전을 저장한다.
- **Rationale**: 사용자 선택. 적용 테스트의 편집이 다른 작업이 사용하는 등록 자산을 자동으로 바꾸지 않게 한다.
- 코드 확인으로 정한 기본값: 공유 원본 편집은 해당 마스터·레이아웃에 연결된 모든 슬라이드에 영향을 준다. 적용 전 연결 범위를 표시하며, 일부 슬라이드 선택만으로 공유 변경의 영향이 제한된다고 표현하지 않는다.
- v3.4의 공유 그룹 내부 요소 편집을 검토하여 재사용한다. 일반 슬라이드 그룹의 자동 적용과 명시적 공유 그룹 편집의 지원 범위를 구분한다.
- 그룹 구조·좌표·요소 ID·문구·관계를 유지한다. 크기·간격 등 공간 검사가 필요한 변경은 지원 가능한 경우에만 수행하고, 공유 요소의 연결 페이지에서 검사에 실패하면 해당 변경을 복원하고 이유를 표시한다.
- 이 편집 설정은 작업에 별도로 보관하며 Skill JSON이나 작업에 보관한 Template 원본을 직접 덮어쓰지 않는다.

## D08. 수정 버전과 명시적인 최신 버전 재적용

- **Chosen**: 작업은 적용 당시 Skill·Template 버전과 결과를 유지한다. 등록 자산이 수정되면 ‘새 버전 있음’을 알리고, 사용자가 ‘최신 버전 재적용’을 실행했을 때만 새 설정을 적용한다.
- **Rationale**: 수정사항을 원하지 않을 수도 있고 필요할 때만 반영하고 싶다는 사용자의 후속 설명을 우선한다. 초기의 자동 최신 전환·강제 재적용 선택은 이 결정으로 대체됐다.
- 등록 자산에 새 버전이 생겼다는 이유만으로 기존 결과 다운로드를 차단하지 않는다.
- 적용 당시 설정과 원본 파일을 함께 참조하는 변경 불가능한 버전 사본을 보관하여, 원본 자산의 최신 내용으로 과거 작업이 바뀌지 않게 한다.
- 현재 작업 자체의 입력·편집 설정·적용 대상이 바뀐 경우에는 현재 설정에 대한 결과가 아직 생성되지 않았음을 표시한다. 이 상태를 등록 자산의 새 버전 알림과 혼동하지 않는다.
- 재적용 실패 시 이전 적용 버전과 성공 결과를 새 성공 결과인 것처럼 덮어쓰지 않는다. 원자적인 결과 교체와 동시 수정 검사는 기존 서비스 패턴에 맞춰 계획한다.

## D09. 비활성화·삭제와 권한 회수의 구분

- **Chosen**: 비활성화·삭제된 자산은 새 작업에서 선택할 수 없지만, 기존 작업은 보관된 버전으로 재적용·PPT 생성·결과 다운로드를 계속할 수 있다. 공개 범위 변경 등으로 현재 이용 권한을 잃으면 기존 작업에서도 이 동작들을 차단한다.
- **Rationale**: 기존 템플릿을 유지하고 싶다는 요구와 별도로, 권한 회수는 기존 작업에도 즉시 적용하는 사용자 선택을 반영한다.

| 발생한 변경 | 기존 작업의 버전·결과 | 기존 작업의 재적용·생성·다운로드 | 새 작업 선택 |
| --- | --- | --- | --- |
| 설정 수정 | 기존 버전 유지, 새 버전 알림 | 기존 버전으로 가능, 명시적 최신 재적용 가능 | 활성·접근 허용된 최신 버전 |
| 비활성화 | 적용 당시 버전 유지 | 현재 이용 권한이 있으면 가능 | 불가 |
| 삭제 | 적용 당시 버전 유지 | 현재 이용 권한이 있으면 가능 | 불가 |
| 이용 권한 회수 | 보관 사본이 권한을 대체하지 않음 | 차단 | 불가 |

- 삭제 시 참조 중인 버전·파일과 권한 판단 정보를 즉시 제거하지 않는다. mock에서도 삭제 상태와 작업 참조를 구분한다.
- 비활성화·삭제된 과거 버전을 새 작업의 적용 대상 선택 목록에 제공하지 않는다.
- 작업 보관본 자체는 수정할 수 없다. 출력에 대한 공유 디자인 편집은 D07의 별도 작업 설정으로 처리한다.
- 권한 검사는 적용 시작뿐 아니라 비동기 처리 완료 및 다운로드 시점에도 현재 상태를 기준으로 한다.
- 이미 사용자가 내려받은 로컬 PPT 파일을 회수하거나 사용을 막는 DRM은 이 정책의 기능이 아니다. 이번 mock의 화면·서비스 제어를 서버 보안 구현으로 표현하지 않는다.

## D10. 다른 부서 자산 복제

- **Chosen**: 원본 조회 권한과 해당 종류 자산의 등록 권한이 있는 관리자는 다른 부서의 공개 자산도 복제할 수 있다. 사본은 자기 부서의 독립 자산이 된다.
- **Rationale**: 사용자 선택. 재사용과 자기 부서의 독립적인 수정을 허용한다.
- 새 ID·소유 부서·수정 버전을 부여하며, 원본 수정이 사본에 자동 동기화되지 않는다.
- 원본의 부서 소유권이나 편집 권한을 그대로 복제하지 않는다. 사본의 권한은 사본 자산 기준으로 관리한다.

## D11. 부분 적용과 지원 한계

- **Chosen**: 정상 파일에서 일부 요소를 처리할 수 없으면 지원되는 요소만 적용하고 나머지는 원본으로 보존한다. 변경·원본 유지·적용 제외 상태와 사유, 전후 비교를 제공하고 결과 다운로드를 허용한다. 파일 손상·권한 오류는 전체 작업을 차단한다.
- **Rationale**: 사용자 선택. 일부 요소의 제한 때문에 전체 파일 사용을 막지 않으면서 적용 범위를 확인할 수 있게 한다.
- 코드 확인으로 정한 기본값: 차트·SmartArt·OLE·이미지 안의 글자·복잡한 공유 표 등은 보존 또는 제한 사유를 표시한다. 지원하지 않는 요소를 임의로 평탄화하거나 삭제하지 않는다.
- 기존 PPT 변환에서는 자동 슬라이드/표 분할을 지원한다고 약속하지 않는다. 새 샘플 PPT 생성 PoC의 분할 기능은 이번 기존 파일 변환의 보장 범위가 아니다.
- 구조 기반 미리보기와 PowerPoint 실제 렌더링은 다르다. 변경 건수는 시각적 차이 건수와 같지 않을 수 있다.
- 손상 파일, 과도한 압축 해제, 취소·실패·빈 결과를 성공 결과와 구분하고 진행 상태를 표시한다.

## D12. 파일 처리 한도

- **Chosen**: 코드 확인으로 정한 기본값으로 PoC의 입력 250 MiB, 슬라이드 200장, 압축 해제 단일 항목 256 MiB·합계 1 GiB 제한을 계승한다. 실제 브라우저에서 검증할 수 있도록 계획한다.
- **Rationale**: 기존에 용량 검증과 미리보기 제한을 구현한 경로를 재사용하되 지원 한도를 성능 보장으로 오인하지 않기 위함이다.
- 이미지 미리보기는 이미지별 8 MiB·2,400만 화소, 전체 원본 이미지 바이트 64 MiB 한도를 참고한다. 미리보기 생략과 다운로드 원본 미디어 손실을 구분한다.
- 원본·압축 해제·수정·출력 데이터가 함께 메모리를 사용하므로 여러 큰 파일을 쌓아도 안전하다고 가정하지 않는다. 작업 정리와 임시 URL·파일 참조 해제를 계획한다.
- 과거의 약 204 MB 합성 파일 시험 기록은 모든 PC·브라우저·고객 파일의 처리 보장이 아니다.

## D13. mock 저장소와 파일의 수명

- **Chosen**: 코드 확인으로 정한 기본값으로 기존 관리자 mock의 수명을 계승한다. 관리 데이터·적용 테스트 작업·업로드 파일은 현재 브라우저 실행 중 메모리에 유지하고, 전체 새로고침 시 초기화한다.
- **Rationale**: 선행 관리자 결정 D13과 `AdminRuntimeProvider`가 이미 이 방식을 사용한다. 별도 영구 보관 요구 없이 새로운 로컬 저장소를 추가하지 않는다.
- 메뉴 이동이나 Query 캐시 교체만으로 저장한 관리 변경·작업이 사라지지 않도록 한다. 실제 인증 사용자 변경 시에는 이전 사용자의 상태와 파일을 정리한다.
- 작업 보관 정책은 이번에는 실행 중인 mock 작업에 적용되며, 새로고침 이후 장기 보관을 제공한다는 뜻이 아니다. UI에서 임시 보관임을 안내한다.
- 화면 → TanStack Query → 타입이 있는 데이터 서비스 → mock 저장소를 유지한다. 파일 바이트·ZIP 객체·미리보기 URL은 직렬화 가능한 관리 정보와 분리한다.
- 이전 PoC의 localStorage Skill 라이브러리·로컬 그룹 저장소를 가져와 현재 사용자·부서·그룹을 이중 관리하지 않는다.
- Zod 경계 검증, 전체 타입에서 Pick/Omit으로 파생하는 타입 전략, 내부 any/unknown 금지, 직접 fetch 대신 기존 Query 패턴을 적용한다.
- 향후 Cosmos DB/파일 저장 연동을 교체 가능한 경계로 준비하되 이번에 컨테이너·파티션 키·Blob 업로드·프로비저닝을 설계하거나 실행하지 않는다.

## D14. 디자인 컴포넌트와 현재 관리자 기능 재사용

- **Chosen**: 코드 확인으로 정한 기본값으로 기존 Fluent UI 컨트롤과 Tailwind 레이아웃, 공통 관리자 UI·테마를 재사용한다. 자산 관리와 PPT 변환 로직을 화면 스타일에서 분리한다.
- **Rationale**: 디자인 전문 업체의 후속 변경에 대응하면서 기존 관리자 UX와 일관성을 유지한다.
- 우선 검토: `components/admin/ui/`, `components/ui/ModalFrame.tsx`, `SegmentedControl.tsx`, `ToggleSwitch.tsx`, `components/providers/FluentUiProvider.tsx`, `app/admin-theme.css`.
- 재사용 가능한 자산 목록·필터·공개 범위 선택·상태/버전 표시·파일 입력·전후 비교·결과 목록과 Skill/Template 전용 폼을 구분한다.
- 디자인 값 변경은 공통 테마에서 다루되, 최종 정보 구조가 바뀌면 화면 구성 수정이 필요할 수 있음을 유지한다.
- 기존 관리자 작업과 동일하게 실제 관리 변경은 공통 감사 기록으로 연결한다. 동일 사건을 여러 저장소에 중복 기록하지 않는다.
- 구현 단계의 디자인 컴포넌트 HTML 정리는 재사용 경계와 화면별 사용처를 설명하도록 기존 산출물을 참고한다. 이번 인터뷰에서 디자인 확정본이나 구현 완료 HTML을 새로 만들지는 않는다.

## D15. 실제 인증과 mock 권한의 경계

- **Chosen**: 실제 로그인은 기존 User/Admin 서버 가드를 유지하며, 슈퍼 관리자·부서 관리자·일반 사용자 시연은 기존 mock 업무 역할을 사용한다.
- **Rationale**: 현재 실제 인증은 2단계이고 부서·3단계 역할이 서버 신뢰 정보로 완성되어 있지 않다. 클라이언트 미리보기 값을 실제 권한 근거로 사용하지 않는다.
- 인증이 켜진 상태에서 클라이언트 역할 조작으로 접근을 넓히지 않는다. 일반 사용자의 직접 관리자 URL 접근도 기존 서버 가드를 통과해야 한다.
- 이번 mock 권한 검사·삭제·권한 회수는 동작 검토용이다. 후속 서버 연결에서는 입력·사용자·부서·대상 버전·행위 권한을 서버에서 다시 검증해야 한다.
- Entra 역할/부서 연동, 실서비스 파일 보호, 저장 보존 기간·물리 삭제 정책은 이번에 임의로 구현 범위에 추가하지 않는다.

## D16. 계획·실행 단계 검증 기준

- **Chosen**: 다음 memory-plan에서 아래 동작을 검증할 Task와 명령을 작성한다. 과거 PoC 통과 기록을 현재 앱의 통과 결과로 사용하지 않는다.
