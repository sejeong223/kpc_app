## D02. 추가 화면 범위 — 사용자 확인 완료

질문: `사용량 상세 분석·토큰 추가 신청` 버튼의 구현 범위.

선택: **이번에는 3개 탭·권한 전환·알림/설정의 로컬 동작까지 구현하고, 상세 분석·신청은 안내만 표시**.

따라서 상세 분석·토큰 신청 버튼은 같은 모양으로 보이고 준비 중 안내를 표시한다. 추가 폼·상세 팝업·서버 처리는 계획하지 않는다. 기존 URL에 대응하는 관리자 토큰 관리 링크와 프로젝트/알림 링크만 연결한다.

## D03. 공용 컴포넌트와 Fluent UI

첨부한 `본문 / 슬라이드` 형태는 재사용 가능한 `SegmentedControl`, 빨간 ON/OFF 형태는 `ToggleSwitch`로 분리한다. 프로필 내부 역할·알림 필터·화면 기본값·알림 설정에서 재사용하며 문구·업무 상태는 호출자가 전달한다. 이전 사용 지시에 따라 기존 Fluent UI v9를 사용하고 스타일은 해당 TSX의 makeStyles 안에 둔다. 팝오버의 탭은 Fluent TabList/Tab, 세그먼트는 RadioGroup/Radio, ON/OFF는 Switch로 구현한다.

## D04. 인증 후순위와 역할 미리보기

현재 인증 비활성 개발 화면에서 일반 사용자/관리자를 누르면 선택 상태·프로필 배지·사이드바 관리자 메뉴가 함께 바뀐다. HTML의 초기 `role:'admin'`을 따라 최초 표시는 관리자다. 일반 사용자는 일반 메뉴 7개, 관리자는 총 15개다. 이름·소속 샘플은 그대로 둔다.

이는 로컬 UI 시연 상태다. 실제 session·토큰·쿠키·인증 여부를 변경하지 않는다. `AUTH_ENABLED=true`에서는 실제 세션 역할을 사용하고 전환 컨트롤을 비활성화한다. 기존 서버 가드를 약화하지 않는다. 관리자 안내 화면을 보는 중 일반 사용자로 바꾸면 `/workspace/pipeline`으로 이동한다.

## D05. 저장과 시연 동작

역할·선택 탭·필터·알림 읽음·환경 설정은 앱 레이아웃 Provider의 메모리에 저장한다. 닫았다 열기와 클라이언트 라우트 이동 중 유지하며 전체 새로고침 시 초기화한다. 이 저장 범위는 구현 기본값이며 실제 설정 저장/알림 발송 기능은 아니다.

사용량 `72,400 / 100,000`, 알림 4개·미확인 2개는 원본의 고정 시연 값을 사용한다. 작업 카드 숫자는 담당 프로젝트 3·반영할 의견 2를 명시적 시연 fixture로 둔다. 원본의 업무 데이터 전체를 이식하거나 실제 집계값이라고 표시하지 않는다. 기존 샘플에 정소담의 추가 신청 건은 없으므로 최초 신청 상태 배너는 표시하지 않는다.

시작 화면은 원본 기본값 `my`가 최종 선택지 `pipeline/make`와 맞지 않으므로 현재 메뉴의 `pipeline`으로 정규화한다. 선택 값은 `pipeline/write`, `doc/slide`, `table/board`를 사용하고 실제 편집기·목록 뷰는 만들지 않는다.

## D06. 화면·접근성

기본 팝오버 `348px × 최대 620px`, 프로필 위 8px, 흰 헤더와 footer·밝은 회색 스크롤 본문·빨간 활성 탭을 재현한다. 프로필 클릭/Enter/Space, 닫기, 외부 클릭, Escape, 포커스 복귀를 포함한다. 접힌 사이드바와 모바일에서도 같은 내용을 사용할 수 있게 한다.

모바일 메뉴의 기존 포커스 순회와 팝오버의 포커스 트랩이 충돌하지 않도록 계획한다. Escape 한 번은 안쪽 프로필만 닫고, 이후 Escape가 모바일 메뉴를 닫는다.

## D07. 보존 범위와 현재 변경

기존 로그인 진입·실로그아웃·Azure 서비스·Cosmos DB 스킬·15개 메뉴 순서·사용자 제공 CollapseIcon/ExpandIcon을 보존한다. `NavSidebar.tsx`의 기존 미커밋 구분선 변경(좌우 6px·width auto)도 보존한다. 과거 결정의 프로필 비대화형·역할 전환 제외 항목은 이번 기능 범위에 한해 새 결정으로 대체하며 과거 기록은 삭제하지 않는다.

현재 요청은 memory-plan이다. 구현·패키지 설치·실제 Azure 작업·Git 커밋 없이 계획 문서와 current 포인터만 작성한다.
