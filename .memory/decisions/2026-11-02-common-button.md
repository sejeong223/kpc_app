## D01. 제공 범위

- **Chosen**: 재사용할 공통 `Button`과 사용 예시를 준비한다. 기존 화면의 버튼은 교체하지 않는다.
- **Source**: 사용자 요청 및 두 번째 질문의 1번 선택.
- **Rationale**: 새 버튼을 필요한 곳에서 가져다 쓸 수 있도록 기반을 만들면서 기존 화면의 동작과 배치를 보존한다.
- 사이드바·프로필·토큰 창·코멘트·관리자·로그인의 기존 버튼을 일괄 이관하지 않는다.
- 사용 예시는 개발자를 위한 문서와 코드 예제로 제공한다. 별도 공개 페이지·메뉴·Storybook·디자인 카탈로그를 새로 만들지 않는다.
- HTML에 있는 업무 처리·다운로드·AI 작업을 버튼 컴포넌트에 구현하지 않는다. 클릭 후 동작은 호출부가 전달한다.

## D02. 클래스 기반 크기와 배치

- **Chosen**: 기존 Tailwind의 `tw:` 접두사를 유지한다. `className="tw:w-4 tw:h-5 active"`처럼 사용한다.
- **Source**: 사용자 요청 및 세 번째 질문의 1번 선택.
- **Rationale**: 프로젝트의 기존 클래스 표기와 CSS 생성 경로를 재사용한다.
- `width`·`height` 전용 속성이나 고정 크기 목록을 별도로 만들지 않는다. 너비·높이·최소/최대 크기·패딩·간격·정렬·반응형 배치는 `className`으로 조정한다. 표준 `style` 속성도 전달할 수 있다.
- `w-4`, `h-5` 같은 접두사 없는 Tailwind 클래스의 별도 지원이나 기존 클래스 전체 변경은 하지 않는다.
- 기본값보다 호출부의 명시적 크기·패딩·배치 클래스가 우선해야 한다. 고정 `min-width`·`min-height`가 작은 크기 지정을 막지 않도록 한다.
- 작은 아이콘 전용 버튼은 패딩과 아이콘 크기도 함께 조절하는 예시를 제공한다. 숫자 4/5는 픽셀값 자체가 아니라 기존 Tailwind 간격 단위다. 내용이 들어가지 않는 크기를 자동으로 적정 크기로 확대하는 기능은 추가하지 않는다.
- 클래스는 소스에 완전한 문자열로 작성한다. 런타임 문자열 조립으로 임의 클래스를 생성하는 별도 변환기는 만들지 않는다.

## D03. 아이콘과 텍스트의 자유로운 조합

- **Chosen**: 버튼 내부는 React `children`으로 자유롭게 구성한다. 아이콘·텍스트의 순서와 위치를 사용처의 클래스로 조절한다.
- **Source**: 네 번째 질문의 1번 선택.
- **Rationale**: 왼쪽/오른쪽 아이콘, 양쪽 아이콘, 아이콘만, 텍스트만, 세로 배치를 같은 버튼으로 표현할 수 있다.
- `icon`, `iconPosition`, `label` 등 별도 배치 속성은 만들지 않는다. 내부에 의무적인 텍스트 래퍼를 삽입하거나 자식을 분석·복제·재정렬하지 않는다.
- 기본 배치는 가로 중앙 정렬이다. `tw:flex-col`, `tw:justify-start`, `tw:justify-between`, `tw:gap-2` 등으로 바꿀 수 있다. 글자의 정렬과 실제 배치는 각각 `text-align`과 flex 정렬의 역할에 맞게 예시에서 설명한다.
- 기존 `@fluentui/react-icons` 아이콘을 사용 예시에 재사용한다. 새 아이콘 라이브러리는 추가하지 않는다.
- 아이콘 전용 버튼은 사용처가 의미 있는 `aria-label`을 제공한다. 장식 아이콘은 `aria-hidden`으로 중복 읽기를 막는다. 버튼 안에 다른 버튼·링크·입력 요소를 중첩하지 않는다.

## D04. 선택 상태와 클릭 불가 상태

- **Chosen**: `active` 클래스는 선택이 유지되는 상태를 뜻한다. 클릭 불가는 표준 `disabled` 속성으로 별도 지정한다.
- **Source**: 첫 번째 질문의 1번 선택.
- **Rationale**: 필터·토글의 선택과 사용 불가 상태는 서로 독립적이다. 선택된 버튼이 일시적으로 비활성화될 수도 있다.
- `active`는 마우스를 누르는 순간의 CSS `:active`와 구별한다. 기본·hover·누르는 동안·선택 유지·키보드 포커스·disabled 상태를 제공한다.
- 버튼은 내부 선택 상태를 보관하거나 클릭 시 자동 토글하지 않는다. 사용처가 상태를 관리하고 `active` 클래스를 추가·제거한다.
- `active`는 외형을 나타낸다. 토글 버튼에서는 같은 상태값으로 `aria-pressed`도 전달하여 보조 기술에 선택 여부를 알린다. 일반 실행 버튼에 일괄적으로 `aria-pressed`를 붙이지 않는다.
- 비활성화는 `disabled` 클래스나 회색 표현만으로 구현하지 않는다. 네이티브 `disabled`로 마우스/키보드 실행과 폼 제출을 차단한다. `aria-disabled`만 전달하는 것을 동작 차단으로 설명하지 않는다.
- 프리셋의 기본 disabled 표현이 선택·hover·누름 표현보다 우선한다. 사용처가 명시적으로 비활성 색을 바꾸더라도 실제 클릭 불가 동작은 유지한다.
- 버튼·프리셋의 기본 테두리 두께를 일정하게 유지하여 선택 전환으로 크기가 바뀌지 않게 한다. 선택 강조가 필요하면 색상·안쪽 강조 등 크기에 영향을 주지 않는 방법을 사용한다.

## D05. 스타일 프리셋과 색상 조정

- **Chosen**: 기본형과 `primary`, `ghost`, `soft`, `dark`, `danger` 프리셋을 제공한다. 각 상태의 기본 색을 제공하고 사용처의 클래스로 조정할 수 있게 한다.
- **Source**: 다섯 번째 질문의 1번 선택.
- **Rationale**: HTML에서 반복되는 버튼 역할을 공통화하면서 색상은 현재 dadam 룩앤필에 맞춘다.

| 클래스 | 기본 역할 | 디자인 기준 |
| --- | --- | --- |
| 생략 | 일반·보조 실행 | 밝은 표면, 중립 글자와 얇은 테두리 |
| `primary` | 주요 실행 | dadam 파란 배경과 흰 글자 |
| `ghost` | 낮은 강조·도구 버튼 | 투명 배경, 중립 글자, hover 강조 |
| `soft` | 옅은 강조 | 옅은 파란 배경, 파란 글자·테두리 |
| `dark` | 진한 중립 강조 | 진한 중립 배경과 밝은 글자 |
| `danger` | 삭제 등 위험 동작 | Fluent 위험 상태 색상으로 의미 구분 |

- 기본형에 별도 클래스는 필요하지 않다. `className="primary tw:h-8 tw:px-4"`처럼 프리셋 하나와 유틸리티를 조합한다. 여러 프리셋의 동시 지정은 지원 계약에 포함하지 않는다.
- `active`는 프리셋과 함께 사용할 수 있다. 선택 상태에서도 위험/중립/브랜드 역할이 무분별하게 같은 색으로 바뀌지 않게 한다.
- 배경·글자·테두리와 hover·선택·disabled 색을 사용처에서 바꿀 수 있어야 한다. 크기와 색상 변경을 위해 매번 별도 버튼 컴포넌트를 복제하지 않는다.
- 일반 Tailwind 색상 클래스는 지정한 속성을 상태 전반에서 덮어쓸 수 있다. 특정 상태만 바꾸려면 `tw:hover:...`, `tw:disabled:...`, `tw:[&.active]:...`처럼 상태를 지정하는 예시를 제공한다.
- 스타일 우선순위는 공통 기본값 → 프리셋/내장 상태 → 호출부의 명시적 유틸리티 순서로 설계한다. 단순히 `className` 문자열 뒤에 붙였다는 이유만으로 덮어쓰기가 보장된다고 가정하지 않는다.
- 프리셋 클래스는 공통 버튼 루트 내부에 한정하여 매칭한다. 전역 `.primary`, `.active`, `.danger` 규칙을 만들어 다른 요소를 변경하지 않는다.

## D06. dadam 디자인 기준과 테마 경계

- **Chosen**: 기존 `lib/ui/dadam-theme.ts`의 `dadamTheme`·`dadamUi`와 로컬 Spoqa Han Sans Neo 서체를 재사용한다.
- **Source**: 사용자 요청, 코드 확인 및 설계 기본값.
- **Rationale**: HTML의 빨간 강조색·둥근 모서리를 그대로 복제하면 현재 dadam UI와 다른 버튼이 된다.
- 기본 디자인 기준은 Fluent `webLightTheme` 계열 파란 강조색, dadam 서체, 14px/20px 글자, 500 굵기, 4px 모서리와 32px 컨트롤 높이다. 이 수치는 코드 기반 기본값이며 호출부의 크기·배치 조정을 막는 제한이 아니다.
- 내부 여백과 아이콘 간격에는 기존 `app/layout-tokens.css`의 적절한 역할 값을 우선 재사용한다. 새 페이지 외곽 간격 규칙을 만들지 않는다.
- 전역 `FluentUiProvider`에는 빨간 `--kpc-*` 브랜드값이 남아 있다. 공통 버튼이 dadam 범위 밖에 놓였을 때도 기본 프리셋이 임의로 빨간색으로 바뀌지 않도록 버튼 범위의 dadam 기준을 보장한다.
- 앱 전체 Provider나 `--kpc-*` 값을 파란색으로 변경하지 않는다. 버튼마다 레이아웃용 외부 래퍼나 새로운 CSS 렌더러·인증 Provider를 추가하지 않는다.
- 디자인 값의 원본은 기존 dadam 테마로 유지한다. 버튼 상태를 위한 역할 매핑은 추가할 수 있지만 기존 테마와 무관한 중복 팔레트를 따로 유지하지 않는다.
- focus-visible, 기존 reduced-motion 정책, 고대비 환경의 포커스/선택 식별을 보존한다.

## D07. 컴포넌트 계약과 구현 방향

- **Chosen**: 의미상 표준 HTML `button`인 가벼운 공통 컴포넌트로 구성하고, `children`, `className`과 표준 버튼 속성을 전달한다.
- **Source**: D02~D04와 코드 확인에 따른 설계 기본값.
- **Rationale**: 자유로운 자식 배치와 Tailwind 크기 조절을 유지하고, 브라우저가 제공하는 버튼 동작을 재사용한다.
- 구현 기본 방향은 네이티브 `button`과 공통 버튼에 한정된 스타일이다. 기존 Fluent 버튼 전체를 대체하지 않고 dadam 디자인 토큰을 재사용한다. Fluent 버튼의 내부 슬롯과 기본 최소 너비를 호출부에 강요하지 않는다.
- `onClick`, `disabled`, `type`, `name`, `value`, `form`, `title`, `aria-*`, `data-*`, `style`, DOM `ref` 등 표준 속성을 보존한다.
- 기본 `type`은 `button`으로 하여 폼 안에서 의도하지 않은 제출을 방지한다. 명시적 `type="submit"`·`type="reset"`은 그대로 동작해야 한다.
- 페이지 이동용 `href`·다형적 `as`·`asChild`, 자동 로딩·비동기 재시도·중복 요청 제어, 드롭다운, 분할 버튼, 내부 토글 상태는 추가하지 않는다. 관련 기능은 필요할 때 별도 결정한다.
- 기존 `SegmentedControl`, `ToggleSwitch`, 탭·링크·코멘트 핀의 역할과 키보드 동작을 이번 범용 버튼 하나로 통합하지 않는다.
- 현재 Tailwind 유틸리티는 CSS 레이어를 사용한다. 공통 버튼의 기본 크기·색상은 유틸리티보다 낮은 우선순위로 배치하여 사용처에서 `!important` 없이 조절할 수 있게 한다.
- `app/globals.css`의 레이어 밖 `font: inherit`·포커스 규칙도 함께 고려한다. 필요한 충돌 해소는 새 버튼에 한정하며 기존 버튼·링크의 스타일을 전역적으로 변경하지 않는다. 상세 파일 구성은 memory-plan에서 확정한다.
- 새로운 UI 라이브러리·Tailwind 중복 설치·새 상태 관리 도구는 도입하지 않는다. 서버 API·DB·인증·권한 변경은 없다.

## D08. 클래스 생성 범위와 사용 예시

- **Chosen**: 공통 버튼을 일반 앱 컴포넌트에서 사용할 수 있도록 기존 Tailwind 소스 탐색 범위를 필요한 만큼 보완한다.
- **Source**: 사용자 범용성 요구 및 코드 확인.
- **Rationale**: 현재 `app/admin-utilities.css`는 `source(none)`과 명시적 경로를 사용하며 `components/ui`, `components/profile`, `components/comments`를 포함하지 않는다. 해당 위치의 새 클래스가 소스에 있어도 CSS가 생성된다고 가정할 수 없다.
- 기존 `tw:` 접두사, Preflight 미도입, 기존 화면의 CSS 역할을 유지한다. 공통 컴포넌트와 사용처를 탐색하도록 보완하고 무관한 테스트·문서·첨부 HTML까지 전체 탐색하지 않는다.
- 사용 문서에는 기본/각 프리셋, 좌우·양쪽·세로 아이콘, 아이콘만, 전체 너비·고정 크기, 선택/disabled 동시 상태, 색상 덮어쓰기, 폼 제출과 `ref` 사용을 간결한 예시로 담는다.
- 토글 예시에서는 동일한 선택값으로 `active` 클래스와 `aria-pressed`를 제어한다. 일반 실행 버튼에는 해당 상태를 넣지 않는다.
- 문서의 사용 예시는 설계/개발 참고이며 실제 화면을 교체하거나 새 페이지를 추가하는 작업으로 확대하지 않는다.

- **Chosen**: 기존 지속 정책에 따라 브라우저 검증을 제외하고 계약에 맞는 자동 검증과 정적 검토를 수행한다.
- **Source**: `.memory/decisions/2026-10-30-task-validation-policy.md` 및 현재 저장소 상태.
- **Rationale**: 사용자가 지정한 검증 경계를 유지하면서 공통 버튼의 동작과 CSS 생성 여부를 확인한다.
- 구현 후 의미 있는 DOM 검증 대상은 기본/명시적 type, 클릭 및 disabled, children/표준 속성/ref 전달, 선택 상태의 호출부 제어와 접근성 예시다. CSS 숫자를 그대로 복사하는 테스트는 만들지 않는다.
- 유틸리티 생성·CSS 레이어 우선순위·기존 전역 규칙과의 충돌·테마 범위는 빌드 산출물과 정적 검토로 확인한다. jsdom을 실제 브라우저 레이아웃 계산의 증거로 사용하지 않는다.
- 검증 명령의 기본은 `npm.cmd run typecheck`, `npm.cmd run lint`, `npm.cmd run build`, `git diff --check`다. 필요한 로컬 DOM 검사는 현재 Vitest 설정에 맞춰 계획한다.
- 현재 `tests/` 폴더는 존재하지 않는다. `vitest.config.ts`는 여전히 `tests/**/*.test.ts`를 대상으로 한다. 과거 기록의 전체 테스트 수·통과 결과를 이번 검증 결과로 복사하지 않는다.
- 최신 관련 결정 `2026-11-02-workspace-spacing-system.md` D10에 따라 원격 테스트 삭제와 로컬 테스트 보관 정책을 유지한다. 필요한 로컬 검증은 가능하지만 테스트를 원격 저장소에 다시 추가하거나 없는 테스트 전체 실행을 통과로 보고하지 않는다.
- 브라우저/E2E/스크린샷/육안 비교·검증용 dev server는 실행하지 않는다. 실제 화면 미검증 사실과 자동 검증 결과를 구분한다.
- 이번 인터뷰에서는 코드·설정·테스트를 구현하거나 테스트·빌드를 실행하지 않았다. 결정 문서만 저장하며 기존 `.memory/current.md`, Plan/Phase/Task와 커밋 상태를 변경하지 않는다.

## 요청 범위 밖 발견사항 — 보고만

- 여러 화면에 Fluent 버튼의 크기·색상·상태 스타일이 반복된다. 이번에는 공통 버튼을 제공하며 기존 코드의 중복 제거·전체 이관은 별도 사용자 결정이 필요하다.
- 전역 KPC 빨간 테마와 일부 dadam 파란 테마가 공존한다. 새 버튼의 dadam 기준 보장은 이번 범위지만 앱 전체 테마 통합은 포함하지 않는다.
- SegmentedControl·ToggleSwitch는 이미 공통 구현이 있다. 버튼처럼 보인다는 이유로 해당 컴포넌트의 상태/키보드 기능을 중복 구현하지 않는다.
- 테스트 폴더 부재와 로컬 전용 테스트 정책 때문에 새 clone/CI에서 과거 검증 전체를 바로 재현할 수 없다. 테스트 공유 정책 복원은 이번 버튼 설계에 포함하지 않는다.
- 현재 탐색에서 별도 보안 취약점이나 깨진 사용자 경로를 확정하지 않았다. 참고 HTML의 시연 동작을 실제 구현 완료로 취급하지 않는다.

## D11. 계획 단계 추가 지시 — common 디렉토리와 기존 dadam 스타일

- **Chosen**: 새 범용 컴포넌트의 위치를 `components/common/`으로 정하고, 이번 버튼을 해당 디렉토리에서 제공한다. 폰트 등 스타일은 현재 사용하는 dadam 룩앤필을 그대로 참조한다.
- **Source**: 2026-11-02 사용자의 memory-plan 요청 — “폰트 등의 스타일은 기존에 사용하는 dadam 룩앤필을 그대로 사용하고, 공통 컴포넌트용 디렉토리 분기도 함께 해줘. common으로”.
- **Rationale**: 재사용 컴포넌트의 진입 경로를 명확히 하면서 기존 dadam 디자인과 별도의 스타일 원본이 생기는 것을 방지한다.
- `components/common/Button.tsx`와 해당 스타일·테마 연결 파일, `index.ts`, 사용 예시/README를 계획한다. 외부 사용 경로는 `import { Button } from "@/components/common"`이다.
- `components/ui`·`components/layout`의 기존 컴포넌트를 이동하거나 이름을 바꾸지 않는다. D01의 기존 화면 유지 범위 안에서 새 디렉토리를 만든다.
- 기본 서체는 기존 `dadamTheme.fontFamilyBase`의 `var(--dadam-font-family)`, 버튼 글자 크기/줄 높이/굵기는 기존 dadam의 14px/20px/500을 참조한다. 원본 `webLightTheme`의 600 굵기를 직접 사용하지 않는다. 새 폰트 파일·폰트 다운로드·별도 전역 타이포그래피를 추가하지 않는다.
- 이 단계에서는 `.memory/`의 문서만 작성한다. 실제 `components/common/` 생성과 앱 코드 변경은 실행 Task에서 수행한다.

## D12. 계획 단계 코드 확인 — 로컬 검증과 CSS 생성

- **Chosen**: T01에서 필요한 로컬 테스트를 만들기 전에 기존 사용자 정책에 맞춰 `/tests/`의 로컬 Git 제외를 확인·보완한다. 기존 테스트 전체를 복원하거나 원격에 재등록하지 않는다.
- **Source**: 이전 D09 정책 및 현재 `git check-ignore` 확인. 현재 checkout에는 `tests/`도 없고 `.git/info/exclude`의 `/tests/` 규칙도 적용되어 있지 않다. 과거 작업 보고서의 로컬 상태와 구분한다.
- **Rationale**: 새 로컬 검증 파일이 실수로 커밋되는 것을 막으며 이미 승인된 로컬 전용 테스트 방침을 이어간다.

- 앱에서 아직 import하지 않는 예시 컴포넌트의 CSS가 Next 빌드 결과에 포함된다고 가정하지 않는다. 실제 Tailwind 입력을 메모리에서 컴파일하는 로컬 검사와 CSS 구조 검토를 따로 계획한다. 새 페이지를 연결하여 검증하지 않는다.
