## D01. 적용 범위와 디자인 기준

- **Chosen**: 제작 화면의 핀 생성 영역과 중앙 편집·슬라이드 배치를 수정한다. HTML의 실제 `wsWrite` 경로를 배치·상호작용 기준으로 삼고 색상·폰트·간격·버튼 스타일은 현재 앱의 테마를 따른다.
- **Rationale**: 사용자는 HTML의 구조를 원하면서 기존 개발 코드의 전체 스타일을 유지하도록 요청했다.
- **Source**: 사용자 직접 요청.
- 헤더 본체, 슬라이드 목록과 출처의 기존 접기/펼치기, 기존 편집·저장 기능을 유지한다. 핀 버튼을 옮기기 위해 헤더 아래의 현재 의견 도구 행은 정리한다.
- 이번 변경을 이유로 공용 컴포넌트 디렉토리를 추가하지 않는다. 필요한 UI 분리는 기존 comments/production 책임 안에서 계획한다.

## D02. 슬라이드별 핀과 의견

- **Chosen**: 새 핀 의견은 생성한 슬라이드에 연결하고 해당 슬라이드에서만 표시한다.
- **Rationale**: 프로젝트 공통 위치보다 수정 대상 슬라이드가 명확해야 하며 HTML도 소목차·페이지별 의견을 표시한다.
- **Source**: 인터뷰 1번 선택 — 슬라이드별로 분리.
- 표시 순번이나 화면 위치가 아니라 안정적인 슬라이드 ID로 연결한다. 재정렬·패널 크기 변경 후에도 같은 슬라이드의 같은 상대 위치를 가리켜야 한다.
- 현재 사용 중인 `CommentsProvider` → `ProjectCanvasCommentsProvider` → canvas 의견 경로와 의견 팝업을 확장한다. 현재 작성·답글·멘션·수정·삭제·처리 상태·권한·충돌 보호를 유지한다.
- 기존 번호 발급 규칙은 유지한다. 슬라이드를 전환했다고 저장된 의견 번호를 다시 매기지 않는다.

## D03. 기존 연결 없는 의견 보존

- **Chosen**: 슬라이드 정보 없이 저장된 기존 canvas 의견은 데이터만 보존하고 제작 화면에서는 숨긴다. 새 의견부터 슬라이드에 연결한다.
- **Rationale**: 기존 좌표만으로 어느 슬라이드에 대한 의견인지 알아낼 수 없고, 사용자는 수동 연결 절차를 원하지 않았다.
- **Source**: 인터뷰 1번 선택 — 저장된 데이터 보존, 화면 숨김, 별도 버튼 없음.
- 기존 의견을 현재 선택 슬라이드나 첫 번째 슬라이드에 자동 배정하지 않는다. 저장 자료를 초기화하거나 자동 삭제·완료 처리하지 않는다.
- 슬라이드 연결 정보가 없는 이전 저장 형식을 읽을 수 있어야 한다. 새 형식에서는 연결 없음과 실제 슬라이드 연결을 구분한다. 구체적인 타입·검증 스키마 변경은 계획 단계에서 지정한다.
- 화면에 보여 줄 의견을 걸러 낸 결과로 전체 저장 상태를 덮어쓰지 않는다. 새 의견 저장, 기존 의견 수정, 회차 변경 시 숨겨진 자료가 유실되지 않도록 한다.
- `이전 의견` 버튼과 그 화면 진입점도 제거한다. 이 버튼이 읽는 예전 의견 저장소는 현재 프로젝트의 canvas 의견과 별개이므로, 버튼 제거를 저장소 삭제로 확장하지 않는다.

## D04. 핀 생성 버튼 위치와 다중 선택

- **Chosen**: 각 중앙 슬라이드 아래 왼쪽에 기존 `핀 생성` 버튼을 둔다. 여러 장을 선택한 경우에도 각 슬라이드에 대응하는 버튼을 둔다.
- **Rationale**: HTML의 `cmtBlock`은 해당 슬라이드 아래에 핀 버튼을 두며 `multiStack`도 각 슬라이드마다 같은 구조를 사용한다.
- **Source**: HTML·코드에서 확인하고 인터뷰 중 안내한 배치.
- 버튼을 누른 슬라이드 한 장만 핀 생성 대상으로 활성화한다. 생성 모드는 한 번에 하나만 활성화한다.
- 왼쪽 목록의 썸네일, 편집 입력칸, 출처, 슬라이드 밖 여백에는 핀을 만들지 않는다.
- 현재 의견 팝업을 유지한다. 버튼 위치를 맞추기 위해 HTML의 별도 의견 목록·상시 입력칸 전체를 새로 구현하는 범위로 넓히지 않는다.

## D05. 핀 영역·커서·좌표

- **Chosen**: 실제 슬라이드 면 내부에서만 핀을 생성·이동한다. 생성 모드에서는 대상 슬라이드 내부에만 십자 커서를 적용하고 외곽을 점선으로 표시한다.
- **Rationale**: 현재 전체 제작 화면에 연결된 클릭·커서·좌표 기준이 화면 밖 핀과 커서 문제의 원인이다. HTML도 `.slide.pinning`과 해당 슬라이드의 경계를 기준으로 동작한다.
- **Source**: 사용자 직접 요청 + 현재 `CommentsWorkspace`와 HTML 비교.
- 안내 문구·로딩·오류 영역까지 포함한 미리보기 전체 래퍼가 아니라 실제 렌더링된 슬라이드 면을 좌표 기준으로 사용한다. 기본·HTML 예시·Template 미리보기 모두 동일하게 적용한다.
- 좌표는 해당 슬라이드 너비·높이에 대한 비율로 저장한다. 화면 스크롤, 확대·축소, 패널 크기 변경 후에도 위치가 맞아야 한다.
- 빈 화면, 로딩 실패, 썸네일 및 권한상 생성할 수 없는 화면에는 생성 모드·점선·십자 커서를 적용하지 않는다.
- Esc 취소, 버튼으로 모드 해제, 키보드 생성·이동, 팝업 위치 보정과 포커스 복귀를 유지한다. 여러 슬라이드 표시나 숨겨진 편집 세션 때문에 핀·팝업이 중복 표시되지 않아야 한다.
- 슬라이드·프로젝트·회차 전환 시 활성 생성 대상을 정리하고 작성 중인 의견은 기존 미저장 입력 보호 흐름으로 처리한다. 다른 슬라이드에 입력을 잘못 저장하지 않는다.

## D06. 편집 입력 높이 축소

- **Chosen**: 너비는 유지하고 높이를 줄인다. 상시 제목·하단 안내 행을 없애거나 축소하고, 반영 아이콘 버튼을 HTML처럼 입력칸 안쪽 오른쪽 아래에 배치한다.
- **Rationale**: 현재 입력 본문뿐 아니라 제목 행과 안내·버튼 행이 높이를 더 차지한다. 사용자는 너비 축소가 아니라 높이 축소를 선택했다.
- **Source**: 인터뷰 1번 선택 — 높이 축소.
- 단일 편집 입력 본문은 HTML `.sl-body`의 최소 48px·최대 180px를 기준으로 하고 긴 내용은 내부 스크롤로 읽고 편집한다. 버튼과 글자가 겹치지 않도록 안쪽 여백을 확보한다.
- 별도 굵은 `편집` 제목을 제거한다. 제목·리딩 메시지·본문 등 실제 슬라이드 내용은 그대로 편집할 수 있어야 한다.
- 상시 일반 안내가 차지하던 행을 정리하되 오류·읽기 전용·미반영 변경 등 필요한 상태 안내와 스크린리더용 이름은 유지한다.
- 한글 입력 중 처리, 미저장 입력 보호, 반영 버튼과 저장 단축키, 기존 문서 구조 보존을 유지한다.
- 다중 선택의 요청 입력은 기존 여러 줄 입력·반영 기능을 유지하면서 같은 중앙 외곽 카드 제거 구조에 맞춘다.

## D07. 중앙 편집과 슬라이드의 시각적 분리

- **Chosen**: 편집·슬라이드를 함께 감싸는 중앙의 흰 배경·테두리·둥근 외곽 카드를 제거한다. 편집 입력칸만 흰 배경을 유지하고 슬라이드는 작업 배경 위에 바로 놓는다.
- **Rationale**: HTML은 `ed-h` 안의 흰 편집 입력과 `ed-wrap`의 슬라이드를 분리하며 전체를 다시 흰 카드로 감싸지 않는다.
- **Source**: 사용자 직접 요청 + `ProductionPanels`의 중앙 `panel` 클래스 확인.
- 중앙의 별도 굵은 `슬라이드` 제목도 제거한다. 슬라이드 내부의 실제 제목, 다중 선택 시 문서를 식별하는 제목·번호, 접근성 이름과는 구분한다.
- 슬라이드 자체의 배경·테두리 및 생성 모드 점선은 유지할 수 있다. 제거 대상은 슬라이드 바깥의 추가 카드다.
- 기존 `min-height: 0`과 중앙 영역의 내부 스크롤을 유지한다. 전체 페이지에 불필요한 스크롤을 만들지 않고 점선·핀·팝업도 잘리지 않도록 배치한다.

## D08. 저장 및 회차 호환 조건

- **Chosen**: 현재 저장·권한·보관본·회차 갱신 규칙을 유지하면서 새 슬라이드 연결 정보를 끝까지 전달한다.
- **Rationale**: 스타일과 이벤트 영역만 바꾸면 새로고침이나 다음 회차에서 슬라이드 연결이 사라질 수 있다.
- **Source**: 현재 provider, repository, canvas 검증·명령·이월 코드를 읽고 도출한 구현 제약.
- 생성 요청에서 슬라이드 존재와 프로젝트·회차 범위를 검증한다. 조회 결과를 숨기는 것만으로 권한 검증을 대체하지 않는다.
- 보관본 및 되돌리기 상태도 호환되어야 한다. 슬라이드가 없는 경우 의견을 다른 슬라이드에 노출하지 않는다.
- 계획에서 슬라이드 삭제·되돌리기·복사, 의견 수 집계, 회차 이월과 연결 정보의 상호작용을 점검한다. 기존 기록을 잃거나 다른 슬라이드에 의견을 복제하는 방식으로 처리하지 않는다.

- **Rationale**: 사용자 지정 인터뷰 → 계획 → 실행 workflow와 명시적으로 호출한 grill-me 스킬의 종료 규칙을 따른다.

- 현재 제작 화면이 사용하는 `canvasComments`와 별개로 `ProjectCommentThread`/`ProjectComments`/`ProjectCommentPins`라는 슬라이드 의견 구현이 존재한다. 두 경로의 데이터·권한·UI를 섣불리 합치면 기존 기능이 달라질 수 있다. 이번 변경은 현재 화면의 경로를 확장하며, 두 의견 체계의 전면 통합이나 미사용 코드 정리는 별도 범위다.
