# Decisions: Microsoft 로그인과 기본 워크스페이스 복원

- Date: 2026-10-26
- Source: 사용자가 디자인 제거 범위를 정정하고 Microsoft 로그인 화면 및 왼쪽 사이드바·중앙 content 틀 복원을 요청함
- Status: Confirmed

## D01. 기본 화면 범위 정정

기존 화면의 업무 도메인·전용 디자인은 제거하지만, 로그인 화면과 범용 앱 레이아웃은 템플릿에 포함한다. 이 결정은 `2026-10-26-azure-template-design-reset`의 D02에서 기본 HTML만 남긴다는 부분을 대체한다.

## D02. Microsoft 로그인

기존 중앙 정렬, 인디고 Languages 아이콘, Sign In 문구, Microsoft 로고 outline 버튼을 복원한다. 별도 UI 라이브러리 없이 CSS module과 SVG로 구현한다. 인증이 꺼져 있어도 `/auth/login` 미리보기는 열리며 버튼을 비활성화하고 인증 서비스를 초기화하지 않는다. 인증을 켜면 기존 callback·popup·계정 전환 보안 흐름을 사용한다.

## D03. 워크스페이스

왼쪽 고정 사이드바, 상단 계정·위치 바, 중앙 콘텐츠 패널을 제공한다. 작은 화면에서는 사이드바를 메뉴 버튼으로 열고 닫는다. 홈은 실제 업무 데이터가 없는 빈 상태를 표현하며 가짜 통계나 작동하지 않는 메뉴는 추가하지 않는다. 관리자 메뉴와 라우트의 역할 검사는 유지한다.

## D04. 인증은 애플리케이션 진입 전에 수행

우측 상단 로그인 버튼을 제거한다. 인증 활성 환경은 `URL 진입 → 로그인 → User/Admin 역할 확인 → AppShell 렌더링` 순서를 서버에서 보장한다. 역할 없는 세션은 계정 전환 화면에 남겨 리다이렉트 반복을 막는다. 로그아웃은 로그인한 사용자의 사이드바 계정 영역에서 제공한다.

인증된 앱 레이아웃은 요청마다 동적으로 렌더링하여 빌드 시 인증 설정이 접근 권한 검사 결과를 고정하지 않도록 한다.

사용자의 후속 지시에 따라 현재 Azure 연결 전 개발 모드(`AUTH_ENABLED=false`)에서는 로그인 화면을 강제하지 않고 홈 레이아웃을 바로 확인할 수 있게 유지한다. 실제 자격 증명이나 배포 환경은 이번 수정에서 변경하지 않는다.

## Verification

- 단위 테스트 164개, TypeScript, ESLint 및 인증 비활성 프로덕션 빌드 통과.
- 로컬 `/` 응답 200, 사이드바·콘텐츠 영역 존재, `/auth/login` 링크 부재 확인.
- 인증 미활성 환경에서는 로그인 화면을 수동으로 확인할 수 있으며 실제 인증 요청 버튼은 비활성 상태.
- 인증 활성 환경의 미로그인·역할 없음·User/Admin·토큰 갱신 실패 분기는 단위 테스트로 검증. 실제 Entra ID 로그인은 자격 증명 연결 후 별도 확인이 필요함.
