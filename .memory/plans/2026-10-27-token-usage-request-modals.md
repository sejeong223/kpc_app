## Scope

### 포함

- 일반 탭의 두 버튼과 업무 알림의 Token 항목에서 사용량/신청 모달 진입.
- 사용량: 4개 KPI, 일별 막대그래프, 프로젝트별·기능별 분석, 최근 사용 내역 6행.
- 신청: 현재 사용량, 신청 후 예상 한도, 승인 대기 안내, +30K/+50K/+100K/직접 입력, 프로젝트, 필수 사유, 사유 예시 버튼, 제출 검증.
- 두 화면을 단일 Fluent UI Dialog에서 전환. 공용 `ModalFrame`과 기존 `SegmentedControl`의 chips 변형 사용.
- 제출 성공 시 모달 닫기·안내 Toast·프로필의 최신 승인 대기 표시. 새 신청을 추가해도 기존 신청을 보존한다.
- 접힌 사이드바·모바일·키보드 포커스·스크롤·접근성 검증.

### 후속 범위

실제 과금/사용량 수집, API·DB 저장, 승인/거절 화면, 승인 후 한도 변경, 이메일, Azure 리소스·인증 연동, 관리자 토큰·비용 관리 화면의 구현. 서버 인증·인가와 기존 역할 미리보기 규칙은 그대로 유지한다. 이번 제출은 로컬 승인 대기 내역이며 실제 접수로 표시하지 않는다.

## UI & State Contract

- 사용량 너비 760px, 신청 너비 560px. 화면이 좁으면 `calc(100vw - 32px)`로 제한. 최대 높이는 88vh 및 `calc(100svh - 32px)` 이내. 헤더/푸터 고정, 본문만 세로 스크롤하며 스크롤바는 숨긴다. 가로 스크롤은 없어야 한다.
- 모달 배경 흰색·반경 16px, scrim `rgba(17,18,22,.28)`, 주색 `#d7192f`, 선택 텍스트 `#c91c2b`. 데스크톱은 HTML의 구성·간격·문구를 따른다.
- 사용량→신청, 신청→사용량은 모달을 중복 생성하지 않고 내용·너비·제목을 바꾼다. 전환 후 새 제목으로 포커스 이동.
- `ProfilePreviewState.tokens`에 모달 종류·입력 초안·신청 목록을 저장. 레이아웃 Provider에서 유지하고 새로고침 시 초기화한다. 사용자/관리자 전환은 표시 역할만 바꾸며 동일 사용자의 신청 내역을 지우지 않는다.
- 신청을 열 때 기본 +50K, 직접 입력·사유는 비우고 직전 프로젝트는 유지. 신청→사용량→신청도 동일하게 초기화한다.
- 직접 입력은 양의 정수 K 단위, 토큰 환산값도 안전한 정수여야 한다. 사유는 trim 후 2자 이상. 프로젝트는 허용 목록의 값만 사용. 유효하지 않으면 제출하지 않는다.
- 성공 시 최신 요청을 `pending`으로 추가한다. **승인 전 실제 한도 100K/사용량 72.4K는 변하지 않는다.** 예상 한도만 현재 한도+이번 신청량으로 계산한다. 이전 대기 신청을 예상 한도에 합산하지 않는다.
- `TokenDialogs`는 인증 레이아웃의 Provider 안에서 `AppShell`의 형제로 한 번만 마운트한다. Sidebar/ProfileMenu의 key 변경에 따라 사라지지 않게 한다.
- 프로필 팝업을 닫은 다음 프레임에 모달을 연다. 모바일 사이드바의 포커스 가드는 열린 모달에 입력을 양보한다. 모달 Escape는 모달만 닫고 프로필 트리거로 복귀한다. 경로 변경 시 모달을 닫되 새 화면 포커스를 덮어쓰지 않는다.
