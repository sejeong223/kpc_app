## Scope

1. 공통 헤더: 560px 2행 프로젝트 선택 버튼, 내부 역할 배지, 외부 회차 배지, 참여 프로젝트 팝오버와 D-day, 재작업 아이콘 → 완성본 → 완성 → 설정 순서. 기존 로딩·오류에서도 동일 외곽을 사용한다.
2. 헤더를 사용하는 `analysis/files/toc/setup/write/review` 경로에서 중복 작업 이동 링크 제거. 파일 개수·한도·진행 막대는 파일 업로드 본문 첫 줄로 이동한다.
3. 제작 외곽: 좌 240px / 가운데 가변 / 우 360px, 6px 조절선, 밀착된 흰 패널, 접힘 레일, 각 영역 스크롤. 저장된 정상 패널 폭은 유지한다.
4. 제작 목록·출처: 실제 슬라이드 수·담당·고정·선택·미처리 의견, HTML의 출처 카드 문구와 인용문 표시. 현재 연결 가능한 자료 원문 열기를 유지한다.
5. 제작 중앙: 대목차 breadcrumb + 소목차 선택 팝오버, 상태 선택 바로 왼쪽 코멘트 추가, 고정된 입력 도구 영역과 스크롤되는 슬라이드 영역, 다중 선택 입력·선택에서 빼기·단축키.

## Boundaries

- 프로젝트/슬라이드/댓글 ID·본문·자료 버전·회차·권한·보관본·draft를 유지한다. 저장 서비스·Cosmos DB·프로비저닝·패키지 변경은 없다.
- `제작 설정` 본문, `목차` 본문, `검토/리뷰` 본문과 GNB는 이번 이식 대상이 아니다. 해당 화면에서는 공통 헤더에 필요한 연결부만 수정한다.
- 기본·HTML 예시·Template 미리보기의 콘텐츠 렌더러는 유지한다. 공통 preview wrapper와 코멘트 도구 연결만 조정한다. HTML 본문을 `dangerouslySetInnerHTML`/iframe으로 통째로 삽입하지 않는다.
- 권한 확인·미저장 입력 보호·제안 비교/확인·실제 저장/다운로드를 HTML의 시연 toast나 전역 상태로 바꾸지 않는다.
- 알림/활동 로그 신규 연동 및 RFP 원문 연결 모델은 사용자가 범위 확인 질문에서 제외했다. 이번 Task에 추가하지 않는다.

## Execution & Validation

T01 → T02 → T03 순서로 실행한다. 각 Task는 정확한 파일·타입·처리 흐름·검증 명령·한국어 커밋 메시지를 포함한다. 이전 HTML 계획의 T04–T08 미커밋 문서는 이 계획의 변경에 섞지 않는다. 이전 계획의 커밋 생략은 Downloads HTML 완성 요청에 한정된 기록이며 이 계획의 Task에는 지정 커밋 계약을 작성한다. 계획 작성 중에는 커밋하지 않는다.

`tests/` 생성·복원, 브라우저/CUA/E2E/dev server/스크린샷 검증을 하지 않는다. 실행 시 타입 검사·변경 파일 lint·최종 전체 lint/build·정적 이벤트/권한/소스 대조로 검증한다. 실제 시각 일치와 마우스 조작은 미검증으로 기록한다.

## Why three tasks

- T01은 공통 헤더와 각 호출부를 함께 바꿔야 중복 메뉴·업로드 안내가 남지 않는 완결된 결과가 된다.
- T02는 목록·출처·폭 저장·반응형까지 묶어 외곽이 동작하는 상태로 끝낸다. 중앙 편집 상태는 이 단계에서 유지한다.
- T03은 입력 상태와 코멘트 버튼의 소유 관계를 함께 정리한다. 버튼만 먼저 옮기면 슬라이드별 좌표·포커스·다중 선택 대상이 어긋나므로 분리하지 않는다.
