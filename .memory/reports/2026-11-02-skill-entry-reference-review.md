# Skill 입력 화면 전환 및 기획 HTML 대조

- 요청: Skill 추가를 팝업 대신 입력 화면으로 전환하고, 첨부 기획의 요소 누락 여부 확인.
- 기준 코드: `cd2f6d3`. 참조: `KPC_제안서_UI_v12 8 (1).html`.
- 비교 기준은 실제 `assetFormHtml()`의 Skill 분기(4276~4293행)와 `skPreview()`(4184~4192행)이다. 문서의 설명 문구는 실행 지시로 취급하지 않았다.
- 기획의 `SK_OPT`, `SK_PT_RULES`, `PAGE_TYPES` 리터럴을 실행 없이 구문 분석해 `tests/fixtures/skills/reference-ui.json`에 원본 SHA-256과 함께 보관했다.

## 구현 결과

`SkillEditorDialog`를 `SkillEditorPage`로 전환했다. 등록·수정·조회 전용 모두 목록 본문을 교체하며, 입력 폼 자체에는 모달을 사용하지 않는다. 취소·목록 복귀·사이드바 이동 시 미저장 변경을 확인하는 작은 모달만 사용한다. 새로고침·탭 닫기는 브라우저 기본 경고를 사용한다.

9개 입력 영역을 펼쳐 표시하고, 넓은 화면은 우측 미리보기, 좁은 화면은 세로 배치로 구성했다. 페이지 유형별 규칙은 6행 표이며 작은 화면에서는 표 영역만 가로 스크롤된다. 등록·저장 버튼은 상단에 유지한다. 목록 복귀 시 검색·필터·페이지 상태와 포커스를 복구한다.

현재 관리자 mock 서비스, Zod 검증, React Query, 소유 부서·공개 대상·CRUD 권한, 내용 버전과 최신 재적용 정책을 유지한다. DB·PPT 변환 엔진의 동작은 변경하지 않았다.

## 등록·수정 입력 항목 대조

| 기획 영역 | 확인한 필드 | 결과 |
| --- | --- | --- |
| 1. 기본 정보 | 이름, 약칭, 설명 | 3개 존재. 이름·약칭 필수, 오류 위치로 포커스 이동. 기존 소유 부서·상태도 유지 |
| 2. 글꼴·크기·굵기·줄 간격 | 글꼴, 공통 줄 간격, 제목·리딩 메시지·본문 크기와 굵기 | 8개 일치 |
| 3. 요소·문단 간격 | 제목–본문, 본문–표, 문단 | 3개 일치. `gap.bt`의 기존 ‘블록 간격’ 표시를 ‘본문–표’로 수정 |
| 4. 표 | 상하/좌우 셀 여백, 행 높이, 문자/숫자 정렬, 머리글 | 6개 일치 |
| 5. 도형·이미지 | 스냅, 이미지 맞춤, 세로 정렬, 최소 폭 | 4개 일치. 최소 폭 단위를 cm에서 **열**로 수정. 엔진도 이미 열 단위이므로 데이터 변경 불필요 |
| 6. 여백·안내선·눈금선 | 상·좌·하·우 여백, 열, 단, 눈금 | 7개 일치 |
| 7. 넘침·겹침 방지 | 글자 축소, 자동 분할, 겹침 방지, 영역 유지, 표 최대 행 | 5개 존재. 자동 분할은 저장만 가능하며 실제 적용 미지원 안내 유지 |
| 8. 페이지 유형 | 표지·목차·간지·본문·표/대응표·부록의 제목/본문/줄 간격/정렬/규칙 | 30개 일치. 상속 선택지에 현재 공통값 표시. ‘표 중심’ 명칭을 ‘표 · 대응표’로 통일 |
| 9. 공개 범위 | 전사, 부서, 그룹, 사용자 대상 지정과 제거 | 체크박스·선택 칩으로 제공. 조회/적용 대상과 원본 편집 권한을 구분 |

서식 입력은 **63개(선택 59개 + 체크박스 4개)**이며 기본 정보 3개와 공개 범위가 추가된다. 21개 선택값 묶음 및 6개 유형의 규칙 문자열은 참조 HTML과 일치한다. 제목 확장값 44/48pt, 본문 9pt, 공통 상속도 포함한다.

## 미리보기

누락되어 있던 슬라이드 여백 테두리, 세로/가로 안내선, 눈금선을 추가했다. 제목·리딩 메시지·본문·표·도형 예시와 글꼴/굵기/크기/줄 간격/간격/정렬/셀 여백/머리글이 즉시 갱신된다. 공통 규칙 또는 6개 페이지 유형을 선택해 공통값 상속도 확인할 수 있다.

미리보기는 33.87×19.05cm 비율의 **설정 비교용 예시**다. 실제 PPT 렌더링·이미지 처리·넘침 해결 결과가 아니며, 설치되지 않은 글꼴은 대체 글꼴로 표시된다.

## 기획과 남아 있는 차이

‘Skill 메뉴 전체가 기획과 100% 동일하다’고 판단할 수는 없다. 등록 폼의 입력 항목을 모두 제공하는 것과 아래 업무 기능을 구현하는 것은 별개다.

| 항목 | 현재 상태 |
| --- | --- |
| 공개 범위 설정 팝업·도달 인원수 | 인라인 체크박스/칩으로 대체. 중복 대상을 합친 실제 인원수는 제공하지 않음 |
| 상세 ‘내용 / 사용 중인 프로젝트 / 변경이력’ 탭 | 전용 상세 탭 없음. 편집 가능 자산은 입력 화면으로 바로 열리고, 공유 자산은 조회 전용 입력 화면으로 열림. 변경 내역은 기존 활동 로그에서 확인 가능하나 자산별 이력 탭과 동일하지 않음 |
| 상세의 6개 샘플 페이지 동시 나열 | 페이지 유형 선택형 미리보기로 제공. 유형별 실제 프로젝트 문서 샘플은 아님 |
| 목록의 서식 요약·사용 횟수 | 현재 목록은 이름/약칭·소유 부서·공개 범위·상태·버전·수정일·작업 중심. 사용 프로젝트와 집계 연결은 후속 |
| 기획의 조합 테스트/제작 연계 | 기존 Template의 실제 PPT 적용 테스트 경로를 유지. 프롬프트/Skill/Template 조합 생성 및 제작 프로젝트 연결은 별도 범위 |
| 자동 슬라이드·표 분할 | 설정은 보존하지만 변환 시 원본 구조를 유지하고 미지원 사유 안내. 자동 분할을 구현한 것으로 표시하지 않음 |
| 자동 재배치·유형 규칙 | 위치 옵션을 켠 경우 지원 가능한 간격/스냅/새 겹침 처리만 수행. 목차 번호 생성·로고 위치 자동 판별·출처 검사·본문 재작성·일반 그룹 자동 정렬 등은 미지원 |
| 브라우저 뒤로/앞으로 | 현재 화면 상태 방식으로 별도 URL/히스토리 항목을 만들지 않음. 앱 내 취소·사이드바 이동과 새로고침 경고 범위이며 브라우저 SPA 히스토리 이동을 가로채지는 않음 |

참조 HTML의 도움말에는 이전 ‘7단계 Skill’·서랍 방식 설명이 남아 있지만, 실제 등록 렌더링은 PPT 서식 9개 영역과 전체 입력 화면이다. 이번 변경은 실제 렌더링 기준으로 대조했다.

첫 검사에서 기존 단위 테스트의 ‘공통 규칙’ 고정 문구 기대값을 현재 공통값 표시로 갱신했다. 브라우저 새로고침 취소 검사는 취소된 navigation의 완료를 기다려 시간 초과가 발생했으므로 실제 `location.reload()` 경고를 취소한 뒤 입력 유지 여부를 검사하도록 수정했다. 320px 메뉴 이동에서 확인창이 한 번 사라진 사례가 있어, 메뉴 클릭이 새 확인창의 바깥 클릭과 겹치지 않도록 다음 프레임에 열고 예약된 처리는 정리하도록 보완했다. 입력 손실은 없었다.

1440px·320px 전체 화면 캡처를 직접 확인했다. 캡처와 상세 결과는 Git 제외 대상인 `test-results/`, `playwright-report/`에 생성된다. 기존 디자인 인계 HTML에도 `SkillEditorPage` 이름·입력 계약·전체 입력 화면·미리보기 변경을 동기화했다.

`baseline-browser-mapping` 갱신 안내, Vite의 향후 config loader 안내는 기존 의존성 경고이며 이번 기능 검사 실패는 아니다.

- `tests/components/admin/skill-reference.test.ts`: 참조 선택값·규칙·63개 필드·상속·조회 전용 검사.
- `tests/e2e/admin-skill-editor.spec.ts`: 9개 영역, 필수값, 전체 서식 저장/재조회/수정, 미저장 보호, 검색/포커스 복구, 권한, 화면 폭 320~1440px 검사.
- `tests/e2e/admin-review.spec.ts`: 기존 Skill 미저장 팝업 검사를 입력 화면 흐름으로 변경하고 모델 단가 회귀 검사 유지.
