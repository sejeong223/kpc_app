## T09 통합 시나리오

`tests/integration/admin-mock-workflow.test.ts`의 9개 시나리오:

1. 개인 사용량 72,400/한도 100,000 → 50,000 신청 → 신청만으로 한도 불변 → 동일 ID 부서 관리자 승인 → 한도 150,000 → 일반 사용자 프로필 DTO에 승인 상태 반영. 중복 승인은 충돌, 새 신청 반려는 한도 불변. 승인 로그는 한 건이다.
2. 사용자 등록·수정은 활동 수에 반영되고 필터 CSV 내보내기는 다운로드 수에 반영된다. 기존 사용자 삭제·복구 후에도 과거 토큰·비용 합계를 유지한다.
3. 단가 2/8 USD와 환율 1,400에서 1,000 입력/500 출력의 비용은 8,400,000 KRW micro다. 단가 4/16·환율 1,500을 사용한 새 계산은 18,000,000이며 과거 원장 비용은 불변이다. 모두 예시값이다.
4. 전사 데이터를 QueryClient에 채워도 부서 조회 키에 노출되지 않는다. 자기 부서 사용자·비용만 반환되며 CRUD 회수 후 새 revision의 조회는 거절된다. 부서 null도 전사 조회로 해석하지 않는다.
5. 서비스 인스턴스 간 신청·한도·삭제 상태를 공유하지 않고 새 인스턴스는 초기값으로 시작한다.
6. 직접 등록한 사용자가 그룹 구성원 후보에 나타나며 삭제 후에는 후보·활성 구성원 표시에서 빠진다.
7. 부서 없는 관리자 생성·역할 변경을 서비스가 거절하고 실패 시 기존 역할을 보존한다.
8. 자기 계정의 부서 편집 후 미리보기 역할 전환은 저장소의 현재 부서를 사용한다. 이전 부서를 명시한 조회는 계속 거절한다.

9. 이전 쿼리 취소를 기다리는 동안 더 새로운 revision이 생겨도 삭제하지 않는다. 다시 관찰 중인 이전 키도 보존하고 비활성 과거 키만 정리한다.

Query 훅은 동일 사용자·역할·부서·필터·permissionRevision의 조회에서만 갱신 중 이전 결과를 잠시 사용한다. 권한 범위가 바뀌면 placeholder를 사용하지 않는다. 실제 React 화면의 갱신 타이밍·포커스는 아래 수동 검증 대상이다.

## 통합 과정에서 보완한 부분

- 디렉터리 후보를 초기 배열에만 의존하지 않도록 수정했다. 현재 등록된 사용자와 미등록 예시 후보를 합치고 삭제된 계정은 제외한다.
- 그룹 편집의 초기값·충돌 재조회는 삭제되지 않은 실제 구성원 ID로 만든다. 삭제된 ID 때문에 무관한 이름 편집이 실패하는 상황을 방지한다.
- 관리자 생성/편집/역할 변경에서 소속 부서를 검사한다. UI 입력 검증 외에도 서비스가 같은 규칙을 강제한다.
- 권한 revision이 달라지면 React Query placeholder를 사용하지 않도록 보강했다.
- 캐시 정리는 시작 시점의 쿼리 객체만 대상으로 하고, 현재 관찰 중인 쿼리는 제거하지 않는다. 빠른 역할·revision 전환의 지연 정리 경합을 테스트했다.
- 런타임은 현재 mock 계정의 이름·부서를 반영한다. UI 미리보기 역할과 실제 인증 가드를 혼합하지 않는다.
