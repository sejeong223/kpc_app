이 선 아래는 관리자 이상

전사 범위로 관리

사용자·그룹·역할별 권한, 모델·가격·토큰 정책을 관리합니다.

메뉴 노출은 역할로, 본문과 버튼은 리소스별 CRUD로 제어합니다. 금지된 버튼은 조건부 렌더링으로 생성하지 않습니다.

개인 사용량 조회와 토큰 신청은 프로필에서 제공합니다. 부서 관리자는 자기 부서 신청만 승인·반려할 수 있습니다.

config/sidebar.ts
config/admin-permissions.ts
lib/admin/permissions.ts

실제 인증의 User/Admin 역할은 유지했습니다. 3단계 업무 역할의 Entra 연동은 후속 작업입니다. 위 선택기는 이 문서의 설명만 바꿉니다.

07 / DESIGN HANDOFF

최종 디자인을 받으면 바꿀 순서

01. 색상과 기본 크기

app/admin-theme.css에서 브랜드·중립·상태 색상을 맞추고 FluentUiProvider.tsx의 토큰 매핑을 확인합니다. 모달·프로필 등 기존 UI의 직접 지정 값은 함께 점검해야 합니다.

:root {
  --kpc-brand: #d7192f;
  --kpc-radius-card: 12px;
}
02. 공통 컴포넌트와 밀도

AdminPrimitives / AdminTable / AdminTabs / AdminCharts의 여백·높이·글자 크기·상태 표시를 맞춥니다. 업무 로직에 종속되지 않은 props와 의미 있는 HTML, label, aria 속성은 유지합니다.

현재 일부 숫자형 크기와 간격은 컴포넌트에 지정되어 있습니다. 모든 디자인 변경이 CSS 변수 한 파일만으로 끝나는 구조는 아닙니다.

03. 화면별 구성과 반응형

정보의 순서와 그리드가 바뀌면 각 Page·Panel에서 배치를 조정합니다. 320~1440px 폭, 낮은 높이에서 모달 본문 스크롤, 표 내부 가로 스크롤을 확인합니다.

현재 실제 브라우저 검증은 도구 중단으로 미완료입니다. 외주 디자인 적용 전후 모두 키보드·포커스·SSR 초기 스타일 확인이 필요합니다.

04. 저장·권한·집계 회귀

스타일 변경 후에도 신청 50K → 승인 → 개인 한도 100K에서 150K로 반영되는 흐름을 보존합니다. 비용은 사용 당시 단가·환율 스냅샷을 유지하며, 권한 변경 시 이전 범위 캐시를 재사용하지 않습니다.
