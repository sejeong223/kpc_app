# 관리자 재검증 개선 — 후속 목록

- Date: 2026-10-30
- Status: Backlog, 이번 Active Plan 실행 범위 밖
- 근거: 사용자는 주요 결함 4개+추가 개선 2개+재검증을 선택하고 보안 의존성 갱신을 후속으로 분리했다.

## B01. 보안 의존성 영향 분석과 갱신
- 현재 검증 기록: 전체 audit 24건(critical3/high13/moderate7/low1), 운영 의존성 11건(critical3/high6/moderate2). 패키지별 advisory가 앱에서 모두 재현된다는 뜻은 아니다.
- 대상 예: Next, NextAuth, 간접 fast-xml-parser 및 audit의 다른 운영 의존성. 실제 사용 경로와 설정을 먼저 확인한다.
- 후속 순서: 실행 시점 audit 재확인→공식 advisory의 영향 조건·수정 버전 확인→호환 가능한 최소 갱신 조합→분리된 변경→인증/서버 액션/빌드/실제 화면 회귀→잔여 위험 기록.
- `npm audit fix --force` 일괄 실행을 기본 방침으로 삼지 않는다. 현재 사용자 lock 변경과 신규 테스트 도구 변경은 분리한다.
- 이번 계획에서는 조사 결과의 보존과 개발 테스트 도구 추가 영향 확인만 수행한다. 이 목록 자체는 업그레이드 실행 지시가 아니다.

## B02. 실제 인증·서버 인가와 저장소 연결
- 현재 mock의 3역할과 실제 User/Admin 서버 가드는 다른 검증 대상이다. 실제 Entra 역할·부서·파일 접근을 서버에서 검증하는 후속 설계가 필요하다.
- Cosmos/Blob 연결은 별도 인터뷰·계획을 거친다. 이번 UI 수정에서 컨테이너/파티션/프로비저닝을 설계하거나 실행하지 않는다.

## B03. 대용량 실파일 성능·메모리
- 실제 204~250 MiB 입력, 200장 고유 슬라이드, 고해상도 미디어, 연속 업로드/폐기 상태에서 처리 시간·메모리·취소 응답성을 측정할 후속 작업.
- 기존 size 메타데이터/반복 참조 fixture 검사를 실제 부하 검증으로 대체 표기하지 않는다. 처리 한도 상향이나 Worker 도입은 측정 후 별도 판단한다.

## B04. 환경별 호환성과 이전 미완료 검증
- Firefox/Safari/모바일 실기기·스크린리더와 다양한 고객 PPT 호환성은 후속이다.
- 기존 관리자 계획 T09 전체 완료를 이번 개선 계획 완료와 혼동하지 않는다. 남은 수동 경합·설정 보존 조합은 기존 Task 기준으로 별도 확인한다.
- 제작 설정/제작 연결, 전역 브랜드 색상 변경·새 로고 삽입은 이전 결정대로 후속이다.
