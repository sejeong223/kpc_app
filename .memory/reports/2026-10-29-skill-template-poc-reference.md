## 인터뷰에서 확인된 사용자 선택

1. **실제 PPTX 추출**: 예시 추출 결과만 표시하는 방식 대신 실제 파일에서 정보를 읽는다. 앞선 Skill PoC 대화와 소스를 참고한다.
2. **관리 범위**: 슈퍼 관리자는 전사 자산을 관리하고, 부서 관리자는 자기 부서 자산을 등록·수정·삭제한다.
3. **전사 공개 권한**: 부서 관리자도 자기 부서의 자산을 직접 전사에 공개할 수 있다. 공개 후에도 원래 소속 부서 관리자가 수정 권한을 유지하며, 다른 부서는 조회·적용만 한다. 이는 직전 선택지에서 전사 공통 자산 전체를 부서 관리자에게 읽기 전용으로 설명했던 부분의 예외를 구체화한다.
4. **수정 버전 반영 — 후속 설명으로 정정**: 작업은 적용 당시 버전과 결과를 유지한다. 원본 설정이 수정돼도 자동으로 최신 설정으로 전환하거나 기존 결과 다운로드를 차단하지 않는다. 새 버전이 있음을 표시하고, 사용자가 ‘최신 버전 재적용’을 선택했을 때 변경사항을 반영한다. 앞서 선택한 자동 최신 전환·강제 재적용 정책은 이번 설명으로 대체한다.
5. **비활성화·삭제 시 적용본 보존 — 사용자 선택 확정**: 원본 자산의 상태와 작업에 보관한 적용본을 분리한다. 비활성화·삭제된 템플릿은 새 작업에서 선택할 수 없지만, 기존 작업은 적용 당시 템플릿과 결과를 유지하며 고정된 버전으로 재적용·PPT 생성을 계속할 수 있다. 작업에 보관한 템플릿 설정 자체는 수정할 수 없다. 수정·비활성화·삭제만으로 기존 적용본을 없애거나 기존 작업의 결과 다운로드를 차단하지 않는다. 공개 범위 축소 등에 따른 권한 회수는 다음 6번 정책을 우선 적용한다.
6. **권한 회수 — 사용자 선택 확정**: 전사 공개를 특정 부서 공개로 줄이는 등 공개 범위 변경으로 사용 권한이 사라지면 기존 작업에도 즉시 반영한다. 해당 자산을 이용하는 재적용·PPT 생성·다운로드를 차단한다. 비활성화·삭제에 따른 기존 버전 사용 허용은 권한 회수를 우회하는 근거가 아니다. 보관된 적용본의 불변성과 현재 사용자에게 허용되는 동작을 분리한다.
7. **서식 우선순위 — 사용자 선택 확정**: Template과 Skill의 설정이 겹치면 글꼴·글자 크기·줄 간격·표 서식은 Skill의 편집 규칙을 우선 적용한다. Template의 색상·로고·기본 배치는 유지한다. 위치 규칙에 따른 배치 변경은 사용자가 별도 옵션을 켰을 때만 적용한다. 이는 기존 PoC의 기본 동작 방향을 현재 앱의 정책으로 채택한 것이다.
8. **부분 적용 — 사용자 선택 확정**: 정상 파일에서 일부 요소에 Skill을 적용할 수 없으면 가능한 요소는 적용하고, 적용할 수 없는 요소는 원본으로 보존한다. 요소별 ‘변경·원본 유지·적용 제외’ 상태와 사유, 전후 비교를 제공한 뒤 결과 다운로드를 허용한다. 파일 자체의 손상이나 권한 오류는 부분 적용 대상으로 처리하지 않고 전체 작업을 차단한다.
9. **복제 권한 — 사용자 선택 확정**: 조회 권한과 해당 자산의 등록 권한이 있는 관리자는 다른 부서의 공개 Skill·Template도 복제할 수 있다. 복제본은 자기 부서의 새 자산으로 관리하며, 원본과 독립적인 ID·소유 부서·수정 버전을 갖는다. 원본의 수정이 사본에 자동으로 동기화되는 연결 복제 방식은 아니다.
10. **공유 디자인 편집의 저장 범위 — 사용자 선택 확정**: 마스터·레이아웃의 로고·공통 글꼴 등 공유 디자인 편집은 현재 PPT 작업과 해당 출력 파일에만 반영한다. 등록된 Template에 자동 저장하지 않는다. 자산 자체를 변경하려면 별도로 Template 수정 화면에서 새 버전을 저장한다. 이는 작업에 보관한 템플릿 원본의 불변성을 유지하면서 출력에 대한 편집 설정을 분리하는 방식이다.
11. **실제 적용 화면의 범위 — 사용자 선택 확정**: 이번에는 관리자 메뉴 안에 ‘적용 테스트’를 제공한다. Template에서 Skill을 선택해 실제 PPT에 적용하고 전후 비교·결과 다운로드를 수행한다. 일반 사용자의 제작 설정·제작 메뉴 연결은 후속으로 남긴다.

공개 범위와 소유 부서는 분리해야 한다. 전사 공개로 바꾸더라도 소유 부서를 제거하거나 모든 부서에 편집 권한을 주지 않는다. 최종 범위와 코드 확인으로 정한 기본값은 별도 Confirmed 결정 파일을 기준으로 삼는다.

### 인용 답변 이후 달라진 중요한 부분

- v3.4는 공유 그룹 전체를 일괄 차단하지 않는다. 가능한 내부 요소의 속성만 변경하고 제한은 요소·속성별로 표시한다.
- 일반 슬라이드 그룹의 자동 Skill 적용과 공유 마스터/레이아웃 그룹의 명시적 편집은 서로 다른 지원 범위다.
- 공유 원본을 바꾸면 동일 마스터/레이아웃에 연결된 전체 슬라이드에 반영된다. 슬라이드 선택 체크로 공유 변경 범위를 좁히지 않는다.
- 차트·SmartArt·OLE·이미지 속 글자·복잡한 공유 표, 일부 페이지만 위한 마스터 복제/재연결 등은 제한이 남는다.
- 기존 PPT 변환 경로는 자동 슬라이드/표 분할을 보류한다. 새 PPT 생성 PoC의 자동 분할 기능과 혼동하지 않는다.
- 미리보기는 구조 기반 표시이며 PowerPoint와 동일한 렌더링을 보장하지 않는다. 기존 문구·관계·수정하지 않는 구성 파일 보존과 실제 출력 확인을 구분한다.
- 기존 PoC는 현재 작업의 설정이나 적용 대상이 바뀌면 이전 결과 다운로드를 무효화하고, 재적용은 항상 원본 사본에서 시작한다. 이는 등록 자산에 새 버전이 생기는 것과 다르다. 이번 설계는 등록 자산 변경만으로 기존 작업 결과를 무효화하지 않는다.

## 현재 앱과 연결할 때의 차이

- 현재 앱에는 Fluent UI 공통 컨트롤, Tailwind 레이아웃, Zod, React Query, Provider별 mock 저장소·권한·감사 로그가 이미 있다.
- 기존 PoC의 localStorage 목록/그룹을 그대로 옮기면 현재 사용자·부서·그룹·권한과 이중 저장소가 생긴다. 변환 엔진과 관리 데이터 계층을 나눠 재사용해야 한다.
- 독립 HTML 빌드를 위한 esbuild 설정은 Next 앱에 그대로 가져올 필요가 없다. PptxGenJS의 새 PPT 생성 경로와 기존 PPT XML 변환 경로도 구분한다.
- 현재 Skill/Template 라우트는 안내 화면이고, 두 리소스의 CRUD 권한은 아직 정의돼 있지 않다. 관리자 메뉴 노출만 이미 적용되어 있다.
- 현재 기획 HTML의 실제 Skill 입력 화면은 9개 영역이고, 도움말에는 이전 7단계 설명이 남아 있다. 구현 근거와 설명 문구를 구분해야 한다.
- 이전 대화의 다른 RAG·LLM·PPT 병렬 생성 실험은 이번 요청에 자동 포함하지 않는다.
