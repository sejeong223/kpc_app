일반 입력 영역

표는 셀에서 여백을 소유하고, 폼은 카드 본문에서 여백을 소유합니다. 내용이 적어 아래에 남는 자연스러운 빈 공간은 채우지 않습니다.

여백의 소유자

AppShell · 바깥 패딩→WorkspacePage · 영역 gap→WorkspaceCard · 내부 구성→Toolbar / Table · 조작·셀

표 카드 조합

<AdminCard title="목록" bodyPadding="flush">
  <WorkspaceCardSection afterHeader>
    <WorkspaceToolbar>필터</WorkspaceToolbar>
  </WorkspaceCardSection>
  <AdminTable ... />
  <WorkspaceCardSection>
    <AdminPager ... />
  </WorkspaceCardSection>
</AdminCard>

필터와 페이지 이동에만 카드 안쪽 패딩을 적용합니다. afterHeader는 헤더 뒤 첫 영역의 상단 패딩 중복을 제거합니다.

중복해서 넣지 않는 간격

AppShell padding: 12px
  └ 페이지 padding: 12px  ← 중복
     └ 카드 padding: 16px
        └ 표 셀 padding: 12px ← 겹침

페이지 외곽을 자식에서 다시 더하지 않습니다. 표와 함께 쓰는 카드에는 flush 본문을 사용합니다. 일반 카드의 기본값은 inset입니다.

컴포넌트와 보존할 동작

페이지 · 메뉴 · 입력

  • WorkspaceHeader — h1 하나, leading/actions 슬롯, 짧은 데이터 안내와 펼침 설명.
  • WorkspaceNavigation — 기존 메뉴 state를 전달하는 UI context. 인증/Query Provider를 새로 만들지 않습니다.
  • 모바일 — 760px 이하 메뉴 버튼을 제목 줄에 포함하고 액션 줄바꿈을 허용합니다.
  • Skill — 외부 form 제출, 미저장 확인, 63개 필드를 유지합니다. sticky 헤더의 실제 높이를 ResizeObserver로 측정합니다.

캔버스 · 팝업

  • 제작 표면 — padding 0. 도구 래퍼만 12px이며 핀 좌표의 기준은 그대로입니다.
  • ModalFrame — 안전 간격16px, 내부 좌우18px. 본문 스크롤/버튼 푸터/포커스 복귀를 유지합니다.
  • 프로필·코멘트 팝업 — 기존 크기/anchor/resize 정책을 유지하고 간격만 별도 변수로 연결합니다.
  • 예외 — 아이콘 크기, PPT의 cm/pt, SVG 도형/차트 비율은 UI 간격 변수가 아닙니다.

설정 원본과 변경 방법

app/layout-tokens.css → app/globals.css에서 한 번 import합니다. dadamUi.cardPadding / sectionGap도 같은 변수를 참조합니다. 포털까지 상속되도록 변수는 :root에 둡니다.

/* 앱에서 수정하는 위치: app/layout-tokens.css */
--layout-page-inset: 12px;
--layout-section-gap: 12px;
--layout-card-inset: 12px;

/* Tailwind */
className="tw:gap-(--layout-section-gap)"

/* Fluent / Griffel */
padding: "var(--layout-card-inset)"

새 layout 경로는 admin-utilities.css의 @source에 포함되어 있습니다. 아래 표와 예시 CSS는 문서 생성 시점의 스냅샷이며 앱의 추가 설정 원본이 아닙니다. 실제 값을 수정한 뒤 이 가이드도 갱신하세요.
