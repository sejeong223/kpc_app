# 제작 상단바·핀 코멘트 통합 복구

> **현재 상태: 통합 철회, 동료의 기존 제작 화면으로 복원.** 후속 사용자 요청 “그냥 제작화면은 동료의 화면으로 되돌려줘”에 따라 아래 통합 구현은 철회했다. `/workspace/write`는 `CommentsWorkspace`를 렌더링하며 코멘트 자동 로딩·공통 상단바·제작 전용 전체 화면 배치를 원격 `152af29` 기준으로 복원했다. 새 제작 편집기의 소스와 프로젝트 저장 데이터는 삭제하지 않았다. RFP 등록 화면의 제목·하단 버튼·안내문 정렬 수정도 유지했다. 아래는 철회된 통합 작업의 이력이다.

최종 복원 검증: 주요 화면·상단바·코멘트·레이아웃 9개 파일이 `152af29`와 일치한다. `npm run typecheck`, `npm run lint`, `npm run build`, `git diff --check`가 통과했으며 철회한 통합 모듈의 잔여 참조는 없다. 브라우저 실기 검증은 수행하지 않았다.

## 원인과 선택

- 로컬 `76ad41f`는 제작 경로를 `WorkspaceScreen`으로 변경하고 기존 전역 코멘트 자동 로딩을 중단했다.
- 원격 `152af29`는 `CommentsWorkspace`의 핀 코멘트와 공통 `ProjectHeader`를 제작 화면으로 사용했다.
- 병합 `b295abc`에서 새 제작 화면을 유지하면서 원격 상단바와 핀 코멘트 화면의 제작 메뉴 연결이 빠졌다. 원본 코드 보존만으로 사용자 기능이 보존되었다고 설명한 것은 부정확했다.
- 사용자는 별도 탭 복원 대신 **새 제작 화면에 기존 상단바·핀 코멘트를 통합**하는 2번을 선택했다.

## 구현

- `ProductionWorkspace`에서 공통 `ProjectHeader`를 재사용한다. `ProductionHeaderScope`와 `workspaceHeaderData`를 통해 현재 프로젝트 선택·권한·회차·참여자 데이터를 연결한다. 보관본에서는 조회 중인 회차를 표시한다.
- 완성·재작업·이력·PPT 액션은 기존 실제 작업 경로를 사용한다. 설정 패널의 권한 탭에서는 기존 프로젝트 권한 관리 화면을 열 수 있다.
- `CommentsWorkspace`의 슬라이드용 변형으로 핀 생성, 드래그, Alt+방향키 이동, hover 미리보기, 답글·멘션·수정·삭제, 반영 완료·다시 열기, 팝업 크기 조절 UI를 재사용한다.
- `ProjectCommentRepository`가 기존 핀 컨트롤러의 명령을 프로젝트 저장소 명령으로 변환한다. 프로젝트·슬라이드·회차·보관본별로 컨트롤러를 분리하며 React Query의 기존 mutation, 권한·revision 검사, 캐시 갱신 경로를 거친다.
- 저장소가 발급한 실제 ID로 생성 직후 대화를 유지한다. 첫 의견 삭제 시 답글을 보존하는 현재 프로젝트 규칙에 맞게 삭제 안내도 조정한다.
- 작성·수정·이동·상태 변경 권한에 맞춰 액션을 렌더링한다. 보관본과 완성본의 기존 의견은 읽기 전용이며 완성 후 리뷰는 별도로 저장한다.
- 입력 중 이동에는 기존 초안 보호를 적용한다. 헤더 설정이나 모바일 메뉴가 열리면 핀 팝업을 접고 초안을 유지한다.
- 코멘트 저장만으로 슬라이드 미리보기를 무효화하지 않도록 변경했다. Template이 없을 때도 의견을 작성할 슬라이드 영역을 유지하고 경고 목록은 핀 좌표 영역 밖에 둔다.
- `components/common` 및 `components/comments`의 Tailwind 소스 검색을 추가했다. 기존 RFP 등록 화면 조정은 유지했다.

## 데이터 보존과 제한

- 이전 전역 코멘트는 프로젝트·슬라이드 식별자가 없어 자동 이관하지 않았다. 저장소를 수정하거나 삭제하지 않고 기존 **이전 의견 보관함**에서 조회한다.
- 위치 없는 프로젝트 의견은 기존 출처·의견 목록에서 유지한다. 임의 좌표를 붙여 핀으로 변환하지 않는다.
- 작업 카탈로그에는 발주처·예산·마감일이 없어 다른 프로젝트의 예시 값을 가져오지 않는다. 해당 값은 미등록/빈 값으로 표시한다.
- 설정 패널의 기본정보·알림·로그 구성은 유지하지만 해당 데이터의 저장·조회 연동은 원래부터 없었다. 실제 제작 화면에서는 조회용으로 표시하며 미지원 안내를 제공한다. 권한 변경만 기존 실제 권한 관리 경로에 연결한다. 분석·리뷰의 기존 목업은 변경하지 않았다.
- 기존 프로젝트 저장소는 브라우저 로컬 데이터다. 이번 작업에 서버·Cosmos DB 연동이나 사용자 간 실시간 동기화를 추가하지 않았다.

## 검증

- 인라인 Node/tsx + 메모리 IndexedDB 검증 **40건 통과**: 생성 ID, 답글, 수정, 이동, 처리 상태, 타인 수정 거절, 다른 슬라이드 접근 거절, revision 충돌, 최신 기준 수정, 첫 의견 삭제 시 답글 보존, 위치 없는 의견, 헤더 데이터·권한, 보관본, 완성 후 리뷰 분리, 기존 저장소 보존, 기존 코멘트 스키마 호환.
- React 정적 렌더링으로 읽기 전용 팝업의 변경 액션 미노출, 핀 생성 버튼 미노출, 팝업 크기 조절 UI를 확인했다.
- `npm run typecheck`, 전체 `npm run lint`, `npm run build` 통과. 최종 소규모 변경에는 해당 파일 ESLint와 diff 검사를 추가했다.
- 빌드 CSS에서 핀·팝업의 포인터 이벤트 선택자 2건 생성 확인.
- `git diff --check` 통과.
- 기존 `baseline-browser-mapping` 데이터 노후 경고가 있다. 브라우저·E2E·스크린샷·실제 키보드/포인터 조작 검증은 실행하지 않았다. `tests/` 폴더는 생성하지 않았다.

이번 복구 변경은 작업 트리에 반영했으며 커밋·push는 하지 않았다.
