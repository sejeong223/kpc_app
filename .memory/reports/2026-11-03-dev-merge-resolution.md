## 충돌 원인과 해결

충돌 파일은 `app/(authenticated)/workspace/[screen]/page.tsx` 하나이며, import와 화면 분기 두 부분이 겹쳤다. 로컬은 파일·목차·제작 설정·제작의 실제 작업 화면을 연결했고, 원격은 RFP 등록 및 공통 프로젝트 헤더 목업을 연결했다.

| 화면 | 병합 후 연결 | 보존한 동작 |
| --- | --- | --- |
| RFP 등록 | `RfpRegisterPage` | 원격의 등록 폼, 파일 목록, 검토자 선택, 알림 |
| 파일 업로드 | `FilesScreen` | 로컬의 프로젝트별 파일 저장·관리 |
| 목차·제작 설정·제작 | `WorkspaceScreen` | 로컬의 목차·설정·편집, 라운드, 댓글, PPT 처리 |
| 분석·리뷰 | `ProjectHeaderPage` | 원격의 공통 헤더, 설정·완료 관련 목업 UI |
| 관리자 화면 | `AdminScreenRouter` | 기존 역할 검사, 탭 처리, 토큰 경로 리다이렉트 |
| 그 외 화면 | `WorkspacePage` | 기존 공통 페이지와 빈 화면 처리 |

원격의 `CommentsWorkspace` 소스는 그대로 보존한다. 제작 경로는 새 작업 화면을 유지하며, 이전 의견 접근도 기존 제작 구현에 남아 있다.

공통으로 변경된 파일은 위 라우터와 `components/layout/AppShell.tsx` 두 개였다. `AppShell` 자동 병합은 로컬의 공통 여백 규칙과 원격의 `ProjectHeaderToaster`를 모두 유지한다. 로컬만 수정했던 198개 파일은 로컬 부모와 동일함을 확인했다. 원격만 변경한 파일도 아래 CSS 보완을 제외하면 원격 부모와 동일하다.

## CSS 보완

`app/admin-utilities.css`는 `source(none)`을 사용하면서 기존에 `components/workspace`를 검색 대상에 포함하지 않았다. 이번 확인 과정에서 발견한 기존 누락으로, `@source "../components/workspace";`를 추가했다. 원격에서 추가한 `components/rfp` 검색 대상도 유지했다.

## 범위와 제한

원격의 프로젝트 헤더 계획은 실제 프로젝트 모델과 분리된 목업 상태를 명시한다. 이를 파일·목차·제작의 실제 화면 대신 연결하면 편집 기능에 접근할 수 없으므로 실제 화면을 유지했다. 따라서 헤더 목업을 모든 실제 작업 화면에 통합한 것은 아니며, 분석·리뷰에서 사용할 수 있다. 헤더의 임시 프로젝트 선택과 실제 작업 저장소를 연결하는 작업은 이번 병합에 포함하지 않았다. 원격에서 비활성화한 완료·재작업·다운로드 버튼도 원래 범위를 유지한다.
